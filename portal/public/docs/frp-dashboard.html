背景：FRP 与内网穿透

FRP（Fast Reverse Proxy）是一套开源内网穿透工具，由 frps（服务端） 与 frpc（客户端） 组成：

  • frps 部署在有公网 IP 的机器（本例：阿里云 120.26.66.182），作为中转/出口；其内置 Dashboard 在独立端口（本例 7500）提供 Web 状态查看，需单独的用户名/密码鉴权。
  • frpc 部署在需要被暴露的内网机器，把本地端口「注册」到 frps；外部流量经 frps 公网端口转发回 frpc 所在内网服务。
  • 典型用途：在家/出差访问家里内网的设备与自托管服务，而无需为每台设备申请公网 IP 或开端口。

本套部署把「出口/看板」放在阿里云、「配置管理」放在内网 Debian，形成「穿透出口 + 集中管控」的分工。

本套部署拓扑（实采）

  • 阿里云 120.26.66.182（Tailscale 100.89.102.74）
  • frps 服务端 + Dashboard 7500。
  • 实采：从 mykng 探测 120.26.66.182:7500 返回 401（鉴权生效，服务在线）；探测默认 bind 端口 :7000 返回 000（不可达，疑似防火墙仅放行 7500 或 bind 端口不同）(待确认)。
  • 内网 Debian 192.168.31.182（Tailscale 100.105.196.63）
  • 容器 frp-manager:1.0.0（Java 21 / Spring Boot），端口 18082，挂载极简（仅 /etc/localtime）。
  • 实采：根路径返回 404，容器进程存活，属 HTTP 管理界面（需具体子路径或登录后访问）。

两者关系（基于实采推断）：frp-manager 是集中配置/管理 FRP 代理与隧道的控制台；其下发的代理配置最终注册到阿里云 frps，由 7500 仪表盘查看服务端侧运行态。具体联动/下发机制未实采，标记为 (待确认)。

核心功能与使用

  • FRP 仪表盘（7500）
  • 查看 frps 服务端状态：运行时间、版本、客户端连接数、各代理流量统计。
  • 查看已建立的代理/隧道列表（TCP/UDP/HTTP/HTTPS 等类型）、对应客户端、最近流量。
  • 运维排障入口：确认某条内网穿透隧道是否在线、流量是否异常、客户端是否掉线。
  • frp-manager（18082）
  • 集中维护 FRP 代理/隧道配置（自研/自选 Java 管理端），通常用于避免手工编辑 frps 配置文件。
  • 面向「需要把内网服务暴露到阿里云公网出口」的场景。

具体 UI 操作细节（按钮/表单）未经实测，按能力层面描述；如需逐项步骤，建议登录后补录。

依赖与关联

  • 依赖：阿里云主机的公网 IP 与带宽（穿透出口）；内网 Deb 的容器运行时（frp-manager）。
  • 被依赖/关联系统：所有经此穿透暴露的内网服务。与腾讯云2号 nginx 入口（marschat.online）是两套并行的对外暴露通道，互不重叠，分工为「公网子域反代」 vs 「任意内网服务穿透」。

安全要点

  • frps Dashboard 必须设强口令（已生效，返回 401）；口令入 Vaultwarden，勿明文。
  • 穿透会直接把内网服务暴露到公网，隧道权限（谁可建、暴露到哪个端口）需最小化管理，避免误暴露高风险服务。
  • frp-manager 仅内网可达、不暴露公网，符合「管理面收敛到内网」的惯例。
