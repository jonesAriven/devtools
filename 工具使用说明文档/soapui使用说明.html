1. SoapUI 简介与安装

1.1 什么是 SoapUI？

SoapUI 是一款开源的 API 测试工具，支持 SOAP、REST、GraphQL、WebSocket 等多种协议，提供以下核心能力：

  • 功能测试：验证 API 的请求/响应逻辑
  • 性能测试：模拟高并发场景，检测接口吞吐量与响应时间
  • Mock 服务：在后端接口未开发完成时，模拟返回预设响应
  • 自动化测试：支持脚本（Groovy）扩展与持续集成

SoapUI 分为两个版本：开源版（SoapUI Open Source） 和 商业版（ReadyAPI），本教程以开源版为基础。

1.2 系统要求

操作系统 Java 版本 内存要求 磁盘空间
Windows 10/11、macOS 10.15+、Linux（Ubuntu 20.04+） Java 8 或 Java 11（推荐） 至少 2GB RAM（性能测试建议 4GB+） 至少 500MB 空闲空间

1.3 下载与安装步骤

  1. 访问 SoapUI 官方下载页：https://www.soapui.org/downloads/latest-release.html
  2. 选择对应操作系统的安装包（开源版标注为「SoapUI Open Source」）：
    • Windows：下载 .exe 安装包，双击运行后按向导完成安装（默认勾选「添加环境变量」）
    • macOS：下载 .dmg 镜像，拖拽 SoapUI 到「应用程序」文件夹
    • Linux：下载 .tar.gz 压缩包，解压后运行 bin/soapui.sh 启动
  3. 启动 SoapUI：首次启动会弹出「欢迎向导」，可选择「创建新项目」或「跳过」
提示：若启动时提示「Java 未找到」，需手动配置 JAVA_HOME 环境变量，指向已安装的 Java 目录。

2. 基础操作：创建与管理项目

SoapUI 以「项目（Project）」为单位管理测试资源，一个项目可包含多个接口（Interface）、测试套件（Test Suite）、测试用例（Test Case）。

2.1 创建 REST 项目

REST 是目前最常用的 API 风格，SoapUI 支持通过 URL 或 API 文档（Swagger/OpenAPI）快速创建项目：

  1. 打开 SoapUI，点击菜单栏 File > New REST Project（或快捷键 Ctrl+N）
  2. 在弹出的对话框中输入「初始 WADL/Swagger/OpenAPI URL」：
    • 示例 1（直接输入接口 URL）：https://petstore.swagger.io/v2/pet
    • 示例 2（导入 Swagger 文档）：https://petstore.swagger.io/v2/swagger.json
  3. 勾选「Create Requests」（自动生成请求模板），点击「OK」
  4. 项目创建完成后，左侧「Navigator」面板会显示项目结构： 
    PetStore-REST（项目）
├─ pet（接口）
│  ├─ GET /pet/findByStatus（请求）
│  ├─ POST /pet（请求）
│  └─ DELETE /pet/{petId}（请求）
└─ Test Suites（测试套件，默认空）

2.2 创建 SOAP 项目

SOAP 接口基于 XML 协议，需通过 WSDL（Web Services Description Language）文档创建项目：

  1. 点击菜单栏 File > New SOAP Project
  2. 输入项目名称（如「Weather-SOAP」），并在「Initial WSDL」中输入 WSDL 地址：

    示例：http://www.webservicex.com/globalweather.asmx?WSDL

  3. 勾选「Create Test Suite」（自动生成测试套件），点击「OK」
  4. SoapUI 会解析 WSDL 并生成 SOAP 请求模板（包含 XML 格式的请求体）

2.3 项目管理基础

  • 保存项目：点击菜单栏 File > Save Project，项目以 .xml 格式存储（如「PetStore.xml」）
  • 导入项目：File > Import Project，选择本地的 .xml 项目文件
  • 删除资源：在「Navigator」面板中右键点击目标（如请求、测试用例），选择「Delete」
  • 复制资源：右键点击目标，选择「Duplicate」，快速创建相似用例

3. 核心功能：发送请求与解析响应

创建项目后，可通过 SoapUI 发送请求并查看响应，以下以 REST 接口为例说明。

3.1 配置 REST 请求

  1. 在「Navigator」面板中，展开项目 > 接口，双击目标请求（如「GET /pet/findByStatus」）
  2. 在请求编辑界面，配置以下参数：
    • Method：选择 HTTP 方法（GET、POST、PUT、DELETE 等）
    • Endpoint：接口的基础 URL（如 https://petstore.swagger.io/v2）
    • Resource：接口的路径（如 /pet/findByStatus）
    • Parameters：URL 参数（Query String），点击「+」添加键值对：

      示例：Key = status，Value = available（查询「可用」状态的宠物）

    • Headers：HTTP 头信息（如 Content-Type、Authorization），示例：

      Key = Content-Type，Value = application/json

    • Request Body（POST/PUT 请求）：输入 JSON/XML 格式的请求体，示例（创建宠物）： 
      {
  "id": 12345,
  "name": "小狗",
  "status": "available",
  "category": {
    "id": 1,
    "name": "dog"
  }
}

3.2 发送请求与查看响应

  1. 点击请求编辑界面左上角的 绿色箭头发送按钮（或快捷键 Ctrl+Enter）
  2. 右侧「Response」面板会显示响应结果，包含 4 个标签页：
    • Raw：原始响应（包含 HTTP 状态行、响应头、响应体）
    • JSON/XML：格式化后的响应体（自动识别格式，便于阅读）
    • Headers：响应头信息（如 Server、Content-Length、Date）
    • Attachment：响应中的附件（如文件下载接口）
  3. 查看关键信息：

    示例响应（JSON 格式）： 

    {
  "id": 12345,
  "name": "小狗",
  "status": "available",
  "category": {
    "id": 1,
    "name": "dog"
  },
  "tags": []
}

    HTTP 状态码：200 OK（表示请求成功）

注意：若请求失败（如 404 Not Found、500 Internal Server Error），可通过「Raw」标签页查看完整错误信息，排查 URL 是否正确、参数是否缺失、权限是否足够。

4. 断言：验证响应正确性

「断言（Assertion）」是 SoapUI 中验证响应是否符合预期的核心功能，通过断言可自动判断测试用例是否通过。

4.1 常用断言类型

断言类型 用途 适用场景
Contains Assertion 验证响应体/响应头中是否包含指定文本 简单文本匹配（如响应中包含「success」）
JSON Path Assertion 通过 JSON Path 表达式提取响应字段，验证其值 REST JSON 接口（如验证「name」字段值为「小狗」）
XML Path Assertion 通过 XPath 表达式提取 XML 响应字段，验证其值 SOAP 接口或 XML 格式的 REST 接口
Response Code Assertion 验证 HTTP 响应状态码是否符合预期 所有 HTTP 接口（如验证状态码为 200、400）
Response Time Assertion 验证响应时间是否小于指定阈值 性能要求高的接口（如响应时间 < 500ms）
Script Assertion 通过 Groovy 脚本自定义断言逻辑 复杂场景（如动态计算字段值、多条件判断）

4.2 添加断言的步骤

以「验证 REST 接口响应状态码为 200」为例：

  1. 打开目标请求（如「GET /pet/findByStatus」），发送请求后，切换到「Assertions」标签页
  2. 点击「+」按钮（Add Assertion），在弹出的对话框中选择「Response Code Assertion」，点击「OK」
  3. 在断言配置界面，选择「Equals」，输入预期状态码「200」，点击「Save」
  4. 再次发送请求，断言会自动执行：
    • 若通过：断言前显示 绿色对勾
    • 若失败：断言前显示 红色叉号，鼠标悬停可查看失败原因

4.3 脚本断言示例（Groovy）

场景：验证 JSON 响应中「status」字段值为「available」，且响应时间 < 500ms

// 1. 获取响应体（JSON 格式）
def responseJson = new groovy.json.JsonSlurper().parseText(messageExchange.responseContent)

// 2. 验证 status 字段值
assert responseJson.status == "available" : "状态不符合预期，实际为：" + responseJson.status

// 3. 获取响应时间（单位：ms）
def responseTime = messageExchange.timeTaken

// 4. 验证响应时间
assert responseTime < 500 : "响应时间过长，实际为：" + responseTime + "ms"

// 5. 打印日志（可选）
log.info("断言通过！响应时间：" + responseTime + "ms")
提示：脚本断言中，messageExchange 是 SoapUI 内置对象，可获取请求/响应信息；log 用于打印日志，日志可在「Log」标签页查看。

5. 数据驱动测试：批量执行用例

数据驱动测试（Data-Driven Testing）通过读取外部数据源（如 Excel、CSV）中的数据，自动参数化请求，实现批量执行测试用例，适用于多组输入场景（如登录、查询）。

5.1 准备数据源（Excel 示例）

创建 Excel 文件（如「pet_data.xlsx」），包含以下数据（测试不同宠物的查询场景）：

petId expectedName expectedStatus
12345 小狗 available
67890 小猫 pending
11122 小兔 sold

5.2 配置数据驱动测试步骤

以「批量查询宠物信息（GET /pet/{petId}）」为例：

  1. 创建测试套件与测试用例：
    • 右键点击项目 > 「New Test Suite」，输入名称（如「PetTestSuite」）
    • 右键点击测试套件 > 「New Test Case」，输入名称（如「PetQueryTestCase」）
  2. 添加「DataSource」步骤（读取 Excel 数据）：
    • 右键点击测试用例 > 「Add Step」> 「DataSource」
    • 输入步骤名称（如「ExcelDataSource」），点击「OK」
    • 在「DataSource」配置界面：

      - 选择「DataSource Type」为「Excel」

      - 点击「Browse」选择 Excel 文件（「pet_data.xlsx」）

      - 选择「Sheet Name」（如「Sheet1」）

      - 点击「Preview」预览数据，确认字段与 Excel 列匹配（petId、expectedName、expectedStatus）

  3. 添加「REST Request」步骤（参数化请求）：
    • 右键点击测试用例 > 「Add Step」> 「REST Request」
    • 选择目标接口（如「pet > GET /pet/{petId}」），点击「OK」
    • 在请求编辑界面，配置「Resource」中的 {petId} 参数：

      1. 选中 {petId}，右键 > 「Get Data」

      2. 在弹出的对话框中，选择「ExcelDataSource」> 「petId」，点击「OK」

      3. 此时 {petId} 会替换为 ${ExcelDataSource#petId}，表示从数据源读取 petId 值

  4. 添加「DataSource Loop」步骤（循环读取数据）：
    • 右键点击测试用例 > 「Add Step」> 「DataSource Loop」
    • 输入步骤名称（如「DataLoop」），点击「OK」
    • 在配置界面：

      - 「DataSource」选择「ExcelDataSource」

      - 「Target Step」选择「REST Request」（表示循环执行该请求）

      - 点击「Save」

  5. 添加断言（验证批量结果）：
    • 打开「REST Request」的「Assertions」标签页，添加「JSON Path Assertion」
    • 配置 JSON Path 表达式：$.name，选择「Equals」，点击「Get Data」选择「ExcelDataSource#expectedName」
    • 重复上述步骤，添加对「status」字段的断言
  6. 执行测试用例：

    右键点击测试用例 > 「Run」，SoapUI 会自动循环读取 Excel 中的 3 组数据，执行 3 次请求并验证断言

注意：若使用 CSV 数据源，选择「DataSource Type」为「CSV」，并确保 CSV 文件编码为 UTF-8（避免中文乱码）。

6. Mock 服务：模拟接口响应

Mock 服务（模拟服务）是在后端接口未开发完成时，由 SoapUI 模拟接口的行为，返回预设的响应数据，便于前端开发或测试用例编写。

6.1 创建 REST Mock 服务

  1. 右键点击目标 REST 接口（如「pet」）> 「Generate REST Mock Service」
  2. 在弹出的对话框中，配置以下信息：
    • 「Mock Service Name」：输入名称（如「PetMockService」）
    • 「Port」：设置 Mock 服务的端口（如 8080，确保端口未被占用）
    • 「Base Path」：设置基础路径（如「/mock/pet」）
  3. 点击「OK」，SoapUI 会自动生成 Mock 服务，并包含接口的所有请求方法（如 GET /pet/{petId}、POST /pet）
  4. 在「Navigator」面板中，展开「Mock Services > PetMockService」，可看到生成的 Mock 响应（如「GET /pet/{petId} - Response 1」）

6.2 配置 Mock 响应

以「配置 GET /pet/{petId} 的 Mock 响应」为例：

  1. 双击「GET /pet/{petId} - Response 1」，打开 Mock 响应编辑界面
  2. 配置响应参数：
    • 「Response Status Code」：设置 HTTP 状态码（如 200）
    • 「Response Headers」：添加头信息（如 Content-Type: application/json）
    • 「Response Body」：输入预设的响应体（JSON 格式）： 
      {
  "id": ${petId}, // ${petId} 表示引用请求中的 petId 参数
  "name": "Mock宠物",
  "status": "available",
  "message": "这是Mock服务返回的响应"
}
  3. 点击「Save」保存配置

6.3 启动与测试 Mock 服务

  1. 右键点击 Mock 服务（如「PetMockService」）> 「Start Mock Service」
  2. 若启动成功，状态栏会显示「Mock Service started on port 8080」
  3. 测试 Mock 服务：
    • 方式 1：使用浏览器访问 Mock 地址：http://localhost:8080/mock/pet/12345，可看到预设的 JSON 响应
    • 方式 2：在 SoapUI 中创建新的 REST 请求，将 Endpoint 设置为 http://localhost:8080/mock，发送请求后可接收 Mock 响应
  4. 停止 Mock 服务：右键点击 Mock 服务 > 「Stop Mock Service」

6.4 动态 Mock 响应（Groovy 脚本）

场景：根据请求中的 petId 参数，返回不同的响应（如 petId=123 返回「小狗」，petId=456 返回「小猫」）

  1. 打开 Mock 响应编辑界面，切换到「Script」标签页
  2. 输入以下 Groovy 脚本： 
    // 1. 获取请求中的 petId 参数
def petId = mockRequest.pathParameters.get("petId")

// 2. 根据 petId 生成不同的响应
def responseJson = ""
if (petId == "123") {
    responseJson = '''{
        "id": 123,
        "name": "小狗",
        "status": "available"
    }'''
} else if (petId == "456") {
    responseJson = '''{
        "id": 456,
        "name": "小猫",
        "status": "pending"
    }'''
} else {
    // 默认响应
    responseJson = '''{
        "id": ''' + petId + ''',
        "name": "未知宠物",
        "status": "sold"
    }'''
}

// 3. 设置响应体
mockResponse.content = responseJson

// 4. 设置响应头
mockResponse.addHeader("Content-Type", "application/json")

// 5. 设置响应状态码
mockResponse.statusCode = 200
  3. 保存脚本后，启动 Mock 服务，分别访问 http://localhost:8080/mock/pet/123 和 http://localhost:8080/mock/pet/456，可看到不同的响应

7. 性能测试（负载测试）

性能测试（又称负载测试）用于模拟高并发场景，检测接口在不同压力下的响应时间、吞吐量、错误率等指标，评估接口的性能极限。

7.1 创建负载测试用例

  1. 右键点击已有的测试用例（如「PetQueryTestCase」）> 「New Load Test」
  2. 输入负载测试名称（如「PetLoadTest」），点击「OK」
  3. 打开负载测试编辑界面，包含「Load Profile」「Test Case」「Reports」等标签页

7.2 配置负载参数

在「Load Profile」标签页中，配置以下核心参数：

参数 说明 示例配置
Load Type 负载类型：
- Concurrent Users（并发用户数）
- Rate（每秒请求数）		 Concurrent Users
Initial Users 初始并发用户数 10
Max Users 最大并发用户数 100
Ramp Up Time (sec) 从初始用户数增加到最大用户数的时间 60（1分钟内逐步增加到100用户）
Hold Load For (sec) 保持最大用户数的持续时间 120（保持2分钟）
Ramp Down Time (sec) 从最大用户数减少到0的时间 30（30秒内逐步减少到0用户）
Test Duration (sec) 测试总时长（优先级高于上述时间） 210（总时长3分30秒）

7.3 执行负载测试与查看报告

  1. 点击负载测试编辑界面左上角的「Start」按钮，开始执行测试
  2. 执行过程中，「Live Statistics」面板会实时显示以下指标：
    • Concurrent Users：当前并发用户数
    • Requests/sec：每秒请求数（吞吐量）
    • Response Time (ms)：平均响应时间
    • Error Rate (%)：错误率
  3. 测试结束后，切换到「Reports」标签页，可查看详细报告：
    • 「Summary Report」：测试概要（总请求数、成功数、失败数、平均响应时间）
    • 「Response Time Distribution」：响应时间分布图表
    • 「Throughput Report」：吞吐量趋势图表
  4. 导出报告：点击「Export Report」，选择报告格式（HTML、PDF），保存到本地
提示：执行负载测试时，建议关闭其他占用资源的程序，避免影响测试结果；若需模拟分布式负载，可使用 SoapUI 商业版的「LoadUI Pro」功能。

8. 持续集成：与 Jenkins/Maven 集成

将 SoapUI 测试用例集成到持续集成（CI）工具（如 Jenkins）中，可实现代码提交后自动执行 API 测试，及时发现问题。

8.1 准备 Maven 项目

SoapUI 支持通过 Maven 插件执行测试，需先创建 pom.xml 文件：



    4.0.0
    com.example
    soapui-test
    1.0-SNAPSHOT

                soapui-maven-plugin
                5.7.0

                    PetTestSuite
                    
                    PetQueryTestCase
                    
                    ${project.basedir}/target/soapui-reports
                    HTML 
                    
                    true
                
                
                    
                        test
                        
                            test

将 pom.xml 与 SoapUI 项目文件（如「PetStore.xml」）放在同一目录下。

8.2 配置 Jenkins 集成

  1. 安装 Jenkins 并配置 Java 环境（确保 Java 版本与 SoapUI 兼容）
  2. 安装必要插件：
    • 「Maven Integration plugin」：支持 Maven 项目构建
    • 「SoapUI Plugin」（可选）：提供 SoapUI 测试报告可视化

    安装方式：Jenkins 首页 > 「Manage Jenkins」> 「Plugins」> 「Available Plugins」，搜索插件并安装

  3. 创建 Jenkins 任务：
    • 点击「New Item」，输入任务名称（如「SoapUI-API-Test」），选择「Maven project」，点击「OK」
    • 在「Source Code Management」中，配置代码仓库（如 Git），输入仓库 URL 和 credentials（若需）
    • 在「Build」部分，设置「Root POM」为 pom.xml，「Goals and options」为 clean test
    • 点击「Save」保存配置
  4. 执行 Jenkins 任务：

    点击任务名称 > 「Build Now」，Jenkins 会自动拉取代码、执行 Maven 命令、运行 SoapUI 测试用例

  5. 查看测试结果：
    • 任务构建完成后，点击「Console Output」查看详细日志
    • 点击「SoapUI Report」（若安装了 SoapUI Plugin）查看可视化报告
    • 测试报告文件会保存在 Jenkins 工作空间的 target/soapui-reports 目录下

8.3 命令行执行 SoapUI 测试

除了 Maven，也可通过 SoapUI 自带的 testrunner.bat（Windows）或 testrunner.sh（Linux/macOS）命令执行测试：

// Windows 示例
cd C:\Program Files\SmartBear\SoapUI-5.7.0\bin

9. 常见问题与社区资源

9.1 常见问题（FAQ）

  • Q1：启动 SoapUI 时提示「Java 未找到」？

    A1：手动配置 JAVA_HOME 环境变量，指向已安装的 Java 目录（如 C:\Program Files\Java\jdk1.8.0_301），并确保 %JAVA_HOME%\bin 已添加到 Path 环境变量。

  • Q2：发送请求时出现「SSLHandshakeException」（SSL 握手失败）？

    A2：这是由于接口使用 HTTPS，但 SoapUI 未信任服务器证书。解决方案：

    • 方式 1：在请求编辑界面，点击「SSL Settings」，勾选「Ignore SSL Errors」（仅测试环境使用）
    • 方式 2：导入服务器证书到 SoapUI 的信任库（适合生产环境）

  • Q3：数据驱动测试中 Excel 中文乱码？

    A3：确保 Excel 文件编码为 UTF-8，或在「DataSource」配置界面，将「Encoding」设置为「GBK」（Windows 默认编码）。

  • Q4：Mock 服务启动失败，提示「端口已被占用」？

    A4：更换 Mock 服务的端口（如将 8080 改为 8081），或关闭占用该端口的程序（Windows 可通过 netstat -ano | findstr "8080" 查找占用端口的进程，再通过任务管理器结束进程）。
