## 背景

R14-L/M 闭环 T-ENG-20（infra 账密会话被 sessionWatcher 误踢）时留下两个待办：① 坑 #47 防复发口径要求的**双模应用 `watchSession` 普查**；② T-ENG-17（kb-ops 权限链 404 ⇒ fail-open 全放行）根因修复「涉后端安全语义，需拍板」。R15 轮用户授权后两项一并执行，**当日全部闭环**。

## 决策一：双模应用 watchSession 普查 —— 发现并修复 kb-ops（第二例）

**普查结论**（`grep -rn "watchSession" src/marschat.ts`）：portal / kb-web / cosmic 显式 `watchSession:false`（cosmic 在 `main.js` 内按 `isOidcSession()` 逐令牌分流）、infra 已修 ⇒ **kb-ops 漏配**（未传 `watchSession` 且未设 `sessionMode`，与 infra 修复前完全同构）。

**kb-ops 的误踢链（比 infra 更隐蔽）**：登录页 `showLocalLogin=false`（后端无本地登录端点）但 `showMailLogin=true` ⇒ 邮箱验证码登录走 auth-center `/auth/mail-login`；`AuthServiceImpl.loginByMail` **只签发 JWT + 写 sso cookie、不建 Spring Security 会话**（`/auth/session` 判据是 SecurityContext）⇒ 探针恒 `false`；登录成功即 `window.location.replace` 硬跳转 ⇒ bootstrap 必带票重跑 ⇒ watcher 必启动 ⇒ **修复前每次邮箱登录 3 秒后被踢回 `/ops/login?slo=1`**（线上真 bug；静态链 + R14-L 同机制实证共同推定「修复前」态）。

**修法**：kb-ops `marschat.ts` 传 `watchSession: () => isOidcToken()`（devtools `73c312ec`，流水线 #866 部署，在线 chunk 双签名核验 `watchSession:()=>Zt()`）。邮箱登录只 `setToken` 不设 `token_kind` ⇒ 天然排除；SSO 流（`sso.ts:121 setTokenKind('oidc')`）不受影响。

**复验（R15-N，15/15 全绿）**：qa 账号邮箱登录（Redis 取码真流程）→ 硬跳转落 `/ops/dashboard` → 13s 不被踢、令牌键在、**CDP 层登录后零新 `/auth/session` 探针**；SSO 对照 `token_kind=oidc`、watcher 照常探针不回归。

## 决策二：T-ENG-17 根因两层，两处修复（kb-ops 权限链恢复 fail-closed）

**根因**：
1. **部署层缺路由**：app-kit ≥0.1.3 同源策略（`resolvePermissionsIssuer`：IdP 不同源 ⇒ 探针 = `apiBase + /auth/permissions`）要求部署栈路由 `{apiBase}/auth/**` 到认证中心。kb-web（gateway `/kb/api/auth/**`）/ infra（nginx `/infra/api/auth/**`）都有，**唯 kb-ops 缺** —— 宿主 nginx `/etc/nginx/conf.d/locations/ops.conf` 把 `/ops-api/` 整体代理给自家后端（无 `/auth/permissions` 端点）⇒ 带票探针 404 ⇒ `configured=false` ⇒ fail-open 全放行。
2. **前端遗留跨域暗线**：`MainLayout.vue` 的 `onMounted` 仍活跃调 `fetchPermissions(permOptions)`（infra/kb-web 只 import 未调用，唯独 kb-ops 在调），`permOptions.issuer = APP_CONFIG.issuer`（跨域 IdP）；与 app-kit 预取**共享 60s 模块级缓存** ⇒ 登录页无票预取不预热 ⇒ SPA 登录后 MainLayout 挂载缓存冷 ⇒ 补发跨域直连（R15-O 实测抓到）。R12「恒 403」/R14「200」观测矛盾由此解释（取决于票据类型与 CORS 放行时机）。

**修法（两处）**：
1. 宿主 nginx 新增 `location /ops-api/auth/ → 127.0.0.1:8090/kb/api/auth/`（与既有 `/ops/auth-api/` **同上游**，零新增端点暴露面；`nginx -t` + 热 reload；备份 `ops.conf.bak-20261022-teng17`）。**不走 kb-ops 后端 BFF 方案**：走网关与 kb-web 同路、零后端改动、无服务身份兜底语义风险。
2. kb-ops `permOptions.issuer` 改 `APP_CONFIG.apiBase`（devtools `a7f08302`，流水线 #867 部署，在线 chunk 签名 `issuer:De.apiBase` 核验）；SSO 客户端 issuer 不变。

**复验（R15-O/P，headless 真浏览器）**：探针同源 200 + `configured=true` + 权限点数组；**零跨域 `/auth/permissions`**（邮箱 + SSO 冷缓存双流，CDP 层 cross=[]）；零 app-kit 告警；**qa 账号侧边菜单仅「看板」**（fail-open 全放行 → 真 enforcement）；业务端点无回归（dashboard 200 / 越权 host/list 403 = 正确执行）；SPA 200。
