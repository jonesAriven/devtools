# ADR-2026-09-09 · 公共组件发布到 Nexus npm 私服

- **日期**：2026-09-09
- **状态**：**已实施**（4 个前端应用全部从私服拉取依赖，CI 构建和本地开发统一）
- **归属**：cross-project
- **关联**：
  - `ADR-2026-09-08 · 统一认证单点登录`（公共组件 `@marschat/auth-components` 的使用方）
  - `marschat-components/packages/auth-components`（发布源）
  - `marschat-components/packages/frontend-common`（发布源）
  - `devtools/mykng/kb-web`、`kb-ops-web`、`infra-monitor-web`、`portal-web`（消费方）

---

## 背景

### 1.1 问题

`marschat-components` monorepo 下的两个公共包：
- `@marschat/auth-components`（SSO 登录组件、Token 管理）
- `@marschat/frontend-common`（HTTP 请求封装、格式化工具、分页 Hook）

此前各前端应用通过 **Vite alias** 指向本地源码路径：

```ts
// vite.config.ts (旧)
resolve: {
  alias: {
    '@marschat/auth-components': path.resolve(__dirname, '../../../marschat-components/packages/auth-components/src'),
    '@marschat/frontend-common': path.resolve(__dirname, '../../../marschat-components/packages/frontend-common/src'),
  }
}
```

**问题**：
1. **CI 构建失败**：CI 容器内没有 `marschat-components` 源码，alias 指向的路径不存在 → 编译报错
2. **本地/CI 不一致**：本地开发依赖源码 alias 能跑，CI 缺少源码必挂
3. **版本不可控**：各应用使用的组件版本无法追踪，改动源码即时生效无版本管理
4. **依赖关系断裂**：无法追踪哪些应用使用了哪个版本的公共组件

### 1.2 约束

- 公共组件需独立构建（Vite Library Mode，输出 ES + UMD）
- CI 容器（`node:20-slim`）不 clone `marschat-components` 源码
- 私服已有 Nexus `npm-hosted`（发布用）和 `npm-public`（组仓库，下载用）
- 各应用使用 pnpm workspace 管理 monorepo 依赖

---

## 决策

### 2.1 将公共组件发布到 Nexus npm 私服

**发布端**：
1. `marschat-components` 使用 Vite Library Mode 构建，输出 `dist/` 目录
2. 通过 `npm publish --registry http://192.168.31.105:8081/repository/npm-hosted/` 发布到 `npm-hosted` 仓库
3. 认证方式：用户级 `.npmrc` 配置 `_auth=base64(admin:password)`
4. 发布版本：
   - `@marschat/auth-components@0.1.0`
   - `@marschat/frontend-common@0.2.0`

**消费端**：
1. 各应用 `package.json` 添加依赖：
   ```json
   {
     "dependencies": {
       "@marschat/auth-components": "0.1.0",
       "@marschat/frontend-common": "0.2.0"
     }
   }
   ```
2. 删除 `vite.config.ts` 中的 alias 配置，强制从 `node_modules` 加载
3. CI 构建时 `pnpm install --frozen-lockfile` 自动从 `npm-public` 组仓库拉取
4. 本地开发也通过 `pnpm install` 获取，不再依赖源码路径

### 2.2 Nexus 仓库分工

| 仓库 | 用途 | URL |
|------|------|-----|
| `npm-hosted` | 发布私有包（写入） | `http://192.168.31.105:8081/repository/npm-hosted/` |
| `npm-public` | 下载包（组仓库 = hosted + proxy） | `http://192.168.31.105:8081/repository/npm-public/` |
| `npm-proxy` | 代理 npm 官方源（缓存） | `http://192.168.31.105:8081/repository/npm-proxy/` |

### 2.3 CI 构建流程

```
┌─────────────────────────────────────────────────────────┐
│                    CI 构建流程                            │
│                                                         │
│  1. clone devtools (from github)                        │
│  2. pnpm config set registry npm-public                 │
│  3. cd mykng/kb-web && pnpm install --frozen-lockfile   │
│     → 从 npm-public 拉取 @marschat/auth-components@0.1.0│
│     → 从 npm-public 拉取 @marschat/frontend-common@0.2.0│
│  4. pnpm build → dist/                                 │
│  5. publish_artifact → /mnt/shared/woodScript/publish/  │
│  6. deploy → 目标服务器                                  │
└─────────────────────────────────────────────────────────┘
```

## 教训

1. **双推遗漏**：devtools 和 marschat-components 仓库有 gitee + github 两个 remote，CI 从 github clone，但只推了 gitee 导致 CI 拿不到最新代码。**每次 push 必须同时推 gitee 和 github**。
2. **测试深度不足**：部署后只看 HTML 源码渲染正常就宣称验证通过，没有实际点击登录按钮、测试 SSO 全流程、验证 UI 美观度。**验证必须覆盖完整用户交互路径**。
3. **偶发失败不追溯根因**：kb-web #497 部署失败（产物不存在）直接重试，未排查并发写入竞争的根因。**偶发失败也要追溯根因**。
4. **自进化系统失效**：LLM Evolver daemon 持续 3 天报 JSON 解析错误但从未检查日志。**后台 daemon 需定期验证产出有效性**。
