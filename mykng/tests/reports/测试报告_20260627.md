- 不带 /kb 的请求被 Nginx 拒绝（404 或 SPA 回退）
- 之前的测试脚本 `test_full_api.py` 第 14 行 `BASE_URL = "https://kb.marschat.online"` + 第 114-147 行路径 `/kb/api/...` **是带了 /kb 上下文路径的**

### 4.2 失败用例分类

#### A. 测试脚本问题（4 个，非真实 bug，可修复脚本后通过）

| 用例 | 现象 | 根因 |
|------|------|------|
| L4-AUTH-003 auth/refresh | HTTP 500 | 测试脚本重复登录导致旧 refresh token 失效；单独调用返回 200 |
| L4-FILE-002 file/merge | biz 400 | 未真实上传分片直接 merge，业务校验合理 |
| L4-SEARCH-001 search | HTTP 0 | URL 中文未编码；编码后返回 200 |
| L4-SHARE-004/005 share verify/detail | biz 400 | 创建分享时设了 extractCode，verify 时漏传 |

#### B. 前后端不一致（2 个，KNOWN_ISSUE）

| 用例 | 现象 | 根因 |
|------|------|------|
| L4-AUTH-010 token/verify POST | HTTP 401 | 规范 2.11 声称 permitAll，但网关 JWT 过滤器仍拦截 |
| L4-OPS-DEPLOY-003 ops/deployment POST | biz 404 | 规范定义路径与后端实现不一致 |

#### C. 真实 bug（9 个）

**C1. 错误码不规范（7 个）— 后端对"删除不存在的资源"应返回 404，实际返回 400**

| 用例 | 接口 | 现象 |
|------|------|------|
| L4-SPACE-004 | DELETE /space/{不存在} | 400（应 404） |
| L4-FOLDER-004 | DELETE /folder/{不存在} | 400（应 404） |
| L4-DOC-007 | DELETE /doc/{不存在} | 400（应 404） |
| L4-WEB-004 | DELETE /web/{不存在} | 400（应 404） |
| L4-SHARE-003 | DELETE /share/{不存在} | 400（应 404） |
| L4-TRASH-002 | POST /trash/restore/{type}/{不存在} | 400（应 404） |
| L4-TRASH-003 | DELETE /trash/{type}/{不存在} | 400（应 404） |

**根因**：kb-knowledge 服务对所有"资源不存在"场景统一返回 400，违反接口规范错误码表（404 = 资源不存在）。

**C2. 服务端 500 错误（2 个）**

| 用例 | 接口 | 现象 |
|------|------|------|
| L4-FILE-001 | POST /file/upload | HTTP 500，multipart 解析异常 |
| L3-PAGE-013 | 访问不存在的分享码 | 后端 500 → 触发 axios 拦截器跳转登录页 |

测试脚本：`tests/functional/test_full_api_v2.py`

### 4.3 关键发现

1. **auth/refresh 的 TooManyResultsException 未复现**：单独调用 `POST /kb/api/auth/refresh` 返回 200，正常返回新令牌对。之前测试脚本的 500 是重复登录导致旧 token 失效的测试脚本问题。
2. **expiresIn 字段值不一致**：refresh 接口返回 `expiresIn=3600000`（1 小时），但接口规范声明 `900000`（15 分钟）。需后端核对 Access Token 过期时间配置。
3. **search 接口正常**：MeiliSearch 全文检索工作正常，能正确返回匹配文档。
4. **kb-knowledge 服务错误码统一性问题**：DELETE 不存在资源统一返回 400 而非 404，系统性契约违反。

### 5.2 关键发现

1. **登录态复用成功**：通过 Playwright `storage_state` 保存登录态，11 个受保护页面全部 HTTP 200，未被重定向。
2. **VM 在线，无 504**：所有页面均无 504/502 网关错误，后端服务健康。
3. **多个详情接口返回 500**：访问 `/doc/1`、`/file/1`、`/web/1` 时，ID=1 的资源在数据库中不存在，后端抛异常返回 500 而非友好的 404。
4. **回收站页面 formatDate 空值报错**：`TypeError: Cannot read properties of undefined (reading 'getFullYear')`，当回收站列表项的 `createdAt` 为 undefined 时报错。
5. **分享页错误处理缺陷**：访问不存在的分享码时，后端返回 500 触发 axios 拦截器全局跳转登录页，应让分享页本地处理"分享不存在"提示。

## 九、发版建议

### 9.1 可发版结论

✅ **可发版**。核心功能（登录、空间管理、文档管理、搜索、运维看板）均可用，上下文路径配置正确。

### 9.2 建议修复顺序

**发版前必修（P1）**：
1. 修复 `POST /file/upload` 500 错误（影响文件上传核心功能）

**发版后 1 周内修复（P2 高优）**：
2. 统一 kb-knowledge 错误码（DELETE 不存在返回 404）
3. 修复详情接口资源不存在返回 500（改为 404）
4. 修复分享页重定向到登录页问题
5. 修复回收站 formatDate 空值报错
6. 补全分块上传接口（L4-GAP-014/015/016）

**后续迭代修复（P2 中优）**：
7. 统一前后端路径风格（trash/version/share 等）
8. 补全缺失端点（/auth/me、/folder/{id}、/space/{id}、/bucket CRUD 等）
9. 修正 expiresIn 字段值
10. 网关白名单补充 /token/verify

### 9.3 测试覆盖率提升建议

- **L1 单元测试**：当前未实现，建议下次迭代补充 kb-auth/kb-knowledge 的 Service 层测试，目标覆盖率 70%
- **L2 集成测试**：当前未实现，建议使用 @SpringBootTest + Testcontainers 补充 Controller 层测试
- **L5 非功能测试**：建议补充性能基线测试（locust）和安全测试（鉴权边界）
