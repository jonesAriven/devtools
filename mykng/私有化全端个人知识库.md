## 1. 项目简介
### 核心功能清单
- 手动富文本录入，无限层级树形知识库分类、标签管理
- Word/Excel/PDF/图片上传，Web端依托OnlyOffice实现在线编辑保存
- URL网页一键收藏，自动清洗网页内容、生成网页PDF/HTML快照归档
- 全内容全文检索：手写笔记、Office内容、PDF、图片OCR文字、网页正文统一检索
- 本地私有化大模型自动摘要、定时批量AI汇总复盘知识点
- MinIO多桶隔离存储、文件生命周期管控、临时预签名URL下载
- 三级知识分享：私密提取码分享、目录分组授权、公开知识库
- 三端统一账号互通：PC管理后台、APP、微信小程序
- APP完整离线录入/离线查看，联网增量自动同步；小程序、H5弱离线缓存

### 部署特点
全部中间件Docker化部署，数据私有化存储，不依赖第三方云服务、第三方AI接口。

## 2. 技术栈选型
### 后端
- 基础框架：SpringBoot3.2 + SpringSecurity + JWT
- 数据库：MySQL8.0
- 缓存：Redis
- 消息队列：RabbitMQ（文件解析、爬虫、AI任务异步解耦）｜轻量版替代：Redis Stream
- 定时任务：XXL-JOB（周期复盘、过期资源清理）｜轻量版替代：Spring @Scheduled
- 检索引擎：Elasticsearch8 + IK中文分词｜轻量版替代：MeiliSearch（内置中文分词）
- 对象存储：MinIO
- 文档解析：POI(Office)、PdfBox(PDF)、PaddleOCR(图片文字提取)｜轻量版替代：Tesseract
- 在线编辑服务：OnlyOffice Document Server（轻量版按需启停）
- 网页抓取：Jsoup(静态页面) + Playwright(JS动态页面)（轻量版Playwright按需启停）
- 私有化AI：Qwen2-7B 本地大模型｜轻量版替代：Qwen2-1.5B-Q4量化版（CPU推理）

### 前端
1. PC管理后台：Vue3 + ElementPlus + Vite（全功能管理、Office在线编辑）
2. 移动端：UniApp+Vue3+Pinia，一套源码编译：Android/IOS APP、微信小程序、H5
3. H5开启PWA ServiceWorker，实现网页局部离线

### API统一规范
基础路由前缀：`/api/v1/`

| 模块 | 接口前缀 | 说明 |
| ---- | ---- | ---- |
| 鉴权 | /api/v1/auth | 账号/微信/手机号登录，统一JWT鉴权 |
| 用户 | /api/v1/user | 用户信息、第三方账号绑定 |
| 知识库空间 | /api/v1/space | 多空间管理，多租户预留 |
| 目录 | /api/v1/folder | 树形分类CRUD |
| 笔记 | /api/v1/doc | 手动富文本笔记 |
| 文件 | /api/v1/file | 附件上传、预览、解析 |
| 网页收藏 | /api/v1/web | URL爬虫、快照归档 |
| 搜索 | /api/v1/search | ES全文检索 |
| AI | /api/v1/ai | 文档摘要、自动复盘 |
| 分享 | /api/v1/share | 分享链接、有效期、访问密码 |
| 存储桶 | /api/v1/bucket | MinIO桶配置管理 |

统一返回体：
```json
{
  "code":200,
  "msg":"success",
  "data":{}
}
```
分页统一字段：page、size、total。

## 3. 系统模块能力
### 3.1 知识库基础模块
- 无限级树形目录，自定义标签，文档备注、学习时间标记
- 富文本编辑器手动录入、图文混排知识点

### 3.2 文件管理模块
- 大文件分片上传（适配小程序/APP文件限制）
- Web端OnlyOffice在线编辑，修改自动回存MinIO
- 上传异步解析文件文本，图片OCR提取内容存入检索库

### 3.3 网页剪藏模块
- 手动填URL、浏览器书签脚本、小程序分享微信文章三种收录方式
- 自动剔除导航、广告，留存正文；生成网页原文件+PDF快照存档

### 3.4 全文检索模块
跨数据源统一检索：手写文档+Excel单元格+PDF+图片OCR+网页内容，关键词高亮、分类/时间筛选。

### 3.5 AI智能模块
1. 单文档：解析完成自动调用本地大模型生成摘要；
2. 周期复盘：定时任务拉取指定目录全文档，AI汇总生成复习大纲并新建文档入库。

### 3.6 MinIO存储桶管理
后台可视化管理桶、查看容量、配置生命周期策略，分享文件自动过期清理，文件使用预签名URL访问。

### 3.7 知识共享模块
1. 私密分享：加密链接+提取码+自定义有效期，H5/小程序/APP均可打开预览；
2. 分组协作：目录粒度权限（只读/可编辑）；
3. 公开知识库：标记公开的文档，游客免登录检索预览。

### 3.8 离线同步模块
依托`sync_record`同步表，APP离线数据落地本地SQLite，联网增量同步，数据冲突弹窗选择保留策略。

## 4. 多端能力&离线说明
| 客户端 | 核心功能 | 离线支持 | 限制 |
| ---- | ---- | ---- | ---- |
| PC管理后台 | 全功能：Office在线编辑、批量上传、爬虫批量导入、桶管理、定时配置 | ❌ 不支持全离线 | OnlyOffice/ES/LLM依赖服务，断网仅可查看缓存笔记 |
| Android/IOS APP | 拍照OCR录入、语音记笔记、本地文件上传、检索、复习提醒 | ✅ 完整离线 | SQLite缓存文档，本地文件缓存附件；离线新增，联网同步；APP内置轻量化离线OCR |
| 微信小程序 | 微信文章一键收藏、文档查阅、短句录入、微信卡片分享 | ⚠️弱离线 | 微信存储上限10MB，仅缓存文本，附件无法本地存储 |
| H5(PWA) | 文档查阅、基础录入、分享 | ⚠️局部离线 | ServiceWorker缓存静态资源，IndexedDB缓存正文，不能离线编辑Office |

> AI补充：在线调用远端大模型生成摘要；离线录入内容待联网后批量生成总结。

## 5. MinIO分桶规划
系统初始化自动创建6个桶，默认私有，`kb-share`默认7天生命周期自动删文件。

| 桶名 | 存储内容 |
| ---- | ---- |
| kb-doc | Word/Excel/PDF源文件、Office编辑回写文件 |
| kb-img | 用户上传图片、APP拍照图、网页配图 |
| kb-web | 网页HTML、网页PDF快照 |
| kb-share | 分享临时资源 |
| kb-ai | AI复盘文档、摘要附属资源 |
| kb-system | 用户头像、系统静态资源 |

## 6. 数据库建表SQL

> **设计规范**：
> - 所有业务表统一包含 `user_id`（数据归属）、`deleted`（逻辑删除）、`created_at`、`updated_at` 四个通用字段
> - 逻辑删除字段 `deleted`：0=正常，1=已删除；删除操作置1而非物理删除，回收站可恢复
> - 所有外键关联字段必须建立索引
> - 唯一性约束字段（如username、bucket name）必须加 UNIQUE KEY

```sql
-- ============================================================
-- 1. 用户表
-- ============================================================
CREATE TABLE `user` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `username` VARCHAR(64) NOT NULL,
  `password` VARCHAR(256) NOT NULL COMMENT 'BCrypt加密存储',
  `phone` VARCHAR(20),
  `wx_openid` VARCHAR(64),
  `avatar` VARCHAR(512),
  `status` TINYINT DEFAULT 1 COMMENT '0禁用 1正常',
  `deleted` TINYINT DEFAULT 0 COMMENT '0正常 1已删除',
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY `uk_username` (`username`),
  UNIQUE KEY `uk_phone` (`phone`),
  UNIQUE KEY `uk_wx_openid` (`wx_openid`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';

-- ============================================================
-- 2. 知识库空间
-- ============================================================
CREATE TABLE `space` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `user_id` BIGINT NOT NULL,
  `name` VARCHAR(64) NOT NULL,
  `description` VARCHAR(512) COMMENT '空间描述',
  `is_private` TINYINT DEFAULT 1 COMMENT '0公开 1私有',
  `deleted` TINYINT DEFAULT 0,
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX `idx_user_id` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='知识库空间';

-- ============================================================
-- 3. 目录表
-- ============================================================
CREATE TABLE `folder` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `space_id` BIGINT NOT NULL,
  `user_id` BIGINT NOT NULL,
  `parent_id` BIGINT DEFAULT 0 COMMENT '0=根目录',
  `name` VARCHAR(64) NOT NULL,
  `sort` INT DEFAULT 0,
  `deleted` TINYINT DEFAULT 0,
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX `idx_space_id` (`space_id`),
  INDEX `idx_user_id` (`user_id`),
  INDEX `idx_parent_id` (`parent_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='目录表';

-- ============================================================
-- 4. 手动文档
-- ============================================================
CREATE TABLE `doc` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `folder_id` BIGINT NOT NULL,
  `user_id` BIGINT NOT NULL,
  `title` VARCHAR(255) NOT NULL,
  `content` LONGTEXT,
  `ai_summary` TEXT,
  `sort` INT DEFAULT 0 COMMENT '目录内排序',
  `starred` TINYINT DEFAULT 0 COMMENT '0普通 1星标/收藏',
  `deleted` TINYINT DEFAULT 0,
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX `idx_folder_id` (`folder_id`),
  INDEX `idx_user_id` (`user_id`),
  INDEX `idx_starred` (`starred`),
  INDEX `idx_updated_at` (`updated_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='手动文档';

-- ============================================================
-- 5. 文件附件
-- ============================================================
CREATE TABLE `file` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `folder_id` BIGINT NOT NULL,
  `user_id` BIGINT NOT NULL,
  `name` VARCHAR(255) NOT NULL,
  `type` VARCHAR(32) NOT NULL COMMENT '文件扩展名：docx/xlsx/pdf/png等',
  `bucket` VARCHAR(64) NOT NULL,
  `path` VARCHAR(512) NOT NULL,
  `size` BIGINT NOT NULL COMMENT '文件字节数',
  `mime_type` VARCHAR(128) COMMENT 'MIME类型，用于上传校验',
  `parsed_text` LONGTEXT COMMENT '解析全文用于检索',
  `ai_summary` TEXT,
  `starred` TINYINT DEFAULT 0,
  `deleted` TINYINT DEFAULT 0,
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX `idx_folder_id` (`folder_id`),
  INDEX `idx_user_id` (`user_id`),
  INDEX `idx_type` (`type`),
  INDEX `idx_starred` (`starred`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='文件附件';

-- ============================================================
-- 6. 网页收藏
-- ============================================================
CREATE TABLE `web_page` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `folder_id` BIGINT NOT NULL,
  `user_id` BIGINT NOT NULL,
  `url` VARCHAR(1024) NOT NULL,
  `title` VARCHAR(255),
  `content` LONGTEXT,
  `snap_path` VARCHAR(512) COMMENT '快照MinIO路径',
  `ai_summary` TEXT,
  `starred` TINYINT DEFAULT 0,
  `deleted` TINYINT DEFAULT 0,
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX `idx_folder_id` (`folder_id`),
  INDEX `idx_user_id` (`user_id`),
  INDEX `idx_starred` (`starred`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='网页收藏';

-- ============================================================
-- 7. 检索索引关联表（仅存ES文档ID映射，全文内容由ES存储）
-- ============================================================
CREATE TABLE `search_index` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `biz_type` VARCHAR(32) NOT NULL COMMENT 'doc/file/web',
  `biz_id` BIGINT NOT NULL,
  `es_doc_id` VARCHAR(128) COMMENT 'ES中的文档ID，用于精准删除/更新',
  `folder_id` BIGINT,
  `user_id` BIGINT,
  `sync_status` TINYINT DEFAULT 0 COMMENT '0待同步 1已同步 2同步失败',
  `sync_retry` INT DEFAULT 0 COMMENT '同步重试次数',
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY `uk_biz` (`biz_type`, `biz_id`),
  INDEX `idx_user_id` (`user_id`),
  INDEX `idx_sync_status` (`sync_status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='检索索引关联表';

-- ============================================================
-- 8. AI复盘记录
-- ============================================================
CREATE TABLE `ai_review` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,

-- ============================================================
-- 16. JWT黑名单表（token主动失效）

  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY `uk_token` (`token`),
  INDEX `idx_expire_time` (`expire_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='JWT黑名单';

-- ============================================================
-- 17. Refresh Token表（双token鉴权）
-- ============================================================
CREATE TABLE `refresh_token` (
```

## 7. 核心业务流程
### 7.1 文件上传流程
文件上传 → MinIO入库 → MQ推送解析任务 → 对应组件解析文本 → 写入库parsed_text字段 → ES同步索引 → LLM生成AI摘要

### 7.2 网页收藏流程
提交URL → Playwright/Jsoup抓取 → 正文清洗 → 正文入库+快照存MinIO → AI总结 → ES建立索引

### 7.3 全文检索流程
前端入参关键词 → ES跨biz_type检索 → 结果高亮返回，支持筛选

### 7.4 APP离线同步
离线新增数据存入本地SQLite，sync_status=0 → 联网触发同步 → 本地上传云端、云端增量拉取 → 同步成功置1；两端同时修改标记冲突，前端选择覆盖方案

### 7.5 AI定时复盘
XXL-JOB定时触发 → 按目录汇总全部文档 → LLM生成汇总文档 → 自动新建知识库笔记

## 9. 部署方案

> **设计原则**：后端代码通过抽象接口层屏蔽中间件差异，同一套业务代码通过配置切换标准版/轻量版组件，无需改写业务逻辑。

### 9.1 双轨部署体系

系统提供**标准版**和**轻量版**两套部署方案，功能完全一致，仅底层组件不同，适配不同硬件条件：

| 能力 | 标准版（全组件） | 轻量版（低资源） |
| ---- | ---- | ---- |
| 全文检索 | Elasticsearch 8 + IK分词 | MeiliSearch（内置中文分词，内存仅ES的1/10） |
| 消息队列 | RabbitMQ | Redis Stream（复用已有Redis，零额外部署） |
| 定时任务 | XXL-JOB | Spring @Scheduled + cron（单用户足够） |
| 在线编辑 | OnlyOffice Document Server | OnlyOffice按需启停（5分钟无操作自动停止，编辑时自动唤醒，约10秒冷启动） |
| 图片OCR | PaddleOCR | PaddleOCR按需启停 / Tesseract（常驻仅200MB，中文精度略低） |
| AI大模型 | Qwen2-7B（需GPU 16GB显存） | Qwen2-1.5B-Q4量化版按需启停（摘要请求时启动，5分钟空闲自动停止，约15秒冷启动） |
| 网页抓取 | Playwright常驻容器 | Playwright按需启停（爬取时启动，完成后自动停止） |
| 数据库 | MySQL 8.0 | MySQL 8.0（共用，轻量版调低buffer pool至256MB） |
| 缓存 | Redis | Redis（共用，轻量版调低maxmemory至128MB） |
| 对象存储 | MinIO | MinIO（共用） |

**轻量版核心替换逻辑**：
- **ES → MeiliSearch**：MeiliSearch支持中文分词、高亮、筛选，API简洁，单二进制文件部署，对个人知识库数据量（万级文档）检索性能与ES相当
- **RabbitMQ → Redis Stream**：Redis 5.0+原生支持Stream数据结构，具备消费者组、ACK、持久化能力，满足异步任务解耦需求；后端抽象`MessageQueue`接口，通过Spring Profile切换实现
- **XXL-JOB → Spring @Scheduled**：个人使用场景无分布式调度需求，Spring内置定时任务完全够用；保留XXL-JOB接口抽象，后续升级标准版无需改代码
- **OnlyOffice按需启停**：通过自定义健康检查脚本+docker-compose `restart: unless-stopped`实现，首次编辑请求触发`docker start`，5分钟空闲触发`docker stop`；用户感知为首次打开文档多等10秒
- **Qwen2-7B → Qwen2-1.5B-Q4**：1.5B量化模型在摘要、总结任务上精度损失可控（个人知识库摘要不需要复杂推理），CPU推理速度约5-8 token/s，单篇摘要10-30秒可完成

### 9.2 标准版 docker-compose

全组件常驻运行，适合服务器/NAS/高性能主机部署：

```yaml
# docker-compose-standard.yml
# 包含：MySQL、Redis、MinIO、Elasticsearch、RabbitMQ、
#       OnlyOffice、PaddleOCR、Qwen2-7B、XXL-JOB、Playwright
# 详见部署仓库
```

1. **本地私有化部署**：整套服务部署NAS/迷你主机，局域网访问，外出携带主机实现全功能离线；
2. **云端部署**：服务上云服务器，公网访问，APP依靠本地缓存实现离线查阅。

### 9.3 轻量版 docker-compose

最小化常驻进程，按需启停重型组件，适合8GB内存的个人电脑/轻量云服务器：

```yaml
# docker-compose-lite.yml
# 常驻：MySQL(256MB buffer)、Redis(128MB maxmemory)、MinIO、MeiliSearch
# 按需：OnlyOffice(5min idle stop)、PaddleOCR(按需启停)、
#       Qwen2-1.5B-Q4(CPU推理)、Playwright(按需启停)
# 详见部署仓库
```

1. **个人电脑本地部署**：日常开发机即可运行，Docker Desktop后台静默运行，浏览器访问localhost；
2. **轻量云服务器**：2核8G云主机即可部署，月成本约35~75元；
3. **NAS部署**：群晖/威联通等支持Docker的NAS，家庭局域网共享使用。

### 9.4 切换方式

通过环境变量`SPRING_PROFILES_ACTIVE=standard|lite`一键切换，无需改代码：

```yaml
# application-standard.yml
search:
  engine: elasticsearch
mq:
  type: rabbitmq
job:
  type: xxljob
ai:
  model: qwen2-7b

# application-lite.yml
search:
  engine: meilisearch
mq:
  type: redis-stream
job:
  type: spring-scheduled
ai:
  model: qwen2-1.5b-q4
```

后端抽象接口示例：
- `SearchEngine` → `ElasticsearchSearchEngine` / `MeiliSearchSearchEngine`
- `MessageQueue` → `RabbitMQMessageQueue` / `RedisStreamMessageQueue`
- `JobScheduler` → `XxlJobScheduler` / `SpringScheduledScheduler`
- `AiModel` → `Qwen7bModel` / `Qwen15bQ4Model`
