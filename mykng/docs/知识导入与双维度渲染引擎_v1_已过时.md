> 版本: v1.0  
> 日期: 2026-06-28  
> 状态: 设计中  

---

## 1. 背景与目标

### 1.1 问题

当前 AI 在工作时（如"你去读一下XXX方案""你去部署一下XXX服务"），面临两个问题：

1. **效率低**：AI 需要读取 3000+ 字的 Markdown 原文，从中现场提取参数（host/port/password），Token 消耗大、耗时长
2. **精度差**：Markdown 中的表格/emoji/Mermaid 图干扰 AI 提取，参数容易遗漏或出错

### 1.2 目标

构建一个知识导入引擎，将文档/文件夹解析为**四层数据**，AI 使用时**按需分层读取**，实现：

| 指标 | 传统方式（读全文） | 本方案（分层读取） |
|------|------------------|------------------|
| Token 消耗 | ~4000/次 | ~200/次（90%场景） |
| 参数精度 | AI 现场提取，~95% | 预处理提取，100% |
| 响应速度 | 慢（全文传输+解析） | 快（结构化直取） |

### 1.3 核心设计思想

```
传统方式: AI 读 3000 字文档 → 现场提取参数 → 可能出错
本方案:   导入时提取参数 → 存为结构化 JSON → 使用时直接读取 → 100%准确
```

## 3. 文件类型与解析策略

基于龙虾记忆库（openclaw-work-space）的实际分析，将文档分为 5 种类型，分别采用不同解析策略：

### 3.1 文件分类

| 类型 | 特征 | 代表文件 | 解析策略 | 抽取难度 |
|------|------|---------|---------|---------|
| **A: 结构化表格** | Markdown 表格为主，列固定 | 主机清单、端口速查表、账密汇总、域名映射 | **规则引擎**（正则精确抽取） | 低 |
| **B: 方案文档** | 参数表+代码块+散文混合 | Nexus部署方案、整体架构总览 | **LLM 提取**（参数+步骤+配置） | 中高 |
| **C: 时间线记录** | 按时间排列的事件序列 | 踩坑记录、健康检查报告 | **规则+LLM**（时间戳正则+事件摘要） | 中 |
| **D: 关系数据** | ASCII 树/Mermaid 图 | 应用依赖关系、网络流量图 | **图结构解析**（节点+边提取） | 高 |
| **E: 规则文档** | 约束条件、操作规范 | 小桉工作规则、运维操作规范 | **LLM 提取**（约束条件+规则） | 中 |

### 3.2 解析策略矩阵

```
                    ┌─────────────────────────────────┐
                    │         解析策略选择              │
                    └──────────────┬──────────────────┘
                                   │
                    ┌──────────────┴──────────────┐
                    │                             │
              文件类型判定                    图片/二进制
              (内容模式识别)                   → MinIO 存储
                    │
        ┌───────┬───┴───┬───────┬───────┐
        ▼       ▼       ▼       ▼       ▼
     A:表格  B:方案  C:时间线  D:关系  E:规则
        │       │       │       │       │
   正则抽取  LLM提取  正则+LLM  图解析  LLM提取
   →JSON数组  →参数表  →事件序列  →图结构  →规则集
```

### 3.3 类型识别规则

通过文件路径、标题、内容特征自动判定类型：

```
类型A（结构化表格）:
  - 表格行数占全文 > 60%
  - 或文件名含"清单|速查|汇总|映射|端口|账密"

类型B（方案文档）:
  - 文件名含"方案|架构|部署|接入|配置"
  - 或含 ```bash/```yaml 代码块 + 参数表

类型C（时间线记录）:
  - 文件名含"踩坑|记录|报告|日志"
  - 或正文含日期模式 (2026-06-XX / ## 问题1)

类型D（关系数据）:
  - 含 ASCII 树状图 (├── / └── / →)
  - 或含 ```mermaid 代码块

类型E（规则文档）:
  - 文件名含"规则|规范|约定"
  - 或正文以"必须/禁止/应当"等约束词为主
```

## 4. 四层数据模型

### 4.1 层级总览

```
┌─────────────────────────────────────────────────────────────┐
│ Layer 1: 索引层（元数据）— 快速定位，~50 Token                │
│ 存储: MySQL kn_document                                      │
│ 内容: 标题、路径、分类、标签、摘要(100字)、文件类型           │
│ 用途: AI 检索"Nexus方案在哪"                                  │
├─────────────────────────────────────────────────────────────┤
│ Layer 2: 参数层（结构化JSON）— 精确操作，~100 Token           │
│ 存储: MySQL kn_entity / kn_param / kn_command / kn_credential│
│ 内容: 主机、服务、端口、密码、路径、命令、配置项               │
│ 用途: AI 执行"部署Nexus"时直接取参数                          │
├─────────────────────────────────────────────────────────────┤
│ Layer 3: 内容层（精简文本）— 理解推理，~500-2000 Token        │
│ 存储: MongoDB kn_content                                     │
│ 内容: 去格式化的语义文本 + 段落标记                           │
│ 用途: AI 需要"理解为什么"时按段落读取                         │
├─────────────────────────────────────────────────────────────┤
│ Layer 4: 向量层（embedding）— 语义检索                        │
│ 存储: MeiliSearch _vectors 字段                               │
│ 内容: 512维向量 (bge-small-zh)                               │
│ 用途: AI 语义搜索"Nexus内存溢出怎么解决"                      │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 Layer 1: 索引层（MySQL）

#### kn_document — 文档元数据表

```sql
CREATE TABLE IF NOT EXISTS kn_document (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    source_id       VARCHAR(64)   NOT NULL COMMENT '导入批次ID',
    title           VARCHAR(256)  NOT NULL COMMENT '文档标题',
    file_path       VARCHAR(512)  NOT NULL COMMENT '原始文件路径',
    file_name       VARCHAR(256)  NOT NULL COMMENT '文件名',
    file_type       VARCHAR(16)   NOT NULL COMMENT '文件类型(md/png/json)',
    doc_type        VARCHAR(16)   NOT NULL COMMENT '文档分类(TABLE/PLAN/TIMELINE/GRAPH/RULE)',
    category        VARCHAR(64)   DEFAULT NULL COMMENT '业务分类(备忘录/知识/经验)',
    tags            JSON          DEFAULT NULL COMMENT '标签数组',
    summary         VARCHAR(512)  DEFAULT NULL COMMENT 'AI摘要(100字)',
    content_hash    VARCHAR(64)   DEFAULT NULL COMMENT '内容SHA256(增量更新用)',
    word_count      INT           DEFAULT 0    COMMENT '字数',
    section_count   INT           DEFAULT 0    COMMENT '章节数',
    status          VARCHAR(16)   DEFAULT 'ACTIVE' COMMENT 'ACTIVE/ARCHIVED',
    created_at      DATETIME      DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME      DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_source (source_id),
    INDEX idx_type (doc_type),
    INDEX idx_category (category),
    INDEX idx_hash (content_hash)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='知识文档元数据';
```

### 4.3 Layer 2: 参数层（MySQL）

#### kn_entity — 实体表

```sql

## 5. 解析引擎设计

### 5.1 解析流程

```
输入: 文件夹路径或文件
  │
  ▼
Step 1: 文件遍历
  │  递归扫描目录，过滤 .md/.txt/.json/.png
  │  计算 content_hash 用于增量更新
  ▼
Step 2: 文件读取 + 类型识别
  │  读取文件内容
  │  根据文件名/内容模式判定 doc_type (A-E)
  ▼
Step 3: 分类型解析
  │
  ├─ 类型A（表格）→ 规则引擎正则抽取 → kn_entity + kn_credential
  ├─ 类型B（方案）→ LLM 提取参数/命令/步骤 → kn_entity + kn_command + kn_content
  ├─ 类型C（时间线）→ 正则提取时间戳 + LLM 摘要事件 → kn_timeline
  ├─ 类型D（关系）→ 图结构解析 → kn_relation
  └─ 类型E（规则）→ LLM 提取约束条件 → kn_content
  │
  ▼
Step 4: 生成摘要 + 标签
  │  LLM 生成 100 字摘要 + 3-5 个标签
  ▼
Step 5: 内容精简
  │  去 emoji/格式标记，按 ## 章节切分 → kn_content (MongoDB)
  ▼
Step 6: 向量生成
  │  bge-small-zh 生成 512 维 embedding → MeiliSearch
  ▼
Step 7: 持久化
  │  写入 MySQL + MongoDB + MeiliSearch
  ▼
完成: 返回导入结果统计
```

### 5.2 规则引擎 — 类型A（结构化表格）解析

**适用文件**: 主机清单、端口速查表、账密汇总、域名映射

**策略**: 正则精确抽取，零 LLM 调用

```java
// 解析 Markdown 表格
// 输入: | 机器 | 角色 | IP | 用户 | 密码 | SSH端口 |
//        | 龙虾 | 🖥️虚拟机 | 49.51.245.134 | root | `root01` | 22 |

// 1. 提取表头
Pattern HEADER = Pattern.compile("^\\|(.+)\\|$");
// 2. 提取数据行
Pattern ROW = Pattern.compile("\\|\\s*([^|]+)\\s*");

// 主机清单解析器
public List<Entity> parseHostTable(String content) {
    List<Entity> entities = new ArrayList<>();
    String[] lines = content.split("\n");
    for (String line : lines) {
        if (!line.startsWith("|") || line.contains("---")) continue;
        String[] cells = line.split("\\|");
        // 跳过表头和分隔行
        if (cells[1].trim().equals("机器")) continue;
        // 构建 Host 实体
        Entity entity = new Entity();
        entity.setType("HOST");
        entity.setName(cells[1].trim().replaceAll("🖥️|✅|❌", "").trim());
        entity.setAttr("role", cells[2].trim());
        entity.setAttr("ip", cells[3].trim());
        entity.setAttr("ssh_user", cells[4].trim());
        entity.setAttr("ssh_pass", cells[5].trim().replace("`", ""));
        entity.setAttr("ssh_port", cells[6].trim());
        entities.add(entity);
    }
    return entities;
}
```

### 5.3 LLM 提取器 — 类型B（方案文档）解析

**适用文件**: Nexus部署方案、整体架构总览、接入方案

**策略**: 调用 LLM 提取结构化参数，使用结构化 Prompt

```
Prompt 模板:
---
你是一个知识提取引擎。请从以下文档中提取结构化信息。

文档标题: {title}
文档内容:
{content}

请提取以下信息，返回严格 JSON 格式:

1. entities: 文档中涉及的所有实体
   - type: HOST/SERVICE/PORT/DOMAIN/PATH/IMAGE
   - name: 实体名称
   - attributes: 实体属性键值对

2. commands: 文档中的可执行命令
   - type: INSTALL/CONFIG/RUN/DEBUG
   - text: 完整命令
   - description: 说明
   - section: 所属章节

3. parameters: 关键配置参数
   - name: 参数名 (如 jvm_opts)
   - value: 参数值
   - section: 所属章节

4. summary: 100字以内的文档摘要

5. tags: 3-5个标签

返回格式:
{
  "entities": [...],
  "commands": [...],
  "parameters": [...],
  "summary": "...",
  "tags": [...]
}
---
```

### 5.4 时间线解析器 — 类型C

**适用文件**: 踩坑记录、健康检查报告

**策略**: 正则提取时间戳 + LLM 摘要事件

```
// 时间戳模式
Pattern[] TIME_PATTERNS = {
    Pattern.compile("(\\d{4}-\\d{2}-\\d{2}[\\s\\T]\\d{2}:\\d{2}(:\\d{2})?)"),  // 2026-06-21 14:30
    Pattern.compile("##\\s*(问题|故障|事件)(\\d+)[:：\\s]*(.+)"),               // ## 问题1: Nexus OOM
    Pattern.compile("(\\d{4}\\.\\d{2}\\.\\d{2})")                                // 2026.06.21
};

// 解析流程:
// 1. 按 ## 标题切分事件
// 2. 每个事件块中正则匹配时间戳
// 3. 提取事件标题 + 描述
// 4. LLM 生成事件摘要 + 解决方案
```

### 5.5 图结构解析器 — 类型D

**适用文件**: 应用依赖关系、网络流量图

**策略**: 解析 ASCII 树/Mermaid 为节点+边

```
// ASCII 树解析
// 输入:
// 用户 → 腾讯云2号:443 → mykng:80 → 知识库
//       └── Nexus:8081

// 解析为:
relations = [
  {source:"用户", target:"腾讯云2号:443", type:"CONNECT_TO"},
  {source:"腾讯云2号:443", target:"mykng:80", type:"PROXY_TO"},
  {source:"mykng:80", target:"知识库", type:"SERVES"},
  {source:"腾讯云2号", target:"Nexus:8081", type:"DEPLOY_ON"}
]
```

### 5.6 增量更新

```
导入时:
  1. 计算文件 content_hash (SHA256)
  2. 查询 kn_document 表是否存在同 file_path 的记录
  3. 若 hash 相同 → 跳过（未修改）
  4. 若 hash 不同 → 重新解析，删除旧数据，写入新数据
  5. 若不存在 → 首次导入，全量解析
```

## 7. 人类版渲染设计

### 7.1 五种视图

| 视图 | 数据来源 | 展示方式 |
|------|---------|---------|
| 目录树 | kn_document (file_path) | 文件夹层级树，按 备忘录/知识/经验 分类 |
| 实体图谱 | kn_entity + kn_relation | 力导向图，主机→服务→端口→域名关系网络 |
| 时间线 | kn_timeline | 垂直时间线，踩坑/检查/部署事件按时间排列 |
| 标签云 | kn_document (tags) | 标签卡片，按主题分类聚合文档 |
| 凭据速查 | kn_credential | 卡片式，支持搜索，密码默认隐藏 |

### 7.2 人类版 API

所有人类版 API 以 `/kb/api/knowledge/human` 为前缀，使用 JWT 认证。

```
# 目录树视图
GET /knowledge/human/tree

# 实体图谱视图
GET /knowledge/human/graph?type=HOST
→ 返回 {nodes: [...], edges: [...]} 供前端渲染力导向图

# 时间线视图
GET /knowledge/human/timeline?from=2026-06-01&to=2026-06-30
