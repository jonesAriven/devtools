> 项目：mykng / Private-Knowledge-Base
> 架构文档：`私有化全端个人知识库_v6.md`
> 部署类型：微服务版（Docker Compose）

### 访问链路

```
用户 → https://kb.marschat.online/kb/
  → 腾讯云2号 Nginx (SSL 终结, :443)
    → /kb/api/*  → proxy_pass → http://100.93.36.113/kb/api/  (Tailscale, :80)
    → /kb/*      → proxy_pass → http://100.93.36.113/kb/      (Tailscale, :80)
  → mykng 本地 Nginx (:80)
    → /kb/api/*  → proxy_pass → http://127.0.0.1:8090         (网关)
    → /kb/s/*    → alias /data/kb-web/                        (静态资源)
    → /kb/*      → try_files/error_page → /kb/index.html      (SPA)
```

### 设计原则

| 原则 | 说明 |
|------|------|
| **单点暴露** | 只有 kb-gateway 映射到宿主机端口 8090，其余服务走 Docker 内网 |
| **Tailscale 直连** | 腾讯云2号 ↔ mykng-debian 通过 Tailscale 私有网络直连，延迟 < 1ms |
| **SSL 终结在边缘** | 证书管理集中在腾讯云2号，内网全 HTTP |
| **双层代理** | 腾讯云2号纯SSL卸载+反代（不存文件），mykng本地Nginx处理静态资源+路由 |
| **前端本地方案** | 前端静态文件部署在mykng本地 `/data/kb-web/`，不传到腾讯云2号 |
| **统一上下文路径** | `KB_CONTEXT=/kb` 一处配置，前后端 + Nginx 同步 |

## 五、Nginx 配置

### 5.1 腾讯云2号 Nginx（SSL终结 + 纯反代）

**文件位置**：`/etc/nginx/sites-available/kb`（腾讯云2号），软链到 `/etc/nginx/sites-enabled/kb`

**域名**：`kb.marschat.online`（DNS 解析到 1.117.70.30）

**证书**：复用 `/etc/letsencrypt/live/nexus.marschat.online/`（SAN 含 nexus + tools，浏览器访问 kb 会有 SNI 警告，建议后续用 DNS-01 申请独立证书）

**职责**：仅做SSL终结和反向代理，不存储任何静态文件，所有请求通过Tailscale转发到mykng本地Nginx。

**完整配置**：

```nginx
# kb.marschat.online - MyKNG 知识库平台
# 腾讯云2号：纯SSL终结+反向代理，不存静态文件
# 证书复用 nexus.marschat.online（SAN: nexus + tools）
# kb.marschat.online 未备案，浏览器会有 SNI 警告，建议后续用 DNS-01 申请独立证书
server {
    listen 80;
    server_name kb.marschat.online;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name kb.marschat.online;

    ssl_certificate /etc/letsencrypt/live/nexus.marschat.online/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/nexus.marschat.online/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;

    access_log /var/log/nginx/kb-access.log;
    error_log  /var/log/nginx/kb-error.log;
    client_max_body_size 200m;

    # API 反代 → mykng 本地 Nginx（Tailscale: 100.93.36.113:80）
    location /kb/api/ {
        proxy_pass http://100.93.36.113/kb/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Trace-Id $request_id;
        proxy_connect_timeout 5s;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }

    # Actuator 监控端点（走/api/路径即可，无需单独配置）

    # 所有其他 /kb/ 路径 → mykng 本地 Nginx（静态资源 + SPA 路由）
    location /kb/ {
        proxy_pass http://100.93.36.113/kb/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 5s;
        proxy_read_timeout 60s;
        proxy_send_timeout 60s;
    }

    location = /kb {
        return 302 /kb/;
    }

    location = / {
        return 302 /kb/;
    }
}
```

### 5.2 mykng本地 Nginx（静态资源 + API反代）

**文件位置**：`/etc/nginx/sites-available/kb.marschat.online`（mykng-debian），软链到 `/etc/nginx/sites-enabled/kb.marschat.online`

**项目配置文件**：`nginx/kb.marschat.online.conf`

**职责**：
- 监听80端口，处理所有经腾讯云2号转发过来的请求
- 前端静态资源服务（`/data/kb-web/`）
- API反向代理到kb-gateway（`127.0.0.1:8090`）
- SPA路由回退

**完整配置**（与项目中 `nginx/kb.marschat.online.conf` 一致）：

```nginx
# ============================================================
# mykng Nginx 配置 - HTTP 模式（SSL在腾讯云2号终结）
# ============================================================
# 部署到: /etc/nginx/sites-available/kb.marschat.online
# 目录结构: /data/kb-web/
#   - index.html          (SPA 入口)
#   - kb/index.html       (root 映射副本，使 /kb/ 路径生效)
#   - assets/             (Vite 构建的静态资源)
#
# 路径规则:
#   /kb/api/*  → 反代到 Gateway (127.0.0.1:8090)
#   /kb/s/*    → 前端静态资源 (alias)
#   /kb/*      → 前端 SPA 路由 (error_page 404 → index.html)
# ============================================================

server {
    listen 80;
    server_name kb.marschat.online 192.168.31.105 100.93.36.113 localhost;

    client_max_body_size 100m;

    # API 反向代理到网关
    location /kb/api/ {
        proxy_pass http://127.0.0.1:8090;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Connection        "";
        proxy_connect_timeout 60s;
        proxy_send_timeout    300s;
        proxy_read_timeout    300s;
        proxy_buffering off;
        proxy_request_buffering off;
    }

    # 前端静态资源（vite base: /kb/s/ → alias 到 /data/kb-web/）
    location /kb/s/ {
        alias /data/kb-web/;
        access_log off;
        expires 7d;
        add_header Cache-Control "public, immutable";
    }

    # 前端 SPA 路由 - 使用 root + error_page 404 避免重定向循环
    location /kb/ {
        root /data/kb-web;
        index index.html;
        error_page 404 =200 /kb/index.html;
    }

    # 根路径跳转到 /kb/
    location = / {
        return 301 /kb/;
    }

    # MinIO 控制台
    location /minio/ {
        proxy_pass http://127.0.0.1:9001/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 健康检查
    location /health {
        access_log off;
        return 200 '{"status":"ok"}';
        add_header Content-Type application/json;
    }
}
```

**前端目录结构说明**：
```
/data/kb-web/
├── index.html           # SPA 入口（Vite构建产物）
├── kb/
│   └── index.html       # index.html 副本，使 root /data/kb-web + /kb/ 路径能找到
└── assets/              # JS/CSS/图片等静态资源（带hash，长缓存）
```

### 5.3 Nginx 方案优劣势分析

| 方案 | 架构 | 优势 | 劣势 | 结论 |
|------|------|------|------|------|
| **A（采用）** | 腾讯云 Nginx(SSL) → Tailscale → 本地Nginx(静态+反代) → 网关 | 静态文件完全本地，无需同步；证书集中管理；双层职责清晰 | 双层Nginx需分别维护 | ✅ |
| B | 腾讯云 Nginx → Tailscale → 网关直连 + 静态资源也在腾讯云 | 单层Nginx，配置简单 | 静态文件需scp同步到腾讯云；腾讯云磁盘占用；更新前端需操作两台机器 | ❌（原v2方案，已废弃） |
| C | 腾讯云 Nginx → FRP → 本地Nginx → 网关 | 不依赖 Tailscale | 多一跳 FRP，延迟更高 | ❌ 备选 |

**方案 A 细节**：
- 腾讯云2号 Nginx 仅做 SSL 终结 + 纯反向代理，不部署任何静态文件
- 所有请求通过 Tailscale 转发到 mykng-debian:80（本地Nginx）
- mykng本地Nginx处理静态资源服务（`/data/kb-web/`）和API反代（`127.0.0.1:8090`）
- 前端部署只需操作mykng-debian一台机器，无需scp到腾讯云2号
- 前端已优化：首屏 JS ~370KB（gzip ~75KB），通过Tailscale传输无感知

## 八、备份策略

### 数据卷备份

| 数据 | 备份路径 | 频率 | 保留 |
|------|---------|------|------|
| MySQL | /mnt/0000sharebak/kb-backup/mysql/ | 每天 02:00 | 7天 |
| MongoDB | /mnt/0000sharebak/kb-backup/mongodb/ | 每天 02:00 | 7天 |
| MinIO | /mnt/0000sharebak/kb-backup/minio/ | 每周日 02:00 | 4周 |
| MeiliSearch | /mnt/0000sharebak/kb-backup/meilisearch/ | 每周日 02:00 | 4周 |

### 备份脚本

```bash
#!/bin/bash
# /root/devtools/mykng/scripts/backup.sh
BACKUP_DIR="/mnt/0000sharebak/kb-backup"
DATE=$(date +%Y%m%d_%H%M%S)

# MySQL 备份（按 schema 分别导出）
for db in kb_auth kb_file kb_knowledge kb_ops; do
  docker exec kb-mysql mysqldump -uroot -pkb123456 --single-transaction $db \
    > "$BACKUP_DIR/mysql/${db}_${DATE}.sql"
done

# MongoDB 备份
docker exec kb-mongodb mongodump --uri="mongodb://kb:kb123456@localhost:27017" \
  --archive > "$BACKUP_DIR/mongodb/mongodb_${DATE}.archive"

# 清理 7 天前的备份
find "$BACKUP_DIR/mysql" -name "*.sql" -mtime +7 -delete
find "$BACKUP_DIR/mongodb" -name "*.archive" -mtime +7 -delete

echo "[$DATE] 备份完成"
```

### Cron 配置

```bash
# 每天凌晨 2:00 备份
0 2 * * * /root/devtools/mykng/scripts/backup.sh >> /var/log/kb-backup.log 2>&1
```

### 知识引擎同步

运维中心支持从知识引擎（kb-intelligence）一键同步实体数据（主机、服务、端口、凭据、域名、依赖关系）。

**触发方式**：
- 前端：运维看板 → 「从知识引擎同步」按钮
- API：`POST /kb/api/ops/sync/from-intelligence`

**请求参数**：
```json
{
  "override": false,
  "entityTypes": ["HOST", "SERVICE", "PORT", "CREDENTIAL", "DOMAIN", "DEPENDENCY"]
}
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| override | boolean | false | 是否覆盖已存在的记录（按唯一键去重） |
| entityTypes | string[] | 全部类型 | 指定同步哪些实体类型 |

**同步规则**：
- 主机按 IP 去重
- 服务按名称去重
- 端口按 主机+端口号 去重
- 凭据按 主机+类型+用户名 去重
- 域名按域名去重
- 凭据密码使用 AES-256-GCM 加密存储（与运维中心原有加密机制一致）

**手动触发（容器内）**：
```bash
# 在 kb-ops 容器内直接调用（绕过网关认证，仅供调试）
docker exec kb-ops wget -qO- --post-data='{}' \
  --header='Content-Type: application/json' \
  http://localhost:8084/ops/sync/from-intelligence
```

### 服务扩容预留

当前单机部署，未来可扩展为多节点：

| 扩展方向 | 方式 | 影响 |
|---------|------|------|
| 多实例 | 同一服务多副本 + Nginx upstream 负载均衡 | 需引入服务发现（Nacos/Consul） |

### 端口变更检查清单

如需修改网关端口（如从 8090 改为其他）：

| 文件 | 修改内容 |
|------|---------|
| `docker-compose.yml` | `ports: - "新端口:8080"` |
| `deploy.sh` | `log "网关地址: http://localhost:新端口"` |
| mykng本地 Nginx (`nginx/kb.marschat.online.conf`) | `proxy_pass http://127.0.0.1:新端口;` |
| 腾讯云2号 Nginx | 无需修改（反代到本地Nginx 80端口，与网关端口无关） |
