# 运维中心 × 知识引擎 数据同步方案

| 属性 | 值 |
|------|-----|
| 版本 | v1.0 |
| 日期 | 2026-06-29 |
| 适用 | mykng v7 微服务架构 |
| 关联需求 | PRD M21：知识引擎→运维中心同步 |

---

## 1. 背景与目标

### 1.1 问题

运维中心（kb-ops）是一套手动维护的运维资产管理系统，有完整的 CRUD、矛盾检测、凭据加密、看板快照等能力，但当前数据量极少（22 台主机大部分是 E2E 测试垃圾数据），实际使用价值低。

知识引擎（kb-intelligence）从 75 篇龙虾文档中自动解析出 26 台主机、若干服务/端口/凭据/域名/依赖等实体，但只是只读视图，无法编辑、无法加密、无法做矛盾检测。

### 1.2 目标

新增「从知识引擎同步到运维中心」一键同步功能，把知识引擎解析的实体批量导入运维中心，让运维中心从"空架子"变成有数据的实用工具。导入后用户可在运维中心手动编辑完善。

### 1.3 非目标

- 不做反向同步（运维中心 → 知识引擎），后续迭代考虑
- 不做实时同步，仅手动触发
- 不做命令/时间线同步（运维中心无对应表）
- 不做文档内容同步（知识引擎的 L3/L4 层不导入）

---

## 2. 总体设计

### 2.1 同步流程

```
用户点击「从知识引擎同步」
    │
    ▼
kb-ops SyncFromIntelligenceController
    │  POST /ops/dashboard/sync-from-intelligence
    ▼
SyncFromIntelligenceService.syncAll()
    │
    ├─→ HTTP GET /intelligence/machine/entities/hosts  (取全量)
    │     │
    │     └─→ 按 IP 去重 → 写入 ops_host
    │
    ├─→ HTTP GET /intelligence/machine/entities/services  (取全量)
    │     │
    │     └─→ 按 name+hostId 去重 → 写入 ops_service
    │
    ├─→ 从 kn_port 查全量 (需 kb-intelligence 新增 listPorts 接口)
    │     │
    │     └─→ 按 hostId+port 去重 → 写入 ops_port
    │
    ├─→ 从 kn_credential 查全量 (需 kb-intelligence 新增 listCredentials 接口)
    │     │
    │     └─→ 按 (hostId+type+username) 去重 → AES 加密 → 写入 ops_credential
    │
    ├─→ 从 kn_domain 查全量 (需 kb-intelligence 新增 listDomains 接口)
    │     │
    │     └─→ 按 domain 去重 → 写入 ops_domain
    │
    └─→ 从 kn_dependency 查全量 (需 kb-intelligence 新增 listDependencies 接口)
          │
          └─→ 按 serviceId+dependsOnServiceId (或名称匹配) 去重 → 写入 ops_dependency
```

### 2.2 通信方式

**kb-ops → kb-intelligence 走 HTTP（RestTemplate）**，不走 Feign（避免循环依赖，kb-intelligence 是上层服务）。

配置项：
```yaml
kb:
  feign:
    intelligence-url: ${INTELLIGENCE_URL:http://kb-intelligence:8086}
```

### 2.3 同步策略

| 策略项 | 说明 |
|--------|------|
| **触发方式** | 手动点击按钮触发，无定时同步 |
| **幂等性** | 每次同步按唯一键判断已存在则更新（可配置跳过/覆盖，默认跳过） |
| **事务** | 每类实体独立事务，一类失败不影响其他类 |
| **数据范围** | 全量同步（知识引擎数据量小，主机 26/服务 0/端口 70/凭据 189/域名 0/依赖 0） |
| **密码处理** | 知识引擎的明文/弱加密密码 → 导入时用 AES-256-GCM 重新加密存储 |
| **ID 映射** | 两边 ID 体系独立，用业务唯一键（IP/name/port 等）关联 |
| **已存在处理** | 默认 `override=false`（跳过已有），前端可选 `override=true`（覆盖更新） |

## 3. 字段映射表

### 3.1 主机（KnHost → Host）

| kb_intelligence.kn_host | kb_ops.ops_host | 说明 |
|-------------------------|-----------------|------|
| name | name | 直接映射 |
| ip | ip | **唯一键**，用于去重 |
| tailscaleIp | tailscaleIp | 直接映射 |
| sshPort | sshPort | 直接映射，默认 22 |
| username | username | 直接映射 |
| passwordEncrypted | passwordEncrypted | 需解密后用 ops 的密钥重新加密（如无法解密则置空） |
| role | role | 直接映射 |
| status (string) | status (int) | 字符串转数字：running→1, stopped→0, maintenance→2，默认 1 |
| tags | tags | 直接映射 |
| remark | remark | 直接映射 |
| osType / osVersion / publicIp / memoryGb 等 | - |  ops 表无对应字段，丢弃，存到 remark 前缀 |

### 3.2 服务（KnService → OpsService）

| kb_intelligence.kn_service | kb_ops.ops_service | 说明 |
|----------------------------|---------------------|------|
| name | name | **唯一键（与 hostId 组合）** |
| serviceType | type | 直接映射 |
| version | version | 直接映射 |
| installPath | deployPath | 映射到部署路径 |
| status (string) | status (int) | running→1, stopped→0, abnormal→2，默认 1 |
| tags | tags | 直接映射 |
| remark | remark | 直接映射 |
| hostId | hostId | 需通过主机同步后的 ID 映射（按 IP 关联） |
| configPath / logPath | - | ops 表无对应字段，丢弃 |

### 3.3 端口（KnPort → Port）

| kb_intelligence.kn_port | kb_ops.ops_port | 说明 |
|-------------------------|-----------------|------|
| port | port | **唯一键（与 hostId 组合）** |
| protocol | protocol | 直接映射（TCP/UDP/HTTP/HTTPS） |
| exposed | exposed | 直接映射 |
| remark | remark | 直接映射 |
| hostId | hostId | 需通过主机同步后的 ID 映射（按 IP 关联） |
| serviceId | serviceId | 需通过服务同步后的 ID 映射（按名称+主机关联） |
| mapping / accessUrl | - | ops 表无对应字段，存入 remark |

### 3.4 凭据（KnCredential → Credential）

| kb_intelligence.kn_credential | kb_ops.ops_credential | 说明 |
|-------------------------------|-----------------------|------|
| credType | type | 直接映射（SSH/DB/API_TOKEN/OTHER） |
| username | username | 直接映射 |
| passwordEncrypted | passwordEncrypted | 解密后用 ops 密钥重新加密，**唯一键（hostId+type+username 组合）** |
| secretKeyEncrypted | secretKey | 解密后用 ops 密钥重新加密 |
| hostId | hostId | 需通过主机同步后的 ID 映射 |
| serviceId | serviceId | 需通过服务同步后的 ID 映射 |
| remark | remark | 直接映射 |
| accessKey / token | - | ops 表无单独字段，存入 remark |

### 3.5 域名（KnDomain → Domain）

| kb_intelligence.kn_domain | kb_ops.ops_domain | 说明 |
|---------------------------|-------------------|------|
| domain | domain | **唯一键** |
| dnsType | type | 映射：A→SUB_DOMAIN, CNAME→SUB_DOMAIN, TOP_LEVEL→TOP_LEVEL，默认 SUB_DOMAIN |
| status (string) | status (int) | active→1, expired→0, pending→2，默认 1 |
| remark | remark | 直接映射 |
| targetHostId / targetPort / targetService | purpose | 拼成用途说明 |
| subDomain | - | ops 表无对应字段，丢弃 |

### 3.6 依赖（KnDependency → Dependency）

| kb_intelligence.kn_dependency | kb_ops.ops_dependency | 说明 |
|-------------------------------|-----------------------|------|
| fromId (service) | serviceId | 需通过服务名称映射 |
| toId (service) | dependsOnServiceId | 需通过服务名称映射 |
| depType | dependencyType | 映射：REQUIRED→REQUIRED, OPTIONAL→OPTIONAL, WEAK→WEAK，默认 REQUIRED |
| remark | description | 映射到描述字段 |
| protocol / port | - | ops 表无对应字段，丢弃 |

## 4. 唯一键与去重规则

| 实体 | 唯一键组合 | 已有数据处理（override=false） | 已有数据处理（override=true） |
|------|-----------|-------------------------------|------------------------------|
| Host | ip | 跳过 | 更新非空字段 |
| OpsService | name + hostId | 跳过 | 更新非空字段 |
| Port | hostId + port | 跳过 | 更新非空字段 |
| Credential | hostId + type + username | 跳过 | 更新非空字段 |
| Domain | domain | 跳过 | 更新非空字段 |
| Dependency | serviceId + dependsOnServiceId | 跳过 | 更新非空字段 |

## 5. API 设计

### 5.1 触发同步

```
POST /kb/api/ops/dashboard/sync-from-intelligence
Content-Type: application/json
Authorization: Bearer <token>

{
  "override": false,
  "entityTypes": ["HOST", "SERVICE", "PORT", "CREDENTIAL", "DOMAIN", "DEPENDENCY"]
}
```

响应：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "host": { "total": 26, "created": 20, "updated": 0, "skipped": 6, "failed": 0 },
    "service": { "total": 0, "created": 0, "updated": 0, "skipped": 0, "failed": 0 },
    "port": { "total": 70, "created": 65, "updated": 0, "skipped": 5, "failed": 0 },
    "credential": { "total": 189, "created": 180, "updated": 0, "skipped": 9, "failed": 0 },
    "domain": { "total": 0, "created": 0, "updated": 0, "skipped": 0, "failed": 0 },
    "dependency": { "total": 0, "created": 0, "updated": 0, "skipped": 0, "failed": 0 },
    "durationMs": 1234
  }
}
```

### 5.2 kb-intelligence 需新增的接口

为支持同步，kb-intelligence 需新增 4 个全量查询接口（因为现有 entities/ 接口返回的是 VO，不含 password 等敏感字段）：

| 接口 | 说明 |
|------|------|
| `GET /intelligence/machine/entities/ports` | 全量端口列表（含 hostId, serviceId） |
| `GET /intelligence/machine/entities/credentials` | 全量凭据列表（含加密密码，需鉴权） |
| `GET /intelligence/machine/entities/domains` | 全量域名列表 |
| `GET /intelligence/machine/entities/dependencies` | 全量依赖关系列表 |

> 注：如果 kb-intelligence 暂不加接口，也可以让 kb-ops 直接配置多数据源直连 kb_intelligence 库，但不符合微服务边界。优先走 HTTP。

## 6. 安全设计

| 风险点 | 防护措施 |
|--------|---------|
| 密码明文传输 | kb-intelligence 返回的密码是加密的（用 its own key），kb-ops 解密后立即用自己的密钥重加密，不落日志 |
| 越权访问 | 同步接口需管理员权限（JWT 鉴权，网关层校验） |
| 误操作覆盖 | 默认 override=false，显式传 true 才覆盖已有数据 |
| 速率限制 | 网关层限流，同一用户 1 分钟最多 1 次同步 |

## 7. 前端设计

### 7.1 入口

- 位置：运维看板页面顶部，右侧操作区
- 按钮：「从知识引擎同步」主按钮 + 下拉「覆盖已有数据」选项
- 点击后：loading 状态 → 成功后展示同步结果弹窗（每类实体的新增/更新/跳过/失败数）

### 7.2 交互流程

1. 用户进入运维看板，看到右上角「从知识引擎同步」按钮
2. 点击按钮，弹出确认框：
   - 提示：将从知识引擎导入主机/服务/端口/凭据/域名/依赖到运维中心
   - 选项：☐ 覆盖已有数据（默认不勾选）
   - 按钮：取消 / 开始同步
3. 点击「开始同步」，按钮变 loading，同步完成后弹出结果卡片
4. 结果卡片展示每类实体的统计，点击「查看详情」跳转对应列表页

## 9. 测试要点

| 测试类型 | 场景 |
|---------|------|
| 单元测试 | 字段映射转换正确性、状态枚举转换、密码加解密、去重逻辑 |
| 集成测试 | HTTP 调用 kb-intelligence 失败降级、事务回滚、部分失败处理 |
| E2E 测试 | 全量同步（空库→有数据）、增量同步（已有数据→跳过）、覆盖同步（已有数据→更新） |
| 安全测试 | 未登录调用应 401、普通用户调用应 403、密码字段在日志中不可见 |

## 10. 风险与约束

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| kb-intelligence 实体数据质量不高（脏 IP/空名称） | 导入垃圾数据 | 同步前做基本校验，IP 格式、名称非空，不合法的跳过并计入 failed |
| 服务/端口的 hostId 映射失败（找不到对应主机） | 关联不上主机 | hostId 置空，remark 标注原始 hostIp，后续人工补 |
| 两边密码密钥不同，无法解密对方密文 | 密码丢失 | 如 kb-intelligence 的密码加密方式与 kb-ops 不同且无法解密，则密码字段置空，由用户手动填写 |
| 知识引擎的数据会变（重新导入文档） | 运维中心数据与知识引擎不一致 | 明确是"一次性导入+手动维护"模式，不做双向同步 |

## 附录 A：知识引擎前端模块设计（M22）

### A.1 模块定位

知识引擎前端模块（kb-web/intel）是 kb-intelligence 服务的只读展示层，负责将知识引擎解析出的文档、实体、命令、时间线等数据以可视化方式呈现给用户。

### A.2 页面结构

| 路由 | 页面 | 说明 |
|------|------|------|
| /intel | 引擎看板 | 统计概览（8 类实体计数 + 文档类型分布 + 快捷入口） |
| /intel/docs | 文档库 | 文档列表（分页）+ 文档详情抽屉（内容 + 关联实体） |
| /intel/hosts | 主机总览 | 主机列表（只读，支持 IP/名称/角色筛选） |
| /intel/services | 服务总览 | 服务列表（只读，支持名称/状态筛选） |
| /intel/ports | 端口总览 | 端口列表（只读，支持端口号/协议/是否暴露筛选） |
| /intel/credentials | 凭据总览 | 凭据列表（只读，密码脱敏展示，支持类型/用户名筛选） |
| /intel/domains | 域名总览 | 域名列表（只读，支持域名/状态筛选） |
| /intel/commands | 命令库 | 命令列表（只读，支持分类/风险筛选，点击复制） |
| /intel/timelines | 时间线 | 运维事件时间轴（支持事件类型/严重程度筛选） |

### A.3 API 对接

前端通过网关调用 kb-intelligence 的 10 个公开查询接口（已有，无需新增后端接口）：

| API | 方法 | 用途 |
|-----|------|------|
| /intelligence/machine/stats | GET | 看板统计 |
| /intelligence/machine/docs | GET | 文档列表（分页） |
| /intelligence/machine/docs/{id}/content | GET | 文档内容 |
| /intelligence/machine/docs/{id}/entities | GET | 文档关联实体 |
| /intelligence/machine/entities/hosts | GET | 主机列表 |
| /intelligence/machine/entities/services | GET | 服务列表 |
| /intelligence/machine/entities/ports | GET | 端口列表 |
| /intelligence/machine/entities/credentials | GET | 凭据列表（密码脱敏） |
| /intelligence/machine/entities/domains | GET | 域名列表 |
| /intelligence/machine/entities/commands | GET | 命令列表 |
| /intelligence/machine/entities/timelines | GET | 时间线列表 |
| /intelligence/machine/search | POST | 文档搜索 |
| /intelligence/machine/docs/{id}/meta | GET | 文档元数据 |

### A.4 侧边栏集成

在 MainLayout.vue 侧边栏中新增「知识引擎」分组（位于「运维中心」和「系统」之间），包含 5 个菜单项：引擎看板、文档库、主机总览、命令库、时间线。

### A.5 数据安全

- 所有页面只读，无新增/编辑/删除操作
- 凭据列表仅展示脱敏后的 passwordHint（首尾字符 + ***）
- 页面顶部有数据来源提示（"数据来源：知识引擎自动解析"）
