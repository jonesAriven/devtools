### 2.3 复用现有表的映射关系

解析引擎需要将提取到的实体写入现有运维表，并关联到 `kn_doc.id`：

| 提取实体 | 写入表 | 关联字段 | 去重策略 |
|---------|--------|---------|---------|
| 主机信息 | ops_host | 按ip去重 | ip唯一，存在则更新 |
| 服务信息 | ops_service | 按name+hostId去重 | name+hostId唯一 |
| 端口信息 | ops_port | 按hostId+port去重 | hostId+port唯一 |
| 凭据信息 | ops_credential | 按name+type去重 | name+type唯一 |
| 域名信息 | ops_domain | 按domain去重 | domain唯一 |
| 依赖关系 | ops_dependency | 按serviceId+dependsOnId去重 | 需新增字段doc_id关联来源 |

## 3. 解析引擎设计

### 3.1 解析流程

```
输入: path = "D:\\...\\openclaw-work-space", recursive=true, sourceId="openclaw-20260628"
  │
  ▼
Step 1: 文件扫描 (FileScanner)
  │  递归遍历目录，过滤 .md/.txt 文件(.png上传MinIO)
  │  跳过 .idea/、node_modules/、垃圾文件(less帮助页)
  │  对每个文件计算 SHA256(content_hash)
  │  查 kn_doc 表:
  │    - 存在且hash相同 → 跳过(未修改)
  │    - 存在且hash不同 → 标记为更新，先清除旧关联数据
  │    - 不存在 → 标记为新增
  ▼
Step 2: 类型识别 (DocTypeDetector)
  │  按规则判定每个文件的 doc_type (A-E)
  │  见3.2类型识别规则
  ▼
Step 3: 分类型解析
  │
  ├─ A: TABLE  → TableParser.parse(file)      → List<Entity>+Credential+Port
  ├─ B: PLAN   → PlanDocParser.parse(file)    → List<Entity>+Command+Parameter(需LLM)
  ├─ C: TIMELINE → TimelineParser.parse(file) → List<TimelineEvent>
  ├─ D: GRAPH  → GraphParser.parse(file)      → List<Relation>
  └─ E: RULE   → RuleParser.parse(file)       → Command+Content(需LLM)
  │
  ▼
Step 4: LLM增强 (LlmClient)
  │  对类型B/E调用LLM:
  │    - 生成100字摘要
  │    - 生成3-5个标签
  │    - 提取结构化参数/命令(类型B)
  │    - 提取约束条件(类型E)
  ▼
Step 5: 内容精简 (ContentCleaner)
  │  - 去除emoji、Markdown格式标记(**、~~、|、表格边框)
  │  - 保留##/###章节标题
  │  - 代码块保留纯文本
  │  - 表格转纯文本列表
  │  - 按##切分为sections
  │  → 写入 MongoDB kn_content
  ▼
Step 6: 实体落库 (EntityPersister)
  │  - Host/Service/Port/Credential/Domain → 写入现有表(去重)
  │  - 写入 kn_doc_entity_ref 关联表
  │  - Command → 写入 kn_command
  │  - TimelineEvent → 写入 kn_timeline
  ▼
Step 7: 向量生成 (VectorService)
  │  - 调用 bge-small-zh(或在线Embedding API)生成512维向量
  │  - 写入 MeiliSearch kn_vectors 索引
  ▼
Step 8: 返回结果
  │  {sourceId, totalFiles, imported, updated, skipped, entities, commands, ...}
```

### 3.2 类型识别规则（DocTypeDetector）

```java
public class DocTypeDetector {

    public DocType detect(String fileName, String content) {
        String name = fileName.toLowerCase();

        // 类型A: 结构化表格 - 文件名关键词
        if (name.contains("清单") || name.contains("速查") || name.contains("汇总")
            || name.contains("映射") || name.contains("账密") || name.contains("端口")) {
            return DocType.TABLE;
        }

        // 类型C: 时间线记录 - 文件名关键词
        if (name.contains("踩坑") || name.contains("记录") || name.contains("报告")
            || name.contains("日志") || name.contains("健康检查")) {
            return DocType.TIMELINE;
        }

        // 类型D: 关系数据 - 内容特征
        if (content.contains("├──") || content.contains("└──")
            || content.contains("mermaid") || content.contains("→")
            || (content.contains("流量图") || content.contains("依赖关系"))) {
            return DocType.GRAPH;
        }

        // 类型E: 规则文档 - 文件名关键词
        if (name.contains("规则") || name.contains("规范") || name.contains("约定")) {
            return DocType.RULE;
        }

        // 类型B: 方案文档 - 文件名关键词或默认
        if (name.contains("方案") || name.contains("架构") || name.contains("部署")
            || name.contains("接入") || name.contains("配置") || name.contains("总览")) {
            return DocType.PLAN;
        }

        // 内容特征二次判定
        long tableLines = content.lines().filter(l -> l.trim().startsWith("|")).count();
        long totalLines = content.lines().count();
        if (totalLines > 0 && (double) tableLines / totalLines > 0.5) {
            return DocType.TABLE;
        }

        // 含bash代码块+参数表→方案
        if (content.contains("```bash") || content.contains("```shell")) {
            return DocType.PLAN;
        }

        // 默认归为方案
        return DocType.PLAN;
    }
}
```

### 3.3 类型A解析器 — TableParser（正则精确抽取，零LLM）

以主机清单为例，核心算法：

```java
public class TableParser {

    public ParsedDoc parseHostTable(Long docId, String content) {
        ParsedDoc result = new ParsedDoc(docId);
        String[] lines = content.split("\n");
        List<String> headers = null;

        for (String line : lines) {
            line = line.trim();
            if (!line.startsWith("|")) continue;

            // 跳过分隔行 |---|---|
            if (line.matches("\\|\\s*[-:]+\\s*(\\|\\s*[-:]+\\s*)*\\|")) continue;

            String[] cells = parseTableRow(line);
            if (cells.length == 0) continue;

            if (headers == null) {
                headers = Arrays.stream(cells)
                    .map(String::trim)
                    .map(h -> h.replaceAll("[\\s\\p{Punct}]+$", ""))
                    .collect(Collectors.toList());
                continue;
            }

            Map<String, String> row = new LinkedHashMap<>();
            for (int i = 0; i < Math.min(headers.size(), cells.length); i++) {
                row.put(headers.get(i), cleanCell(cells[i]));
            }

            // 根据表头判定是哪种表
            if (headers.contains("机器") && headers.contains("IP")) {
                result.addHost(parseHostRow(row));
            } else if (headers.contains("端口") && headers.contains("服务")) {
                result.addPort(parsePortRow(row, docId));
            } else if (headers.contains("应用") && headers.contains("账号")) {
                result.addCredential(parseCredentialRow(row));
            } else if (headers.contains("域名") && headers.contains("解析到")) {
                result.addDomain(parseDomainRow(row));
            } else if (headers.contains("项目") && headers.contains("值")) {
                result.addCredential(parseKvCredentialRow(row));
            }
        }
        return result;
    }

    private String[] parseTableRow(String line) {
        // 去掉首尾|后按|分割
        String trimmed = line;
        if (trimmed.startsWith("|")) trimmed = trimmed.substring(1);
        if (trimmed.endsWith("|")) trimmed = trimmed.substring(0, trimmed.length() - 1);
        return trimmed.split("\\|", -1);
    }

    private String cleanCell(String cell) {
        return cell.trim()
            .replaceAll("`", "")           // 去掉反引号
            .replaceAll("🖥️|✅|❌|⚠️|~~", "")  // 去掉emoji和删除线
            .replaceAll("~~", "")
            .trim();
    }
}
```

**LlmClient实现（使用RestClient调用通义千问DashScope API）**:

```java
@Service
public class LlmClient {

    @Value("${knowledge.llm.api-url:https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions}")
    private String apiUrl;
    @Value("${knowledge.llm.api-key:}")
    private String apiKey;
    @Value("${knowledge.llm.model:qwen-plus}")
    private String model;
    @Value("${knowledge.llm.enabled:true}")
    private boolean enabled;

    private final RestClient restClient;

    public LlmClient() {
        this.restClient = RestClient.builder()
            .defaultHeader("Content-Type", "application/json")
            .build();
    }

    public <T> T extract(String prompt, Class<T> responseType) {
        if (!enabled || !StringUtils.hasText(apiKey)) {
            // LLM未配置时返回空结果，降级为仅规则解析
            return createEmpty(responseType);
        }
        Map<String, Object> body = Map.of(
            "model", model,
            "messages", List.of(
                Map.of("role", "system", "content", "你是一个精确的结构化数据提取引擎，只返回JSON。"),
                Map.of("role", "user", "content", prompt)
            ),
            "temperature", 0.1,    // 低温度，保证精确性
            "response_format", Map.of("type", "json_object")
        );
        try {
            String response = restClient.post()
                .uri(apiUrl)
                .header("Authorization", "Bearer " + apiKey)
                .body(body)
                .retrieve()
                .body(String.class);
            // 解析响应，提取content字段中的JSON
            JsonNode root = objectMapper.readTree(response);
            String content = root.path("choices").get(0).path("message").path("content").asText();
            return objectMapper.readValue(content, responseType);
        } catch (Exception e) {
            log.warn("[LLM] 调用失败，降级处理: {}", e.getMessage());
            return createEmpty(responseType);
        }
    }
}
```

### 3.5 内容精简（ContentCleaner, Layer 3）

```java
@Component
public class ContentCleaner {

    private static final Pattern EMOJI = Pattern.compile("[\\x{1F300}-\\x{1F9FF}]");
    private static final Pattern BOLD = Pattern.compile("\\*\\*(.+?)\\*\\*");
    private static final Pattern STRIKE = Pattern.compile("~~(.+?)~~");
    private static final Pattern CODE = Pattern.compile("`([^`]+)`");
    private static final Pattern HEADER = Pattern.compile("^(#{2,3})\\s+(.+)$", Pattern.MULTILINE);

    public KnContent clean(Long docId, String markdown) {
        KnContent content = new KnContent();
        content.setDocId(docId);

        // 1. 提取章节
        List<Section> sections = extractSections(markdown);
        content.setSections(sections);

        // 2. 生成纯文本（去格式）
        String plain = markdown;
        plain = plain.replaceAll("```[a-z]*\\n?", "\n").replace("```", "\n");  // 代码块
        plain = BOLD.matcher(plain).replaceAll("$1");
        plain = STRIKE.matcher(plain).replaceAll("");
        plain = CODE.matcher(plain).replaceAll("$1");
        plain = EMOJI.matcher(plain).replaceAll("");
        // 表格行: 去掉|分隔符
        plain = plain.lines()
            .map(l -> l.startsWith("|") ? tableToText(l) : l)
            .filter(l -> !l.matches("\\|?\\s*[-:]+\\s*(\\|\\s*[-:]+\\s*)*\\|?"))
            .collect(Collectors.joining("\n"));
        content.setPlainText(plain.trim());
        content.setWordCount(plain.trim().length());
        return content;
    }

    private List<Section> extractSections(String markdown) {
        List<Section> sections = new ArrayList<>();
        String[] parts = markdown.split("(?=^##\\s+)", Pattern.MULTILINE);
        for (String part : parts) {
            String trimmed = part.trim();
            if (trimmed.isEmpty()) continue;
            String title = trimmed.lines().findFirst().orElse("")
                .replaceAll("^#{2,3}\\s+", "").trim();
            String body = trimmed.lines().skip(1)
                .collect(Collectors.joining("\n")).trim();
            Section s = new Section();
            s.setId(generateId(title));
            s.setTitle(title);
            s.setLevel(title.startsWith("### ") ? 3 : 2);
            s.setContent(cleanInline(body));
            s.setWordCount(s.getContent().length());
            sections.add(s);
        }
        return sections;
    }

    private String generateId(String title) {
        return PinyinUtil.getPinyin(title).toLowerCase()
            .replaceAll("[^a-z0-9]+", "-")
            .replaceAll("^-|-$", "");
    }
}
```

## 7. 安全设计

### 7.1 路径安全

```java
// 导入接口必须校验路径在白名单内
private void validatePath(String path) {
    Path p = Paths.get(path).normalize().toAbsolutePath();
    boolean allowed = allowedPaths.stream()
        .map(ap -> Paths.get(ap).normalize().toAbsolutePath())
        .anyMatch(ap -> p.startsWith(ap));
    if (!allowed) {
        throw new BusinessException(403, "路径不在允许范围内: " + path);
    }
}
```

### 7.2 凭据安全

- 凭据密码使用现有 `CryptoUtil` AES-256-GCM 加密存储
- API返回时解密为明文（AI需要直接使用）
- 机器版API建议使用API Token认证（比JWT更适合服务间调用）
- 可配置是否在API中返回明文密码（通过环境变量控制）

### 7.3 LLM安全

- LLM API Key 通过环境变量注入，不硬编码
- LLM调用超时30秒，失败降级为规则解析
- 发送给LLM的内容截断为4000 Token，防止泄露过多信息
- temperature设为0.1，尽量减少幻觉

## 11. 实现状态与差异分析（v2.1 校准版）

> **本章为 v2.1 校准章节**，记录 v2.0 设计方案的实际落地情况。**实际实现以本章为准**，前面章节保留为设计历史。

### 11.1 架构决策变更：独立微服务化（与 v2.0 设计存在重大差异）

| 维度 | v2.0 设计 | v2.1 实际实现 | 差异原因 |
|------|----------|--------------|---------|
| 模块位置 | 在 kb-ops 中扩展（com.kb.ops.knowledge/*） | **独立微服务 kb-intelligence**（com.kb.intelligence.*） | 知识引擎职责单一且重（含解析器+LLM+MongoDB+向量），独立部署便于独立扩缩容、独立升级解析器而不影响 kb-ops 运维功能 |
| 服务端口 | 复用 kb-ops 8084 | **独立端口 8086** | 与 kb-ops 解耦 |
| 网关路由 | 复用 `/kb/api/ops/**` | **新增 `/kb/api/intelligence/**`** | 独立路由前缀，便于权限隔离 |
| API 路径前缀 | `/ops/knowledge/...` | **`/intelligence/{import,machine}/...`** | 语义更清晰，明确区分"导入"和"机器版查询" |
| 包路径 | com.kb.ops.* | **com.kb.intelligence.*** | 独立 Maven 模块 + 独立 Spring 容器 |
| 数据库 | 复用 kb_ops 库 | **独立 kb_intelligence 库**（含 10 张表） | 隔离知识引擎数据，避免污染 kb_ops 运维表 |

**决策修正说明**：v2.0 设计阶段倾向"最小改动复用 kb-ops"，但实际编码时发现：
1. 知识引擎引入了 MongoDB + MeiliSearch + LLM Client 三类重型依赖，若塞入 kb-ops 会导致 kb-ops 镜像体积膨胀、启动变慢
2. 解析器有 12 个类（v2.0 设计低估了复杂度），独立模块更清晰
3. 独立部署后，知识引擎可独立升级（如新增解析器类型）而无需重启 kb-ops

**降级策略**：
- 应用启动时检测 MongoDB 连接，可用则注入 MongoContentStorage
- 不可用则注入 InMemoryContentStorage（数据不持久化，重启丢失）
- 通过 Spring `@ConditionalOnProperty` 或 `@Profile` 切换

**KnContent 结构**（与 v2.0 设计基本一致）：
- `id`：MongoDB ObjectId
- `docId`：关联 kn_doc.id
- `sections`：按 ## 切分的章节列表
- `plainText`：去格式化全文纯文本
- `wordCount`：字数

### 11.11 与 v2.0 设计的差异原因分析

| 差异类别 | 差异点 | 原因分析 |
|---------|--------|---------|
| 架构层面 | 独立微服务 vs 复用 kb-ops | 实际编码时发现依赖过重（MongoDB+MeiliSearch+LLM），独立部署更合理 |
| 接口路径 | `/intelligence/*` vs `/ops/knowledge/*` | 独立微服务后路由前缀自然分离 |
| 接口拆分 | 按实体类型拆分 vs type 参数过滤 | RESTful 风格更清晰，前端调用更直观 |
| 解析器降级 | GRAPH/RULE 用 GeneralParser 兜底 | Phase 1 优先保证 TABLE/PLAN/TIMELINE 三种核心类型，GRAPH/RULE 留待 Phase 1.5 |
| LLM 默认禁用 | `enabled=false` vs `enabled=true` | 避免开发环境消耗 API 配额，生产环境按需启用 |
| ImportStats 简化 | `successFiles/failedFiles` vs 详细的 `newImported/updated/skipped/entities` | 简化首版实现，实体统计通过 `/stats` 接口查询 |
| 安全限制未实现 | `allowed-paths` 白名单未配置 | Phase 1 内网部署，路径安全由部署环境保障；Phase 2 生产环境前需补充 |
| 向量服务未实现 | VectorService 未创建 | Phase 2 范围，Phase 1 用 MeiliSearch 关键词搜索兜底 |
