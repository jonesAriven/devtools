## 1. 概述

### 1.1 系统架构

MyKNG 采用 **Spring Cloud Gateway 微服务架构**，由网关统一负责路由转发、JWT 鉴权、跨域处理、限流与链路追踪。后端拆分为 4 个业务服务：

| 服务 | 端口 | 职责 |
|------|------|------|
| `kb-gateway` | 8090 | API 网关，统一入口、鉴权、路由 |
| `kb-auth` | 8081 | 认证授权、用户管理、API Token 管理 |
| `kb-file` | 8082 | 文件上传/合并/解析、对象存储桶管理 |
| `kb-knowledge` | 8083 | 文档、文件夹、空间、标签、搜索、分享、回收站、版本、网页收藏 |
| `kb-ops` | 8084 | 运维看板、矛盾检测、主机/服务管理、部署记录、数据导入、运维知识 |

```
                        ┌─────────────────────┐
   Client / Frontend ──►│   kb-gateway (:8090) │
                        │  /kb/api/**          │
                        └──────┬───────────────┘
               ┌───────────────┼───────────────┬────────────────┐
               ▼               ▼               ▼                ▼
        ┌──────────┐    ┌──────────┐    ┌────────────┐    ┌──────────┐
        │ kb-auth  │    │ kb-file  │    │kb-knowledge│    │  kb-ops  │
        │  :8081   │    │  :8082   │    │   :8083    │    │  :8084   │
        └──────────┘    └──────────┘    └────────────┘    └──────────┘
```

### 1.2 公网访问路径说明

所有对外接口统一通过网关暴露，公网路径格式为：

```
http://{网关地址}{上下文路径}/api/{module}/{action}
```

- **上下文路径**：`/kb`（默认值，由环境变量 `KB_CONTEXT` 控制，修改后所有路由前缀同步变更）
- **API 标识**：`/api`（固定，不可更改）
- **功能模块**：由 Controller 的 `@RequestMapping` 定义，如 `/auth`、`/file`、`/doc`、`/ops/host` 等
- **StripPrefix=2**：网关转发时剥离 `/kb/api` 两段路径，后端服务收到的是 `/{module}/{action}`

> **示例**：客户端请求 `GET http://localhost:8090/kb/api/user/profile`  
> 网关转发至 `http://localhost:8081/user/profile`（kb-auth 服务）

#### 路由映射表

| 网关路由 ID | 网关匹配路径（/kb/api 前缀下） | 转发目标 |
|-------------|-------------------------------|----------|
| kb-auth | `/auth/**`、`/user/**`、`/token/**` | kb-auth:8081 |
| kb-file | `/file/**`、`/bucket/**` | kb-file:8082 |
| kb-knowledge | `/doc/**`、`/folder/**`、`/web/**`、`/search/**`、`/share/**`、`/tag/**`、`/space/**`、`/trash/**`、`/version/**` | kb-knowledge:8083 |
| kb-ops | `/ops/**`、`/log/**` | kb-ops:8084 |

### 1.3 认证机制

#### 认证方式

采用 **JWT Bearer Token** 认证。客户端在请求头中携带 Access Token：

```
Authorization: Bearer <accessToken>
```

#### Token 类型

| Token 类型 | 用途 | 说明 |
|-----------|------|------|
| **Access Token** | 访问业务接口 | JWT 格式，type=access，有过期时间 |
| **Refresh Token** | 刷新 Access Token | 用于 `/auth/refresh` 接口换取新的令牌对 |
| **API Token** | 第三方系统调用 | 通过 `/token` 创建的长期令牌，明文仅返回一次 |

#### 鉴权流程

1. 网关 `JwtAuthFilter` 拦截所有 `/kb/api/**` 路径请求（白名单除外）
2. 从 `Authorization` 头提取 Bearer Token
3. 使用 HMAC-SHA 本地验签 + 校验过期 + 校验 `type=access`
4. 校验通过：清除客户端伪造的 `X-User-Id`，注入真实 `userId`/`username` 到下游请求头
5. 校验失败：返回 `401` 统一 JSON 响应（携带 `traceId`）

#### 白名单（免认证路径）

| 路径 | 说明 |
|------|------|
| `/kb/api/auth/login` | 用户登录 |
| `/kb/api/auth/refresh` | 刷新令牌 |
| `/kb/api/share/verify/**` | 分享验证（公开访问） |
| `/kb/api/token/verify` | API Token 验证（kb-auth 内部 permitAll） |

> 所有 `OPTIONS` 预检请求（CORS）自动放行。

#### 令牌刷新机制

Access Token 过期后，客户端使用 Refresh Token 调用 `/auth/refresh` 获取新的令牌对。建议前端在检测到 401 响应时自动执行刷新流程。

### 1.4 统一返回格式

#### Result\<T\>（通用返回格式）

所有接口统一返回 `Result<T>` 结构：

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "traceId": "a1b2c3d4e5f6"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | `int` | 状态码，`200` 表示成功，其余为错误码 |
| `message` | `string` | 状态描述信息 |
| `data` | `T` | 业务数据，失败时为 `null` |
| `traceId` | `string` | 链路追踪 ID，用于问题排查（由 `TraceIdFilter` 自动生成注入） |

#### PageResult\<T\>（分页返回格式）

分页接口的 `data` 字段为 `PageResult<T>`：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "list": [],
    "total": 100,
    "page": 1,
    "size": 20
  },
  "traceId": "a1b2c3d4e5f6"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `list` | `List<T>` | 当前页数据列表 |
| `total` | `long` | 总记录数 |
| `page` | `int` | 当前页码（从 1 开始） |
| `size` | `int` | 每页条数 |

### 1.5 错误码对照表

| 错误码 | HTTP Status | 说明 | 典型场景 |
|--------|-------------|------|----------|
| **200** | 200 | 成功 | 正常请求 |
| **400** | 400 | 参数校验失败 / 请求格式错误 | 必填字段缺失、参数类型不匹配、导入数据为空、不支持的导入类型 |
| **401** | 401 | 未认证 / 认证失效 | 缺少 Token、Token 无效、Token 已过期、令牌类型错误、RefreshToken 无效、API Token 为空/过期、用户不存在或已禁用 |
| **403** | 403 | 无权限 | 无权操作他人资源（如他人创建的 Token） |
| **404** | 404 | 资源不存在 | 文件不存在、Bucket 不存在 |
| **409** | 409 | 资源冲突 | IP 已存在等唯一约束冲突 |
| **500** | 500 | 服务内部错误 | 未捕获异常、业务逻辑异常（未指定错误码时默认 500） |

#### 401 响应示例

```json
{
  "code": 401,
  "message": "访问令牌无效或已过期",
  "data": null,
  "traceId": "a1b2c3d4e5f6"
}
```

#### 400 参数校验失败示例

```json
{
  "code": 400,
  "message": "参数校验失败: username: 用户名不能为空; password: 密码不能为空",
  "data": null,
  "traceId": "a1b2c3d4e5f6"
}
```
