# ADR: kb 统一日志架构（三路输出 + Kafka 总线）

- 日期: 2026-08-23
- 状态: 已实施（kb 六模块+portal-server+activecode 八应用接入；Kafka→Loki 消费端已建成）
- 关联流水线: #378(失败) #379(成功)，提交 8fc1e5e / ab16863

## 背景

对家庭日志体系全面盘点后发现：

1. kb 五模块各自持有私有 logback-spring.xml，与 kb-common 公共配置仅注释级差异（配置漂移，无实质个性化）
2. kb-common v2 公共配置内置 KAFKA appender（springProfile=kafka-log 条件激活），且 compose 环境变量早已配 `SPRING_PROFILES_ACTIVE=prod,kafka-log`——但五模块私有配置无 KAFKA 段，profile 空转
3. app-logs topic 唯一生产者是 kb-ops（854 条历史消息），零消费者
4. kb-ops 是独立项目（/root/devtools/kb-ops，不依赖 kb-common jar），靠"复制配置副本"接入

## 考虑过的方案

1. **砍掉 Kafka 通道，单轨 stdout→Loki**：Loki 链路已验证全通，Kafka 无消费端属堆积。被否——保留总线口子，后续 Kafka→Loki/ES 消费端有审计/离线分析/多订阅价值
2. **全模块统一 kb-common 配置 + kafka-log profile，消费端后补**（采纳）
3. portal-server/activecode 跨项目引入 kb-common 依赖：被否——两者是独立系统，不应跨依赖；采用**复制配置**方式接入（与 kb-ops 同模式）

## 决策

1. kb 五模块（gateway/auth/file/knowledge/intelligence）删除私有 logback-spring.xml，统一走 kb-common jar 内配置
2. **kb-common 加回 kb-parent Reactor**（源码构建），废弃"独立发布到 Nexus"模式——见事故记录
3. portal-server 与 activecode：复制 kb-common 的 logback-spring.xml 副本进各自 resources（不引依赖）；portal-server 的 compose env 已带 kafka-log，只需加配置文件；activecode 需同时补 env
4. Kafka→Loki 消费端：后续专项补全（暂无消费者，消息按保留策略自然过期，堆积无害）

## 事故记录（流水线 #378，五服务启动全崩）

- 现象: ClassNotFoundException: com.github.danielwegener.logback.kafka.KafkaAppender，五服务 Exited(1)
- 根因: 构建脚本只构建 kb-parent Reactor 的五服务，kb-common 从 Nexus 拉——仓库上的 kb-common 1.2.0 是"半新"货：jar 内 logback-spring.xml 含 KAFKA 段，但 pom 元数据无 logback-kafka-appender 依赖（源码 pom 的依赖改动未同步发布到 Nexus）。配置要加载类，classpath 却无类
- 修复: kb-common 加回 Reactor（ab16863），配置与依赖永远同源，此类故障根除
- 教训: 多模块项目改公共库配置/依赖后，必须验证构建产物中公共库的实际来源（Reactor 源码 vs 仓库旧货），源码正确 ≠ 产物正确

## 现行日志链路全景

```
应用 stdout(JSON,含traceId) ─→ docker json-file ─→ promtail(docker_sd) ─→ Loki(182:15100, 7天) ─→ Grafana
应用 FILE(容器内 /data/logs/<app>.log, 50MB/天/30天/5GB)  ← 容器可写层，随容器重建丢失（已知盲区）
应用 KAFKA(topic=app-logs, 单partition, 192.168.31.105:9092)  ← 零消费者，待建消费端
traceId: TraceIdInterceptor 入口注入 MDC → FeignTraceIdInterceptor 出站传播 → 网关 WebFluxMdcConfig(Hooks)
```

## 后果

- 正面: 日志配置单一事实源（kb-common 一份）；kb 六模块 Kafka 全接入（验证 230 条启动消息）；profile 开关即总闸（去掉 kafka-log 即关通道）
- 代价: mykng 构建时长 +约15s（kb-common 参与编译）；portal/activecode 的配置副本存在漂移风险（kb-common 改配置需手动同步，记入运维手册）
- 遗留: Nexus 上 kb-common 1.2.0 旧货仍在（无引用方，待清理）；Docker json-file 无轮转（woodpecker-server 已 562M）；promtail 走 Tailscale 未改直连
