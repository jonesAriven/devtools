## 一、P0 严重问题（阻断/安全/数据丢失，必须立即修复）

### P0-1 全代码库无任何角色权限控制（RBAC 缺失）
- **现象**：全代码库搜索 `@PreAuthorize`/`hasRole`/`hasAuthority`/`ROLE_ADMIN` 零命中。`GatewayAuthFilter`（kb-knowledge）硬编码 `List.of(new SimpleGrantedAuthority("ROLE_USER"))`，所有用户身份无差别。`kb-intelligence/SecurityConfig.java` `anyRequest().permitAll()`。
- **影响**：PRD 明确要求管理员专属功能（M03 用户管理、M07 桶管理、M17 运维看板、M18 运维资源 CRUD、M19 矛盾检测、M20 知识导入、M21 同步、M22 知识引擎模块）任何登录用户均可访问。普通用户可执行同步、删除主机、清空回收站、管理存储桶、查看所有用户操作日志、管理 API Token 等高危操作。
- **建议方案**：
  1. 在 `JwtTokenProvider` 生成 token 时写入 `role` claim（admin/user）
  2. 网关 `JwtAuthFilter` 注入 `X-User-Role` 头
  3. 各服务 `GatewayAuthFilter` 解析 role 并设置 `ROLE_ADMIN`/`ROLE_USER`
  4. 在所有管理员接口加 `@PreAuthorize("hasRole('ADMIN')")`
  5. 前端根据 `user.role` 控制菜单显隐

### P0-2 kb-intelligence 内部接口泄露全部凭据
- **现象**：`KnowledgeMachineController.java` 定义了 6 个 `/internal/*` 端点（`/internal/hosts`、`/internal/services`、`/internal/ports`、`/internal/credentials`、`/internal/domains`、`/internal/dependencies`），返回完整实体含敏感字段。kb-intelligence `SecurityConfig` 是 `anyRequest().permitAll()`，任何登录用户均可调用。
- **影响**：`/internal/credentials` 直接返回所有凭据（含密码密文），`/internal/hosts` 暴露所有主机 IP，构成严重数据泄露。
- **建议方案**：
  1. 将 `/internal/**` 端点改为服务间 Feign 内部调用，不暴露 HTTP 接口；或
  2. 在 kb-intelligence SecurityConfig 中对 `/intelligence/machine/internal/**` 要求 `ROLE_ADMIN` 且校验来源 IP 为内网；或
  3. 网关层对 `/api/intelligence/machine/internal/**` 配置 IP 白名单（仅允许 kb-ops 服务调用）

### P0-3 JWT 密钥硬编码在配置文件
- **现象**：`kb-gateway/src/main/resources/application.yml` `secret: YourSuperSecretKeyForJwtTokenGenerationMustBe256BitsLong!!`，明文写死在源码仓库。
- **影响**：任何能读到源码的人可伪造任意用户（含管理员）的 access token，完全绕过鉴权。这是整个系统安全的根基。
- **建议方案**：
  1. 密钥移到环境变量 `JWT_SECRET`（通过 `.env` + docker-compose 注入）
  2. 生产环境使用 256 位随机密钥，禁止提交到 git
  3. `.env.example` 只放占位符不放真实值

### P0-4 搜索结果 XSS 漏洞
- **现象**：`SearchView.vue` `<div class="resource-name" v-html="item.title"></div>`、`<span v-html="item.highlight"></span>`，将后端返回的搜索标题和高亮片段直接以 HTML 渲染。
- **影响**：若文档标题或内容含 `<script>`/`<img onerror>` 等载荷，访问搜索页即可触发 XSS，盗取 token 或执行越权操作。
- **建议方案**：
  1. 后端对高亮片段做 HTML 转义后再包 `<em>` 标签
  2. 前端引入 `DOMPurify`，`v-html` 前清洗：`v-html="DOMPurify.sanitize(item.title)"`
  3. 或改用 `v-text` + 自定义高亮组件（推荐）

### P0-5 分片上传功能未实现（PRD M05 未完成）
- **现象**：`FileUpload.vue` UI 文案"大文件自动分片"，但实际只用 `FormData` 整体上传，无分片逻辑。`FileListView.vue` 同理。
- **影响**：PRD M05 验收标准"所有分片合并成功，生成唯一 fileId"完全未实现。大文件（>30MB）会因前端 30s 超时或网关限制失败。后端 `KbFileController` 有分片接口但前端未对接。
- **建议方案**：
  1. 前端实现分片上传：按 5MB 切片 → 并发上传分片 → 调用合并接口
  2. 增加分片进度、断点续传、失败重试
  3. 移除"大文件自动分片"文案直到实现，避免误导

### P0-6 SettingsView 函数名拼写错误导致运行时崩溃
- **现象**：`SettingsView.vue` 定义 `async function toggleTokenStat(id: number)`（少一个 `us`），但模板调用 `toggleTokenStatus(row.id)`。
- **影响**：用户点击"禁用/启用"Token 按钮时，JS 报 `toggleTokenStatus is not defined`，操作直接失败且无任何反馈。
- **建议方案**：将函数名改为 `toggleTokenStatus`。

### P0-7 无 404 兜底路由
- **现象**：`router/index.ts` 未定义 `path: '/:pathMatch(.*)*'` 的 catch-all 路由。
- **影响**：用户输错 URL 或点击失效链接，看到空白页，无任何提示，误以为系统卡死。
- **建议方案**：在路由表末尾添加 `{ path: '/:pathMatch(.*)*', name: 'NotFound', component: () => import('@/views/404.vue') }`。

### P0-8 PRD M03 用户管理完全未实现
- **现象**：`UserController.java` 仅有 `/profile`(GET/PUT)、`/password`(PUT) 三个端点，无 `/list`、`/POST`(创建)、`/DELETE`(删除)、`/PUT/{id}/status`(禁用启用)。前端无用户管理页面。
- **影响**：PRD M03 验收标准"管理员创建/禁用/删除用户"完全无法执行。系统无法新增用户（只能改库表），无法禁用离职用户。
- **建议方案**：
  1. 后端新增 `UserController` 的 list/create/delete/toggleStatus 端点（管理员鉴权）
  2. 前端新增 `views/system/UserManageView.vue`
  3. 补充注册/忘记密码流程（可选）

### P0-9 CORS 配置允许任意源携带凭证
- **现象**：`kb-gateway/application.yml` `allowedOriginPatterns: "*"` + `allow-credentials: true`。
- **影响**：任何恶意网站可携带用户 cookie/Authorization 头发起跨域请求，构成 CSRF。
- **建议方案**：将 `allowedOriginPatterns` 改为精确域名列表（如 `https://kb.marschat.online`）。

## 二、P1 严重问题（功能缺失/体验差/性能隐患）

### P1-1 文档编辑无自动保存（数据丢失风险）
- **现象**：`DocEditView.vue` `handleSave` 仅手动触发，无定时保存、无离开提示。
- **影响**：浏览器崩溃、断电、误关标签页，所有未点"保存"的内容丢失。
- **建议方案**：每 30s 自动保存草稿到 localStorage；每 2 分钟调用 `updateDoc`；`beforeunload` 事件提示未保存。

### P1-2 同步功能缺少预览和历史（PRD M21/M23 部分实现）
- **现象**：`SyncController.java` 仅 `POST /from-intelligence` 一个端点，无 `/preview`、无 `/history`。
- **影响**：PRD M23 要求"弹出同步预览框，展示即将新增/更新/跳过的数量"和"可在同步历史中查看过往记录"，均未实现。
- **建议方案**：新增 `POST /ops/sync/preview` 和 `GET /ops/sync/history`。

### P1-3 知识导入同步阻塞且无路径校验
- **现象**：`KnowledgeImportController.java` `importByPath` 同步执行，无路径白名单校验。`status` 端点是假实现，永远返回 `"running"`。
- **影响**：大目录导入超过前端 30s 超时；可传任意服务器路径存在信息泄露风险。
- **建议方案**：改为异步任务 + 路径白名单 + 进度查询。

### P1-4 网页收藏无 URL 校验（SSRF 风险）
- **现象**：`WebPageController.java` `collect` 无 URL 格式校验、无内网 IP 黑名单。
- **影响**：用户可提交 `http://192.168.1.1/admin` 等内网地址，构成 SSRF。
- **建议方案**：后端校验 URL 格式 + 禁止内网 IP + 限制抓取超时和响应体大小。

### P1-5 GlobalExceptionHandler 缺少自定义异常处理
- **现象**：仅处理 `BusinessException`、`MethodArgumentNotValidException`、`Exception`。`NotFoundException`、`NoPermissionException`、`NotLoginException`、`ConflictException`、`FileParseException` 均无对应 handler。
- **影响**：抛出 `NotFoundException` 会被兜底为 500，前端无法区分"不存在"和"服务器错误"。
- **建议方案**：为每个自定义异常加 `@ExceptionHandler`，返回对应 HTTP 状态码和业务码。

### P1-6 操作日志筛选不完整（PRD S01 部分实现）
- **现象**：`OpsLogView.vue` 有日期范围选择器，但 `loadData` 只传 `action` 和 `resourceType`，日期范围被丢弃。无用户筛选。
- **影响**：PRD S01 要求"按时间/用户/操作类型查询"，时间筛选无效。
- **建议方案**：补全 `startTime`/`endTime`/`userId` 参数传递。

### P1-7 网关未校验 token 黑名单（登出不立即生效）
- **现象**：`JwtAuthFilter.java` 仅验签和查过期，未查询 `jwt_blacklist` 表。
- **影响**：用户登出后，旧 token 在 15 分钟内仍可用。
- **建议方案**：网关登录出时把 token 加入 Redis 黑名单，网关每次验签后查 Redis。

### P1-8 文件上传无类型/大小校验
- **现象**：`FileUpload.vue` 不校验文件类型和大小。
- **影响**：可上传 `.exe`、`.sh`、`.jsp` 等可执行文件；可上传超大文件导致存储耗尽。
- **建议方案**：前端限制白名单扩展名 + 单文件 100MB 上限；后端二次校验 MIME 类型。

### P1-9 文档状态机未实现（PRD 3.1）
- **现象**：`DocController.java` 无 `/publish`、`/unpublish` 端点，`Doc` 实体无 `status` 字段流转逻辑。
- **影响**：所有文档默认就是"发布"状态，无草稿概念。
- **建议方案**：补充 `status` 字段流转接口和 UI 按钮。

### P1-10 无备份恢复方案
- **现象**：全项目搜索 `backup` 零命中，无备份脚本，运维手册未提及备份。
- **影响**：MySQL/MongoDB/MinIO 数据丢失无法恢复。
- **建议方案**：编写 `scripts/backup/` 脚本 + cron 每日全量备份 + 文档化恢复流程。

### P1-11 50 处空 catch 吞掉错误
- **现象**：28 个文件 50 处 `catch(){}` 或 `catch{ }`。
- **影响**：接口失败时用户看到无反馈的"静止"页面。
- **建议方案**：除拦截器已处理的 401/业务错误外，其余 catch 至少 `console.error`。

### P1-12 分享密码可暴力破解
- **现象**：`ShareController.java` `verify` 无失败次数限制。
- **影响**：分享密码通常是 4-6 位，可被脚本快速遍历。
- **建议方案**：Redis 记录 code+IP 的失败次数，5 次/小时上限。

### P1-13 IntelDashboardView 八卡片无响应式
- **现象**：`el-col :span="3"` 每张卡片占 1/8 宽，无断点。
- **影响**：平板/手机上 8 张卡片挤在一行。
- **建议方案**：改为 `:xs="12" :sm="8" :md="6" :lg="3"`。

### P1-14 DashboardView 缺少"新建文档"快捷入口
- **现象**：快捷操作只有"新建空间/搜索文档/我的标签/分享中心"，无"新建文档"。
- **影响**：用户最高频的操作（写笔记）需要绕道空间→文件夹→新建。
- **建议方案**：快捷操作首项加"新建文档"。

### P1-15 SearchController 搜索建议是空实现
- **现象**：`suggest` 注释"后续可对接MeiliSearch"，永远返回空列表。
- **影响**：搜索框无下拉建议。
- **建议方案**：对接 MeiliSearch 的 `attributesToCrop` 能力返回建议词。

### 5. 搜索性能优化（2026-07-02，commit 68f6751）

#### 5.1 根因分析
通过对比 Everything/AnyText 与本系统的差异，定位到搜索慢的根本原因：

| 维度 | Everything/AnyText | 本系统（优化前） |
|------|-------------------|----------------|
| 数据位置 | 本地内存/磁盘直接读 | 跨进程 HTTP 调用 MeiliSearch |
| 查询模式 | 单次查询 | 3 索引（kb_docs/kb_webpages/kb_files）串行查询 |
| 响应大小 | KB 级 | **可达 1MB**（含完整 content 字段） |

**关键瓶颈**：MeiliSearch 默认 `displayedAttributes=["*"]` 导致响应包含完整 `content` 字段。
对于 xlsx/docx 文件（Tika 解析后内容可达数百 KB）和网页（含完整 HTML），中文搜索命中这些大内容
文档时，单次响应可达 **1,007,792 字节（约 1MB）**，导致：
- MeiliSearch 序列化大响应慢
- Java 应用 JSON 反序列化 + 处理慢
- 网络传输 1MB 慢

实测："区块链"搜索 474.6ms（响应 1MB），"quantum"搜索 72.7ms（响应 1KB）。

#### 5.2 后端优化（kb-knowledge）
1. **`SearchServiceImpl.searchIndex()` 添加 `attributesToRetrieve`**
   - 显式指定只返回展示字段（id/title/name/type/folderId/userId/starred/createdAt 等）
   - 排除 `content` 字段（content 仍可搜索，只是不返回给客户端）
   - 高亮片段通过 `_formatted.content` + `attributesToCrop=cropLength=120` 获取
2. **结果集字段过滤**
   - 改为 `new HashMap<>()` 只放入白名单字段，剔除 `_formatted`/`_matchesInfo` 等大字段
3. **3 索引并行查询**
   - 使用 `CompletableFuture.supplyAsync()` + 3 线程 daemon 线程池
   - 串行延迟 3× 降为并行延迟 1×（max）
   - `CompletableFuture.allOf().get(5, TimeUnit.SECONDS)` 超时兜底
   - `safeSearchIndex()` 包装异常不抛出，单索引失败不影响其他
4. **查询参数优化**
   - `limit` 从固定 100 改为 `Math.min(size + 10, 50)`
   - `attributesToHighlight` 从 `["*"]` 收窄为 `["title", "content", "name"]`
   - 新增 `attributesToCrop=["content"]` + `cropLength=120` 用 MeiliSearch 原生裁剪

#### 5.3 MeiliSearch 索引设置优化
通过 PATCH `/indexes/{idx}/settings` 优化 3 个索引：

| 设置项 | 优化前 | 优化后 | 说明 |
|--------|--------|--------|------|
| `displayedAttributes` | `["*"]` | 显式列表（排除 content） | 避免返回大字段 |
| `searchableAttributes` | `["*"]` | `["title","content"]` 等 | 限制可搜索字段，避免搜索 metadata |
| `typoTolerance.enabled` | `true` | `false` | 中文无 typo 概念，关闭节省开销 |
| `proximityPrecision` | `byWord` | `byAttribute` | 牺牲少量精度换性能 |

#### 5.4 前端优化（kb-web）
1. **`SearchView.vue`**
   - 350ms 防抖（`debouncedSearch`）
   - `AbortController` 请求取消：新请求发出时取消上一个未完成请求
   - 本地缓存 Map（5 分钟 TTL）：重复搜索同一关键词秒开
   - `onUnmounted` 清理定时器和请求
2. **`search.ts`**
   - `search()` 函数新增 `signal?: AbortSignal` 参数
3. **`api/index.ts`**
   - axios 超时从 30000ms 降至 8000ms

#### 5.7 注意事项
- `typoTolerance.enabled=false` 会移除部分模糊匹配（如"区旗"匹配"区块链"中的"区"）
- 这是正确行为：中文不应有 typo 概念，避免假阳性
- 若后续需要模糊匹配，可在 `disableOnWords` 中精确控制，而非全局开启
- MeiliSearch 索引设置变更需通过 API 应用，不在代码仓库中（运行时配置）
