| 入口 | 地址 | 适用场景 |
|------|------|---------|

## 四、服务管理

### 4.1 启动 / 停止 / 重启

```bash
# 进入部署目录
cd /root/kb-deploy

# 启动所有服务
bash /root/devtools/mykng/scripts/deploy.sh up
# 等价于：docker compose up -d

# 停止所有服务
bash /root/devtools/mykng/scripts/deploy.sh down

# 重启所有服务
bash /root/devtools/mykng/scripts/deploy.sh restart

# 重启单个服务（推荐方式）
docker restart kb-gateway
docker restart kb-auth
docker restart kb-knowledge
docker restart kb-intelligence

# 重新构建并启动单个服务（代码变更后）
cd /root/devtools/mykng
bash scripts/build.sh kb-auth          # 重新构建镜像
docker compose -f /root/kb-deploy/docker-compose.yml up -d kb-auth
```

### 4.2 状态查看

```bash
# 所有容器状态
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"

# 详细健康检查
bash /root/devtools/mykng/scripts/health-check.sh

# 单容器健康状态
docker inspect --format='{{.State.Health.Status}}' kb-gateway
docker inspect --format='{{.State.Health.Status}}' kb-mysql

# 容器资源占用
docker stats --no-stream
```

### 4.3 日志查看

```bash
# 实时跟踪某服务日志（最近 200 行）
docker logs -f --tail 200 kb-gateway
docker logs -f --tail 200 kb-knowledge
docker logs -f --tail 200 kb-intelligence

# 查看最近 1 小时的 ERROR 日志
docker logs --since 1h kb-gateway 2>&1 | grep ERROR

# 按 traceId 跨服务追踪
TRACE_ID="<traceId>"
for svc in kb-gateway kb-auth kb-knowledge kb-ops kb-intelligence; do
  echo "=== $svc ==="
  docker logs kb-$svc 2>&1 | grep "$TRACE_ID"
done

# 导出某时段日志到文件
docker logs --since 2026-06-29T00:00:00 --until 2026-06-29T06:00:00 kb-knowledge > /tmp/kb-knowledge-20260629.log
```

### 4.4 构建

```bash
cd /root/devtools/mykng

# 拉取最新代码
git pull origin main

# 构建所有镜像（使用 Maven 多阶段构建）
bash scripts/build.sh

# 构建单个服务
bash scripts/build.sh kb-intelligence

# 不使用缓存构建（镜像出问题时使用）
bash scripts/build.sh --no-cache

# 仅编译 jar 包（不构建 Docker 镜像）
cd kb-parent && mvn -Pfast clean package -DskipTests
```

## 五、用户与认证

### 5.1 默认账号

| 系统 | 账号 | 密码 |
|------|------|------|
| 知识库 Web | `admin` | `admin123` |
| MySQL | `root` | `kb123456` |
| MongoDB | `kb` | `kb123456` |
| MinIO | `minioadmin` | `minioadmin` |
| Redis | （无密码） | — |

### 5.2 登录获取 Token

```bash
# 公网入口（推荐）
curl -X POST https://kb.marschat.online/kb/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'

# 内网入口（管理员）
curl -X POST http://100.93.36.113:8090/kb/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'
```

**响应示例**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "accessToken": "eyJhbGciOi...",
    "refreshToken": "eyJhbGciOi...",
    "tokenType": "Bearer",
    "expiresIn": 900
  }
}
```

> **字段说明**：响应字段名为 `accessToken` / `refreshToken`（驼峰），不是 `token`。

### 5.3 刷新令牌

```bash
curl -X POST https://kb.marschat.online/kb/api/auth/refresh \
  -H "Content-Type: application/json" \
  -d '{"refreshToken":"<refreshToken>"}'
```

### 5.4 调用业务接口

```bash
# 所有非白名单接口需要 Authorization 头
TOKEN="<accessToken>"

# 示例：查询知识空间列表
curl https://kb.marschat.online/kb/api/space/list \
  -H "Authorization: Bearer $TOKEN"

# 示例：创建文档
curl -X POST https://kb.marschat.online/kb/api/doc \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"测试文档","content":"# 内容","folderId":1}'
```

### 5.5 API Token（长期令牌）

适用于脚本、自动化工具调用：

1. Web 界面登录后，进入"设置"页
2. 找到"API Token 管理"
3. 点击"创建 Token"，填写名称、有效期
4. **立即复制返回的 Token 明文**（仅展示一次）
5. 调用 API 时携带：`Authorization: Bearer <api-token>`

### 9.2 备份

#### 自动备份（推荐）

部署目录下有备份脚本，建议配置 crontab：

```bash
# 编辑 crontab
crontab -e

# 每天凌晨 2:30 执行全量备份
30 2 * * * /root/devtools/mykng/scripts/backup.sh >> /var/log/kb-backup.log 2>&1
```

#### 手动备份

```bash
# 全量备份（MySQL + MongoDB + MinIO 元数据）
bash /root/devtools/mykng/scripts/backup.sh

# 仅备份 MySQL
docker exec kb-mysql mysqldump -uroot -pkb123456 \
  --databases kb_auth kb_file kb_knowledge kb_ops kb_intelligence \
  --single-transaction --routines --triggers \
  > /root/kb-deploy/backup/mysql/kb_$(date +%Y%m%d_%H%M%S).sql

# 仅备份 MongoDB
docker exec kb-mongodb mongodump --uri="mongodb://kb:kb123456@localhost:27017" \
  --out=/backup/mongodb/$(date +%Y%m%d_%H%M%S)

# 备份 MinIO 数据（使用 mc 客户端）
docker run --rm -v /root/kb-deploy/minio/data:/data \
  -v /root/.mc:/root/.mc minio/mc \
  cp --recursive minio/kb-bucket /backup/minio/$(date +%Y%m%d)
```

### 9.3 恢复

#### MySQL 恢复

```bash
# 1. 停止依赖 MySQL 的服务（避免脏数据）
docker stop kb-gateway kb-auth kb-file kb-knowledge kb-ops kb-intelligence

# 2. 恢复数据库
docker exec -i kb-mysql mysql -uroot -pkb123456 < /root/kb-deploy/backup/mysql/kb_20260628.sql

# 3. 验证数据
docker exec kb-mysql mysql -uroot -pkb123456 -e "USE kb_auth; SELECT COUNT(*) FROM user;"

# 4. 重启服务
docker start kb-auth kb-file kb-knowledge kb-ops kb-intelligence kb-gateway

# 5. 健康检查
bash /root/devtools/mykng/scripts/health-check.sh
```

#### MongoDB 恢复

```bash
# 1. 停止 kb-knowledge（避免写入冲突）
docker stop kb-knowledge

# 2. 恢复
docker exec kb-mongodb mongorestore \
  --uri="mongodb://kb:kb123456@localhost:27017" \
  /backup/mongodb/20260628

# 3. 重启
docker start kb-knowledge
```

### 9.5 索引重建（MeiliSearch）

当前**无手动索引重建 API**，如遇索引不一致：

```bash
# 方案 1：通过 API 触发单条重建（修改文档会自动同步）
curl -X PUT https://kb.marschat.online/kb/api/doc/1 \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"原标题"}'   # 不改内容，触发索引同步

# 方案 2：直接操作 MeiliSearch（管理员，谨慎）
curl -X DELETE http://192.168.31.105:7700/indexes/docs/documents \
  -H "Authorization: Bearer <meili-master-key>"

# 方案 3：重建索引（极端情况，会丢失所有索引）
docker exec kb-meilisearch curl -X DELETE http://localhost:7700/indexes/docs
# 然后通过修改文档触发全量重建
```

```bash
# 网关健康（推荐入口）

# 基础设施健康
```

### 10.3 日志告警（简易方案）

```bash
# 检查最近 5 分钟所有服务的 ERROR 日志
for svc in kb-gateway kb-auth kb-file kb-knowledge kb-ops kb-intelligence; do
  count=$(docker logs --since 5m $svc 2>&1 | grep -c ERROR)
  if [ "$count" -gt 0 ]; then
    echo "[$(date '+%H:%M:%S')] $svc 有 $count 条 ERROR"
    docker logs --since 5m $svc 2>&1 | grep ERROR | tail -5
  fi
done

# 检查容器健康状态
for c in kb-gateway kb-auth kb-file kb-knowledge kb-ops kb-intelligence kb-mysql kb-mongodb kb-redis kb-minio kb-meilisearch; do
  status=$(docker inspect --format='{{.State.Health.Status}}' $c 2>/dev/null || echo "N/A")
  if [ "$status" != "healthy" ]; then
    echo "[$(date '+%H:%M:%S')] $c 状态异常: $status"
  fi
done
```

可配置 crontab 每 5 分钟执行一次：


### 16.1 错误码对照表

| 错误码 | 含义 | 排查方向 |
|--------|------|---------|
| 400 | 参数错误 | 检查请求体 JSON 格式、必填字段 |
| 401 | 未认证 / Token 失效 | 重新登录获取 Token |
| 403 | 无权限 | 检查用户角色、资源 ownership |
| 404 | 资源不存在 | 检查 URL 路径、资源 ID |
| 409 | 资源冲突 | 检查唯一约束（用户名、空间名等） |
| 429 | 限流 | 检查请求频率，降低 QPS |
| 500 | 服务器内部错误 | 查看 `docker logs` 找堆栈 |
| 502 | 网关上游错误 | 检查上游服务健康状态 |
| 503 | 服务不可用 | 检查容器是否启动 |
| 504 | 网关超时 | 检查 Tailscale 网络、上游响应时间 |
