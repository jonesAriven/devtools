## A1. 产品定位与核心理念

### 1.1 什么是 Private-Knowledge-Base？

Private-Knowledge-Base 是一套**完全私有化部署**的个人知识管理系统。核心理念是**"知识多源归一"**——无论是你手动上传的文件、写的笔记、收藏的网页，还是小桉自动采集的运维数据（主机、端口、账密、拓扑），最终都沉淀到同一个知识库中，统一搜索、统一展示。

### 1.2 为什么需要私有化知识库？

| 痛点 | 我们的解决方案 |
|------|---------------|
| 第三方笔记应用数据存在云端，隐私无法保障 | 全部数据存储在自己的服务器上，不依赖任何第三方云服务 |
| 文件散落在电脑各处，找不到、搜不到 | 上传即解析、即索引，全文搜索秒级命中 |
| 网页看到好文章，收藏后原链接失效 | 一键收藏网页，自动清洗正文永久保存 |
| 运维知识（主机/端口/账密）散落在文档里，查起来费劲 | 自动采集 + 结构化存储 + 知识看板可视化展示 |
| 不同类型的知识（文件/笔记/网页/运维数据）分散在不同工具 | 统一管理，一次搜索全部命中 |

### 1.3 核心设计原则

1. **知识多源归一** — 人工录入（文件/笔记/网页）+ 程序自动采集（运维数据）+ 外部 API 接入，统一存储
2. **文件即知识单元** — 文件不是笔记的附件，它本身就是一条独立知识
3. **上传即索引** — 文件上传后自动解析全文并建立搜索索引
4. **统一搜索** — 文件内容、笔记正文、网页收藏、运维数据一次搜索全部命中
5. **完全私有** — 数据存储在自己的服务器上，不经过任何第三方
6. **渐进式建设** — 先跑通核心链路，再逐步迭代高级功能

## A3. 知识采集

### 3.1 人工采集（已有，v3 继承）

#### 3.1.1 文件上传与解析

| 格式 | 解析方式 | 阶段 |
|------|---------|------|
| txt、md | 直接读取全文 | MVP |
| pdf | PdfBox 提取纯文本层 | MVP |
| docx | POI 提取文本内容 | MVP |
| xlsx、pptx | POI 提取表格/演示内容 | 后续 |
| jpg、png | PaddleOCR/Tesseract 图片文字识别 | 后续 |

#### 3.1.2 网页一键收藏

```
① 复制网页 URL → 粘贴到知识库
② 后端自动抓取网页内容
③ 智能清洗：去除广告、导航栏、侧边栏等噪音，提取正文
④ 存为独立知识条目，自动进入搜索索引
```

#### 3.1.3 富文本笔记

提供富文本编辑器，支持图文混排、标题、列表、表格、代码块、Markdown 快捷输入。

### 3.2 自动采集（v4 新增 — 知识时光机整合）

知识时光机（原独立 Shell 脚本）改造为知识库的内置自动采集模块，通过 API 将运维知识写入数据库：

| 采集项 | 数据来源 | 存储方式 | 更新频率 |
|--------|---------|---------|---------|
| 主机清单 | 解析备忘录文档 | MySQL ops_host 表 | 每天 02:00 + 实时触发 |
| 端口映射 | 解析备忘录 + ss 扫描 | MySQL ops_port 表 | 每天 02:00 + 实时触发 |
| 账密信息 | 解析备忘录文档 | MySQL ops_credential 表 | 每天 02:00 |
| 域名映射 | 解析备忘录 + dig 验证 | MySQL ops_domain 表 | 每天 02:00 |
| 应用依赖关系 | 解析文档 + 服务探测 | MySQL ops_dependency 表 | 每天 02:00 |
| 变更记录 | git diff + 文档对比 | MySQL ops_change_log 表 | 实时触发 |
| 矛盾提醒 | 数据交叉验证 | MySQL ops_conflict 表 | 每天 02:00 |
| 历史快照 | 全量数据快照 | MySQL ops_snapshot 表 | 每天 02:00 |
| 架构图 | 根据拓扑数据生成 | MinIO 存储 PNG | 每天 02:00 |

#### 采集流程

```
知识时光机 Shell 脚本（改造后）
    │  不再直接输出 Markdown 文件
    ▼
调用 kb-server API (/api/ops/import/*)
    │
    ├──→ MySQL 写入结构化数据
    ├──→ 架构图上传 MinIO
    └──→ 变更记录写入操作日志
```

### 3.3 API 接入（v4 新增）

提供 REST API 供外部程序录入知识：

| 接口 | 说明 | 认证方式 |
|------|------|---------|
| `POST /api/ops/import/hosts` | 批量导入主机 | API Token |
| `POST /api/ops/import/ports` | 批量导入端口 | API Token |
| `POST /api/ops/import/credentials` | 批量导入账密 | API Token |
| `POST /api/ops/import/domains` | 批量导入域名 | API Token |
| `POST /api/ops/import/dependencies` | 批量导入依赖关系 | API Token |
| `POST /api/ops/import/snapshot` | 提交快照 | API Token |
| `POST /api/ops/import/changelog` | 提交变更记录 | API Token |

## A5. 知识检索

### 5.1 统一全文搜索（已有）

一次搜索同时命中：文件内容、笔记正文、网页收藏。

### 5.2 运维数据搜索（v4 新增）

运维数据（主机、端口、账密等）也纳入 MeiliSearch 索引，统一搜索：

```
搜索 "3383" → 命中端口映射表、主机清单、变更记录
搜索 "Hwx"  → 命中账密信息、相关文档
搜索 "FRP"  → 命中端口映射、域名映射、依赖关系
```

### 5.3 结构化查询（v4 新增）

运维数据除了全文搜索外，还支持结构化查询：

```
GET /api/ops/ports?host=内网Debian    → 查询该主机的所有端口
GET /api/ops/credentials?type=mysql  → 查询所有 MySQL 账密
GET /api/ops/hosts?network=内网      → 查询所有内网主机
```

## A10. 安全与隐私

| 安全层 | 措施 | 说明 |
|--------|------|------|
| 数据存储 | 全部私有化部署 | 数据在自己的服务器上 |
| 认证 | JWT 双 Token | Access + Refresh 自动刷新 |
| 传输加密 | HTTPS + Tailscale | 公网 HTTPS，内网加密隧道 |
| 访问控制 | API 限流 + API Token | 防止滥用 |
| 上传安全 | 类型白名单 + 大小限制 | 单文件最大 200MB |
| 内容安全 | HTML Sanitizer | 防止 XSS |
| 运维数据安全 | 账密接口需额外权限 | 敏感数据分级访问 |

## B5. 知识时光机整合方案

### 5.1 现状

知识时光机目前是独立 Shell 脚本（`/home/liangzi/tools/knowledge-time-machine-v3/main.sh`），每天 02:00 通过 cron 执行，输出 Markdown 文件到 `/home/liangzi/document/知识时光机/` 目录。

### 5.2 改造目标

Shell 脚本不再直接输出文件，改为调用 kb-server API 写入数据库：

```
改造前：
  Shell 脚本 → 解析文档 → 输出 Markdown/PNG → 存到文件系统

改造后：
  Shell 脚本 → 解析文档 → 调用 /api/ops/import/* → 写入 MySQL + MinIO
```

### 5.3 改造步骤

| 步骤 | 内容 | 优先级 |
|------|------|--------|
| 1 | 在 kb-server 中完成运维知识模块开发（表 + API） | P0 |
| 2 | 知识看板前端开发 | P0 |
| 3 | 修改 Shell 脚本，将输出改为调 API | P1 |
| 4 | 保留每天 02:00 的定时执行 | P1 |
| 5 | 保留历史快照目录（作为文件备份，同时写入数据库） | P2 |

### 5.4 保留的 Shell 脚本功能

- 文档解析逻辑（解析 Markdown/YAML → 提取结构化数据）
- 端口扫描（ss -tlnp）
- 架构图生成（mermaid → mmdc → PNG）
- 动态验证（SSH/端口/DNS/HTTP）
- 矛盾检测（交叉验证）

**仅改变输出方式：** 解析结果 → API 调用，不再直接写文件。
