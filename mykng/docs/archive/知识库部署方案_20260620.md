## 一、整体架构

```
用户（公网）
    │ HTTPS
    ▼
┌─────────────────────────────────────────────┐
│  腾讯云2号 Nginx (:443)                      │
│  tools.marschat.online                      │
│  SSL 终结 + 静态资源服务 + API 反代          │
└──────────┬──────────────────────────────────┘
           │ Tailscale 直连 (100.93.36.113:8090)
           ▼
┌─────────────────────────────────────────────┐
│  mykng-debian (192.168.31.105)              │
│  Tailscale: 100.93.36.113                   │
│                                             │
│  ┌─────────────────────────────────────┐    │
│  │  Docker Compose                     │    │
│  │                                     │    │
│  │  kb-gateway (:8090 宿主机映射)      │    │
│  │    │                                │    │
│  │    ├── kb-auth (:8081 内网)         │    │
│  │    ├── kb-file (:8082 内网)         │    │
│  │    ├── kb-knowledge (:8083 内网)    │    │
│  │    └── kb-ops (:8084 内网)          │    │
│  │                                     │    │
│  │  基础设施:                           │    │
│  │    MySQL 8.0 (:3306)                │    │
│  │    Redis 7 (:6379)                  │    │
│  │    MinIO (:9000/:9001)              │    │
│  │    MeiliSearch v1.6 (:7700)         │    │
│  │    MongoDB 7 (:27017)               │    │
│  └─────────────────────────────────────┘    │
└─────────────────────────────────────────────┘
```

### 访问链路

```
用户 → https://tools.marschat.online/kb/
  → 腾讯云2号 Nginx (SSL 终结)
    → /kb/api/*  → proxy_pass → 100.93.36.113:8090 (Tailscale)
    → /kb/s/*    → 本地静态文件 /data/knowledge-base/web/
    → /kb/       → try_files → /kb/s/index.html (SPA)
```

### 设计原则

| 原则 | 说明 |
|------|------|
| **单点暴露** | 只有 kb-gateway 映射到宿主机端口 8090，其余服务走 Docker 内网 |
| **Tailscale 直连** | 腾讯云2号 ↔ mykng-debian 通过 Tailscale 私有网络直连，延迟 < 1ms |
| **SSL 终结在边缘** | 证书管理集中在腾讯云2号，内网全 HTTP |
| **静态资源边缘缓存** | 前端构建产物部署到腾讯云2号本地，减少 Tailscale 传输 |
| **统一上下文路径** | `KB_CONTEXT=/kb` 一处配置，前后端 + Nginx 同步 |

## 四、Docker Compose 配置

### 4.1 配置变更说明

基础设施容器（MySQL/Redis/MinIO/MeiliSearch/MongoDB）已在运行，Docker Compose 会接管管理。数据卷保持不变。

**关键变更：**
1. kb-gateway 端口映射 `8080:8080` → `8090:8080`
2. kb-auth/kb-file/kb-knowledge/kb-ops 删除 `ports` 映射（仅内网通信）
3. 网关 application.yml 端口保持 8080（容器内），宿主机映射到 8090

### 4.2 docker-compose.yml

```yaml

      context: ./kb-gateway
      dockerfile: Dockerfile
    container_name: kb-gateway
    restart: unless-stopped
    ports:
      - "8090:8080"           # ← 变更：8080→8090
    environment:
      - SPRING_PROFILES_ACTIVE=prod
      - JWT_SECRET=${JWT_SECRET}

      - KB_FILE_HOST=kb-file
      - KB_KNOWLEDGE_HOST=kb-knowledge
      - KB_OPS_HOST=kb-ops

      - kb-net
```

## 五、Nginx 配置

### 5.1 腾讯云2号 Nginx（SSL 终结 + 反代）

**文件位置**：`/etc/nginx/sites-available/tools`（腾讯云2号）

**变更**：`proxy_pass` 从 `100.93.36.113:8080` 改为 `100.93.36.113:8090`

```nginx
server {
    server_name tools.marschat.online;

    # API 反代到 kb-gateway（Tailscale 直连）
    location /kb/api/ {
        proxy_pass http://100.93.36.113:8090/kb/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 5s;
        proxy_read_timeout 60s;
        client_max_body_size 200m;
    }

    # 前端静态资源（本地缓存，减少 Tailscale 传输）
    location /kb/s/assets/ {
        alias /data/knowledge-base/web/assets/;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    location /kb/s/ {
        alias /data/knowledge-base/web/;
        expires 7d;
    }

    # SPA 路由回退
    location /kb/ {
        try_files $uri /kb/s/index.html;
    }

    location = /kb {
        return 302 /kb/;
    }

    location = / {
        return 302 /kb/;
    }

    listen 443 ssl;
    ssl_certificate /etc/letsencrypt/live/nexus.marschat.online/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/nexus.marschat.online/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;
}
```

### 5.2 Nginx 方案优劣势分析

| 方案 | 架构 | 优势 | 劣势 | 结论 |
|------|------|------|------|------|
| **A（采用）** | 腾讯云 Nginx → Tailscale → 网关 | 最简单；复用现有 SSL；单点配置；静态资源边缘缓存 | 静态文件需同步到腾讯云 | ✅ |
| B | 腾讯云 Nginx → 本地 Nginx → 网关 | 静态文件完全本地 | 双层 Nginx 维护成本高；端口 80 被 Apache 占用 | ❌ |
| C | 腾讯云 Nginx → FRP → 网关 | 不依赖 Tailscale | 多一跳 FRP，延迟更高 | ❌ 备选 |

**方案 A 细节**：
- 腾讯云2号 Nginx 做 SSL 终结 + 静态资源服务 + API 反代
- API 请求通过 Tailscale 直连 mykng-debian:8090（延迟 < 1ms）
- 前端静态资源部署到腾讯云2号 `/data/knowledge-base/web/`（减少 Tailscale 传输）
- 前端已优化：首屏 JS ~370KB（gzip ~75KB），按页面懒加载

## 八、备份策略

### 数据卷备份

| 数据 | 备份路径 | 频率 | 保留 |
|------|---------|------|------|
| MySQL | /mnt/0000sharebak/kb-backup/mysql/ | 每天 02:00 | 7天 |
| MongoDB | /mnt/0000sharebak/kb-backup/mongodb/ | 每天 02:00 | 7天 |
| MinIO | /mnt/0000sharebak/kb-backup/minio/ | 每周日 02:00 | 4周 |
| MeiliSearch | /mnt/0000sharebak/kb-backup/meilisearch/ | 每周日 02:00 | 4周 |

### 备份脚本

```bash
#!/bin/bash
# /root/devtools/mykng/scripts/backup.sh
BACKUP_DIR="/mnt/0000sharebak/kb-backup"
DATE=$(date +%Y%m%d_%H%M%S)

# MySQL 备份（按 schema 分别导出）
for db in kb_auth kb_file kb_knowledge kb_ops; do
  docker exec kb-mysql mysqldump -uroot -pkb123456 --single-transaction $db \
    > "$BACKUP_DIR/mysql/${db}_${DATE}.sql"
done

# MongoDB 备份
docker exec kb-mongodb mongodump --uri="mongodb://kb:kb123456@localhost:27017" \
  --archive > "$BACKUP_DIR/mongodb/mongodb_${DATE}.archive"

# 清理 7 天前的备份
find "$BACKUP_DIR/mysql" -name "*.sql" -mtime +7 -delete
find "$BACKUP_DIR/mongodb" -name "*.archive" -mtime +7 -delete

echo "[$DATE] 备份完成"
```

### Cron 配置

```bash
# 每天凌晨 2:00 备份
0 2 * * * /root/devtools/mykng/scripts/backup.sh >> /var/log/kb-backup.log 2>&1
```

### 服务扩容预留

当前单机部署，未来可扩展为多节点：

| 扩展方向 | 方式 | 影响 |
|---------|------|------|
| 多实例 | 同一服务多副本 + Nginx upstream 负载均衡 | 需引入服务发现（Nacos/Consul） |
| 独立数据库 | MySQL/MongoDB 迁移到独立服务器 | 修改 .env 连接地址 |
| 独立存储 | MinIO 迁移到独立服务器 | 修改 .env MINIO_ENDPOINT |
| 水平拆分 | knowledge 服务按用户分片 | 需要路由层改造 |

### 端口变更检查清单

如需修改网关端口（如从 8090 改为其他）：

| 文件 | 修改内容 |
|------|---------|
| `docker-compose.yml` | `ports: - "新端口:8080"` |
| `deploy.sh` | `log "网关地址: http://localhost:新端口"` |
| 腾讯云2号 Nginx | `proxy_pass http://100.93.36.113:新端口/kb/api/` |
| `nginx/kb.marschat.online.conf` | `upstream kb_gateway { server 127.0.0.1:新端口; }` |

> 网关容器内端口始终为 8080（application.yml），仅宿主机映射端口变更。
