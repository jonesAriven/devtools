## A1. 产品定位与核心理念

### 1.1 什么是 Private-Knowledge-Base？

Private-Knowledge-Base 是一套**完全私有化部署**的个人知识管理系统。核心理念是**"知识多源归一"**——无论是你手动上传的文件、写的笔记、收藏的网页，还是小桉自动采集的运维数据（主机、端口、账密、拓扑），最终都沉淀到同一个知识库中，统一搜索、统一展示。

### 1.2 为什么需要私有化知识库？

| 痛点 | 我们的解决方案 |
|------|---------------|
| 第三方笔记应用数据存在云端，隐私无法保障 | 全部数据存储在自己的服务器上，不依赖任何第三方云服务 |
| 文件散落在电脑各处，找不到、搜不到 | 上传即解析、即索引，全文搜索秒级命中 |
| 网页看到好文章，收藏后原链接失效 | 一键收藏网页，自动清洗正文永久保存 |
| 运维知识（主机/端口/账密）散落在文档里，查起来费劲 | 自动采集 + 结构化存储 + 知识看板可视化展示 |
| 不同类型的知识（文件/笔记/网页/运维数据）分散在不同工具 | 统一管理，一次搜索全部命中 |

### 1.3 核心设计原则

1. **知识多源归一** — 人工录入（文件/笔记/网页）+ 程序自动采集（运维数据）+ 外部 API 接入，统一存储
2. **文件即知识单元** — 文件不是笔记的附件，它本身就是一条独立知识
3. **上传即索引** — 文件上传后自动解析全文并建立搜索索引
4. **统一搜索** — 文件内容、笔记正文、网页收藏、运维数据一次搜索全部命中
5. **完全私有** — 数据存储在自己的服务器上，不经过任何第三方
6. **渐进式建设** — 先跑通核心链路，再逐步迭代高级功能

## A3. 知识采集

### 3.1 人工采集（已有，v3 继承）

#### 3.1.1 文件上传与解析

| 格式 | 解析方式 | 阶段 |
|------|---------|------|
| txt、md | 直接读取全文 | MVP |
| pdf | PdfBox 提取纯文本层 | MVP |
| docx | POI 提取文本内容 | MVP |
| xlsx、pptx | POI 提取表格/演示内容 | 后续 |
| jpg、png | PaddleOCR/Tesseract 图片文字识别 | 后续 |

#### 3.1.2 网页一键收藏

```
① 复制网页 URL → 粘贴到知识库
② 后端自动抓取网页内容
③ 智能清洗：去除广告、导航栏、侧边栏等噪音，提取正文
④ 存为独立知识条目，自动进入搜索索引
```

#### 3.1.3 富文本笔记

提供富文本编辑器，支持图文混排、标题、列表、表格、代码块、Markdown 快捷输入。

### 3.2 自动采集（v4 新增 — 知识时光机整合）

知识时光机（原独立 Shell 脚本）改造为知识库的内置自动采集模块，通过 API 将运维知识写入数据库：

| 采集项 | 数据来源 | 存储方式 | 更新频率 |
|--------|---------|---------|---------|
| 主机清单 | 解析备忘录文档 | MySQL ops_host 表 | 每天 02:00 + 实时触发 |
| 端口映射 | 解析备忘录 + ss 扫描 | MySQL ops_port 表 | 每天 02:00 + 实时触发 |
| 账密信息 | 解析备忘录文档 | MySQL ops_credential 表 | 每天 02:00 |
| 域名映射 | 解析备忘录 + dig 验证 | MySQL ops_domain 表 | 每天 02:00 |
| 应用依赖关系 | 解析文档 + 服务探测 | MySQL ops_dependency 表 | 每天 02:00 |
| 变更记录 | git diff + 文档对比 | MySQL ops_change_log 表 | 实时触发 |
| 矛盾提醒 | 数据交叉验证 | MySQL ops_conflict 表 | 每天 02:00 |
| 历史快照 | 全量数据快照 | MySQL ops_snapshot 表 | 每天 02:00 |
| 架构图 | 根据拓扑数据生成 | MinIO 存储 PNG | 每天 02:00 |

#### 采集流程

```
知识时光机 Shell 脚本（改造后）
    │  不再直接输出 Markdown 文件
    ▼
调用 kb-server API (/api/ops/import/*)
    │
    ├──→ MySQL 写入结构化数据
    ├──→ 架构图上传 MinIO
    └──→ 变更记录写入操作日志
```

### 3.3 API 接入（v4 新增）

提供 REST API 供外部程序录入知识：

| 接口 | 说明 | 认证方式 |
|------|------|---------|
| `POST /api/ops/import/hosts` | 批量导入主机 | API Token |
| `POST /api/ops/import/ports` | 批量导入端口 | API Token |
| `POST /api/ops/import/credentials` | 批量导入账密 | API Token |
| `POST /api/ops/import/domains` | 批量导入域名 | API Token |
| `POST /api/ops/import/dependencies` | 批量导入依赖关系 | API Token |
| `POST /api/ops/import/snapshot` | 提交快照 | API Token |
| `POST /api/ops/import/changelog` | 提交变更记录 | API Token |

## A5. 知识检索

### 5.1 统一全文搜索（已有）

一次搜索同时命中：文件内容、笔记正文、网页收藏。

### 5.2 运维数据搜索（v4 新增，v5 优化安全策略）

运维数据（主机、端口、域名、依赖关系）纳入 MeiliSearch 索引，统一搜索：

```
搜索 "3383" → 命中端口映射表、主机清单、变更记录
搜索 "FRP"  → 命中端口映射、域名映射、依赖关系
```

> ⚠️ **v5 安全策略**：**账密数据（密码、密钥等）不进入 MeiliSearch 索引**，仅通过结构化 API 查询，且需额外权限认证。避免搜索时意外暴露敏感信息。详见 Part B §B3.3。

### 5.3 结构化查询（v4 新增）

运维数据除了全文搜索外，还支持结构化查询：

```
GET /api/ops/ports?host=内网Debian    → 查询该主机的所有端口
GET /api/ops/credentials?type=mysql  → 查询所有 MySQL 账密
GET /api/ops/hosts?network=内网      → 查询所有内网主机
```

## A10. 安全与隐私

| 安全层 | 措施 | 说明 |
|--------|------|------|
| 数据存储 | 全部私有化部署 | 数据在自己的服务器上 |
| 认证 | JWT 双 Token | Access + Refresh 自动刷新 |
| 传输加密 | HTTPS + Tailscale | 公网 HTTPS，内网加密隧道 |
| 访问控制 | API 限流 + API Token | 防止滥用 |
| 上传安全 | 类型白名单 + 大小限制 | 单文件最大 200MB |
| 内容安全 | HTML Sanitizer | 防止 XSS |
| 运维数据安全 | 账密接口需额外权限 + 账密不进搜索索引 | 敏感数据分级访问 |

### 3.5 密码加密方案（v5 新增）

#### 加密算法

| 项目 | 选型 |
|------|------|
| 算法 | **AES-256-GCM** |
| 密钥长度 | 256 位 |
| 认证标签 | 128 位（GCM 内置） |
| 初始向量 | 96 位随机（每次加密生成，存于 `password_nonce` 字段）|
| 编码 | 密文和 nonce 均以 hex 编码存储 |

#### 密钥管理

| 层级 | 配置方式 | 示例 |
|------|---------|------|
| 生产环境 | 环境变量 `KB_CREDENTIAL_KEY` | `export KB_CREDENTIAL_KEY=$(openssl rand -hex 32)` |
| Docker 部署 | docker-compose environment | `KB_CREDENTIAL_KEY: "${KB_CREDENTIAL_KEY}"` |
| 开发环境 | application-dev.yml | 固定测试密钥（不上生产） |

#### 加解密流程

```
加密：
  明文密码 + 随机 nonce(12字节) → AES-256-GCM → 密文(hex) + nonce(hex)
  → 存入 password_encrypted + password_nonce 字段

解密：
  password_encrypted(hex) + password_nonce(hex) + KB_CREDENTIAL_KEY
  → AES-256-GCM 解密 → 明文密码

密钥变更：
  1. 生成新密钥 KB_CREDENTIAL_KEY_NEW
  2. 遍历 ops_credential 表，用旧密钥解密，新密钥重加密
  3. 更新 KB_CREDENTIAL_KEY 环境变量
  4. 重启 kb-backend
```

#### Java 实现参考

```java
// CryptoUtil.java
public class CryptoUtil {
    private static final String ALGORITHM = "AES/GCM/NoPadding";
    private static final int GCM_IV_LENGTH = 12;    // 96 bits
    private static final int GCM_TAG_LENGTH = 128;  // bits

    public static String[] encrypt(String plaintext, SecretKey key) {
        byte[] iv = new byte[GCM_IV_LENGTH];
        SecureRandom.getInstanceStrong().nextBytes(iv);
        Cipher cipher = Cipher.getInstance(ALGORITHM);
        cipher.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(GCM_TAG_LENGTH, iv));
        byte[] ciphertext = cipher.doFinal(plaintext.getBytes(StandardCharsets.UTF_8));
        return new String[]{
            Hex.encodeHexString(ciphertext),  // password_encrypted
            Hex.encodeHexString(iv)           // password_nonce
        };
    }

    public static String decrypt(String ciphertextHex, String ivHex, SecretKey key) {
        Cipher cipher = Cipher.getInstance(ALGORITHM);
        cipher.init(Cipher.DECRYPT_MODE, key,
            new GCMParameterSpec(GCM_TAG_LENGTH, Hex.decodeHex(ivHex)));
        return new String(cipher.doFinal(Hex.decodeHex(ciphertextHex)),
            StandardCharsets.UTF_8);
    }
}
```

#### 通用错误处理

| HTTP 状态码 | 说明 | 处理方式 |
|-------------|------|---------|
| 200 | 全部成功 | 正常返回 |
| 400 | 部分失败或参数错误 | 返回 errors 数组，调用方需重试失败项 |
| 401 | API Token 无效或过期 | 重新生成 Token |
| 403 | Token 无此接口权限 | 检查 Token scope |
| 429 | 请求过于频繁 | 等待后重试（Retry-After header）|

#### 幂等性保证

导入接口支持幂等重试：
- **hosts**：按 `name` 去重，同名更新
- **ports**：按 `host_id + port` 去重
- **credentials**：按 `host_id + service` 去重
- **domains**：按 `domain` 去重（UNIQUE KEY）
- **dependencies**：按 `source + target + type` 去重
- **snapshot**：按 `snapshot_date` 去重，同日期覆盖

```bash
# 重试函数
retry_api_call() {
  local url=$1
  local data=$2
  local max_retries=3
  local retry_delay=5

  for ((i=1; i<=max_retries; i++)); do
    response=$(curl -s -w "\n%{http_code}" -X POST "$url" \
      -H "Authorization: Bearer $KB_API_TOKEN" \
      -H "Content-Type: application/json" \
      -d "$data")
    http_code=$(echo "$response" | tail -1)
    body=$(echo "$response" | sed '$d')

    if [ "$http_code" = "200" ]; then
      echo "✅ 导入成功"
      return 0
    elif [ "$http_code" = "400" ]; then
      # 部分失败，记录错误但继续
      echo "⚠️ 部分失败: $body" >> /var/log/knowledge-time-machine.log
      return 0
    elif [ "$http_code" = "429" ]; then
      sleep $((retry_delay * i))
      continue
    else
      echo "❌ 失败 (HTTP $http_code)，第 ${i} 次重试..."
      sleep $retry_delay
    fi
  done

  echo "❌ 重试 $max_retries 次后仍失败" >> /var/log/knowledge-time-machine.log
  return 1
}
```

## B6. 矛盾检测规则（v5 新增，细化）

### 6.1 检测类型

| 类型 | 检测逻辑 | 严重程度 | 示例 |
|------|---------|---------|------|
| `port_conflict` | 同一主机上两个服务占用相同端口 | 4 | 内网 Debian:3306 同时被 MySQL 和 Redis 占用 |
| `credential_mismatch` | 同一服务的密码在不同文档中不一致 | 5 | 文档A写 MySQL root 密码是 abc，文档B写是 xyz |
| `dns_mismatch` | DNS 解析结果与 ops_domain 记录不一致 | 3 | domain 记录解析到 1.2.3.4，实际 dig 得到 5.6.7.8 |
| `host_unreachable` | 主机标记为在线但 SSH/ICMP 不可达 | 3 | ops_host 状态=1 但 ping 不通 |
| `port_offline` | 端口标记为在线但实际未监听 | 2 | ops_port 状态=1 但 ss 未发现该端口 |
| `orphan_host` | 有端口/账密引用了不存在的 host_id | 2 | ops_port.host_id 指向已被删除的主机 |

### 6.2 检测触发时机

| 触发方式 | 时间 | 说明 |
|---------|------|------|
| 定时检测 | 每天 02:00（知识时光机运行时）| 全量交叉验证 |
| 实时检测 | 数据写入时 | 仅检测关联数据一致性（如外键检查）|

### 6.3 矛盾解决流程

```
发现矛盾 → 写入 ops_conflict 表（status=0）
  → 知识看板展示 ⚠️ 提醒
  → 用户在知识看板处理：
      ├── 标记"已解决"（status=1）→ 记录 resolved_at
      ├── 标记"忽略"（status=2）→ 不再提醒
      └── 不处理 → 下次检测时重新提醒（不重复创建）
```

### 6.4 去重规则

同一类型的同一矛盾不重复创建。判断依据：

```sql
-- port_conflict 去重：同一 host + 同一 port
SELECT COUNT(*) FROM ops_conflict
WHERE conflict_type = 'port_conflict'
  AND JSON_EXTRACT(detail_json, '$.host_id') = ?
  AND JSON_EXTRACT(detail_json, '$.port') = ?
  AND status IN (0, 1);  -- 未处理或已解决的不重复，已忽略的可以重新提醒
```
