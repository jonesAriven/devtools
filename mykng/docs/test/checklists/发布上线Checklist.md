## 四、回滚铁律

> **核心原则**：宁可回滚，不可硬扛。回滚是安全的，硬扛是危险的。

### 4.1 触发回滚的条件（满足任一即触发）

| 编号 | 触发条件 | 阈值 | 数据来源 |
|------|---------|------|---------|
| RB-01 | 核心服务不可用 | 任一服务健康检查连续 3 次失败 | 健康检查端点 |
| RB-02 | 5xx 错误率飙升 | 5xx 错误率 > 5% 持续 2min | 监控大盘 |
| RB-03 | 接口 RT 严重劣化 | P99 > 2s 持续 5min | 监控大盘 |
| RB-04 | 数据损坏 | 数据校验脚本失败，或用户反馈数据丢失 | 校验脚本/用户反馈 |
| RB-05 | 内存泄漏 | 内存使用率 > 95% 持续 5min | 监控大盘 |
| RB-06 | 数据库故障 | 主从延迟 > 30s，或连接池耗尽 | DBA 监控 |
| RB-07 | 核心业务流程失败 | 登录/上传/搜索任一流程不可用 | 冒烟测试 |
| RB-08 | 用户集中投诉 | 30min 内投诉 > 10 单 | 客服反馈 |
| RB-09 | 安全事件 | 发现注入/越权/数据泄露 | 安全监控 |
| RB-10 | 发布负责人判断 | 发布负责人根据经验判断需回滚 | 人工决策 |

### 4.2 回滚决策权与时效

| 阶段 | 决策人 | 决策时效 | 通知范围 |
|------|--------|---------|---------|
| 发布后 30min 内 | 发布负责人 | 5min 内决定 | 发布群 |
| 发布后 30min-2h | 发布负责人 + 架构师 | 10min 内决定 | 发布群 + 产品 |
| 发布后 2h-24h | 架构师 + 运维负责人 | 15min 内决定 | 发布群 + 产品 + 管理层 |
| 发布后 24h+ | 紧急变更流程 | 30min 内决定 | 全员 |

### 4.3 回滚执行步骤

| 序号 | 步骤 | 命令/操作 | 预期耗时 | 责任人 |
|------|------|----------|---------|--------|
| RB-S-01 | 通知干系人 | 发布群公告 "执行回滚" | 1min | 发布负责人 |
| RB-S-02 | 停止新服务 | `docker compose stop kb-auth kb-file kb-knowledge kb-ops` | 30s | 运维 |
| RB-S-03 | 执行数据库回滚脚本 | `mysql -u root -p < db/migration/V1.x.x__rollback.sql` | 1-5min | DBA |
| RB-S-04 | 数据库回滚校验 | `bash db/verify/verify_rollback.sh` | 1min | DBA |
| RB-S-05 | 启动旧版本镜像 | `docker compose up -d kb-auth:prev ...` | 1min | 运维 |
| RB-S-06 | 健康检查 | `curl http://localhost:8081/actuator/health` | 30s | 运维 |
| RB-S-07 | 回滚前端 | `rsync -av /data/kb-web-prev/ /data/kb-web/` | 30s | 运维 |
| RB-S-08 | reload Nginx | `nginx -t && nginx -s reload` | 5s | 运维 |
| RB-S-09 | 冒烟测试 | `bash tests/smoke_prod.sh` | 2min | 测试 |
| RB-S-10 | 通知用户 | 公告 "服务已恢复" | 1min | 产品 |
| RB-S-11 | 复盘记录 | 30min 内提交回滚原因初步报告 | 30min | 发布负责人 |
| RB-S-12 | 正式复盘 | 24h 内召开复盘会议，输出根因 + 改进项 | 24h | 全员 |

### 4.4 回滚注意事项

- [ ] **数据库回滚优先**：若涉及表结构变更，先回滚数据库，再回滚应用，避免应用因表结构不一致崩溃
- [ ] **不可逆变更特殊处理**：DROP COLUMN / TRUNCATE 类不可逆操作，必须从备份恢复，回滚耗时较长
- [ ] **配置回滚**：`.env` / `application.yml` 必须同步回滚，否则应用读取错误配置
- [ ] **缓存清理**：回滚后清理 Redis 缓存，避免脏数据：`redis-cli FLUSHDB`（仅业务库）
- [ ] **CDN 缓存刷新**：前端静态资源回滚后，刷新 CDN 缓存
- [ ] **日志保留**：回滚前后日志全部保留，用于复盘

### 5.1 灰度方式选择

| 方式 | 适用场景 | MyKNG 采用情况 |
|------|---------|---------------|
| 功能开关（Feature Flag） | 新功能灰度 | ✅ 首选，配置中心控制 |
| 按用户灰度 | 部分用户优先体验 | ✅ 按 userId 白名单 |

| 蓝绿发布 | 整体切换 | ❌ 资源占用高，不采用 |
