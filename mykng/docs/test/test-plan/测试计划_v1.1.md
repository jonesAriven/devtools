# MyKNG 知识库平台 — 测试计划 v1.1

> **版本**：v1.1
> **更新日期**：2026-06-28
> **适用对象**：开发、测试、运维、架构组
> **SOP 对应**：本计划遵循 SOP V1.1「研发交付全流程标准作业」阶段 0 要求
> **测试目标**：基于 SOP V1.1 的「6 层自测 + 业务功能专项」体系，覆盖 123 个 API 接口、15 个前端路由、10 大业务流程，验证功能正确性、前后端一致性、路径配置、业务流程闭环与回归稳定性。

### 3.1 层级 1：变异测试（PITest）

| 项目 | 说明 |
|------|------|
| **工具** | PITest（Maven 插件 pitest-maven） |
| **目标** | 验证单元测试的有效性，发现「伪通过」的测试 |
| **范围** | kb-auth/kb-file/kb-knowledge/kb-ops 的 Service 层核心方法 |
| **准入门槛** | 变异覆盖率 ≥ 70%，无存活变异体（SURVIVING mutants） |
| **执行频率** | 每次提测前 |
| **执行命令** | `mvn org.pitest:pitest-maven:mutationCoverage -pl kb-auth,kb-file,kb-knowledge,kb-ops -DtargetClasses=**.service.impl.** -DtargetTests=**.*Test` |
| **报告位置** | `target/pit-reports/` |

**关注变异类型**：
- 条件边界变异（NEGATE_CONDITIONALS）
- 返回值变异（RETURN_VALS）
- 数学运算变异（MATH）
- void 方法调用变异（VOID_METHOD_CALLS）

### 3.4 层级 4：接口集成测试（Spring Boot Test + MockMvc）

| 项目 | 说明 |
|------|------|
| **工具** | Spring Boot Test + @AutoConfigureMockMvc + Testcontainers（可选） |
| **目标** | 验证 Controller → Mapper → 数据库的真实链路 |
| **范围** | 123 个 API 接口的契约测试 |
| **准入门槛** | ① 正常用例全通过；② 异常用例（参数校验/越权/不存在/冲突）全通过；③ 幂等用例（重复请求结果一致）通过；④ 并发用例（20 并发无错误）通过；⑤ 事务回滚用例（异常时数据不残留）通过 |
| **执行频率** | 每日构建 + 提测前 |
| **执行命令** | `mvn verify -pl kb-auth,kb-file,kb-knowledge,kb-ops -Dspring.profiles.active=test` |

**集成测试五维度**：
1. **正常路径**：合法参数 + 有效 token，返回 200 + 正确数据
2. **异常路径**：参数校验失败(400)/未认证(401)/无权限(403)/不存在(404)/冲突(409)
3. **幂等性**：同一请求重复调用 N 次，结果一致（如收藏切换、token 创建需防重）
4. **并发安全**：20 并发请求同一资源，无数据错乱、无死锁
5. **事务回滚**：模拟异常，验证数据库无脏数据残留

## 六、风险与缓解

| 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|---------|
| **上下文路径 KB_CONTEXT 配置不一致** | 高 | 公网访问 404 | L4-CTX-001~006 前置验证，不通过则终止测试 |
| **refresh_token 表无唯一约束导致 TooManyResultsException** | 高 | 刷新令牌 500 | 已知 bug，修复 selectOne→selectList.findFirst，L1-AUTH-006 验证 |
| **双层 Nginx 链路某层配置错误** | 高 | 公网全站不可用 | 部署前 nginx -t 校验；L4-CTX 验证双层链路 |
| **MinIO/MeiliSearch 第三方服务不可用** | 中 | 文件上传/搜索功能失效 | 测试前检查第三方服务健康；集成测试用 Testcontainers 隔离 |
| **前后端接口路径不一致（已知 22 项 GAP）** | 中 | 前端调用失败 | L4-GAP-001~022 专项跟踪，标注 KNOWN_ISSUE |
| **测试数据污染生产** | 高 | 生产数据错乱 | 严格环境隔离；测试仅在 SIT/TEST/UAT/STAGING 执行；生产环境禁止测试数据写入 |
| **变异测试执行慢** | 中 | CI 流水线延迟 | 仅对 Service 层核心方法执行；夜间全量变异 |
| **BDD 场景维护成本高** | 低 | 场景过时 | 每次需求变更同步更新 feature；CR 时审查场景 |
| **并发测试环境不稳定** | 中 | 误报 | 并发用例重试 3 次取稳定结果；隔离并发测试环境 |
| ** kb-intelligence 知识解析依赖 LLM** | 中 | 解析结果不确定 | Mock LLM 响应；解析结果用结构断言而非精确匹配 |

## 八、测试执行流程

### 8.1 执行顺序

```
1. 环境检查（VM 在线 + 容器健康 + Nginx 配置正确 + 第三方服务可用）
   ↓
2. L4-CTX 上下文路径验证（前置约束，不通过则终止）
   ↓
3. 层级 1 变异测试（PITest，开发机执行）
   ↓
4. 层级 2 编译静态检查（mvn compile + SonarQube + 敏感信息扫描）
   ↓
5. 层级 3 单元测试（mvn test，覆盖率 ≥ 85%）
   ↓
6. 层级 4 接口集成测试（mvn verify，五维度全通过）
   ↓
7. 层级 6 BDD 业务场景验收（mvn test -Dtest=*BddTest）
   ↓
8. 业务功能专项（状态机覆盖 + 数据工厂 + E2E 录制）
   ↓
9. L4 全量功能测试（公网 + VM 直连双链路，123 接口）
   ↓
10. 层级 5 功能流程测试（Playwright + 终端操作，13 页面 + 5 流程）
   ↓
11. L5 非功能测试（鉴权 + 错误码 + 性能 + 兼容性）
   ↓
12. 汇总测试报告 + 归档测试产物 → test-reports/
```

### 8.2 测试脚本组织

```
mykng/
├── kb-*/src/test/java/.../         # 层级 1/2/3/4/6 Java 测试（随源码）
├── kb-*/src/test/resources/features/ # 层级 6 BDD feature 文件
├── tests/
│   ├── e2e/                         # 层级 5 E2E（Playwright）
│   ├── functional/                  # L4 全量功能（Python）
│   ├── non_functional/              # L5 非功能（Python）
│   ├── fixtures/                    # 测试数据
│   └── reports/                     # 测试报告归档
```

### 8.3 执行命令汇总

```bash
# 层级 1 变异测试
mvn org.pitest:pitest-maven:mutationCoverage -pl kb-auth,kb-file,kb-knowledge,kb-ops

# 层级 2 编译静态检查
mvn clean compile
mvn sonar:sonar

# 层级 3 单元测试
mvn test -pl kb-auth,kb-file,kb-knowledge,kb-ops,kb-intelligence,kb-common

# 层级 4 集成测试
mvn verify -pl kb-auth,kb-file,kb-knowledge,kb-ops -Dspring.profiles.active=test

# 层级 5 E2E 测试
cd tests/e2e && python -m pytest -v

# 层级 6 BDD 测试
mvn test -Dtest=*BddTest -pl kb-auth,kb-file,kb-knowledge,kb-ops

# L4 全量功能测试
cd tests/functional && python -m pytest -v

# L5 非功能测试
cd tests/non_functional && python -m pytest -v
```
