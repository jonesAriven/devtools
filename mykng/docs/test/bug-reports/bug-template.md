# Bug 报告模板

> **用途**：记录测试发现的缺陷，跟踪修复进度
> **命名规范**：`BUG-YYYYMMDD-NNN.md`（如 BUG-20260628-001.md）
> **SOP 对应**：阶段 4 测试执行

---

## Bug 信息

| 字段 | 内容 |
|------|------|
| **Bug ID** | BUG-YYYYMMDD-NNN |
| **标题** | （一句话描述问题，含模块与现象） |
| **等级** | P0 阻塞 / P1 严重 / P2 一般 / P3 提示 |
| **模块** | kb-auth / kb-file / kb-knowledge / kb-ops / kb-gateway / kb-intelligence / kb-common / 前端 |
| **所属版本** | v1.x.x（commit hash） |
| **发现人** | XXX |
| **发现日期** | YYYY-MM-DD HH:mm |
| **指派人** | XXX |
| **状态** | 新建 / 已确认 / 修复中 / 已修复 / 验证中 / 已关闭 / 重新打开 / 拒绝 |

### 等级定义

| 等级 | 定义 | 示例 | SLA |
|------|------|------|-----|
| P0 阻塞 | 核心功能不可用，无法发版 | 登录失败、数据丢失、公网全站 404 | 立即修复 |
| P1 严重 | 重要功能不可用，影响主流程 | 文件上传失败、搜索失效、刷新 token 500 | 24h 内修复 |
| P2 一般 | 次要功能不可用，有规避方案 | 分享密码校验失效、回收站恢复失败 | 发版前修复 |
| P3 提示 | 体验问题、文案错误 | 错误提示不友好、样式错乱 | 排期修复 |

## 使用说明

1. **复制本模板**：新建 Bug 报告时复制本文件，命名为 `BUG-YYYYMMDD-NNN.md`
2. **填写完整**：所有字段尽量填写完整，特别是复现步骤与证据附件
3. **附 traceId**：后端 bug 务必附 traceId，便于快速定位日志
4. **状态同步**：状态变更时及时更新「状态流转记录」
5. **验证关闭**：验证通过后由测试人员关闭，开发不可自行关闭
