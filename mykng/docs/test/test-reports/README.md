## 一、命名规范

### 1.1 测试报告

| 类型 | 命名规范 | 示例 |
|------|---------|------|
| 全量测试报告 | `测试报告_YYYYMMDD_HHmm.md` | `测试报告_20260628_1430.md` |
| 专项测试报告 | `测试报告_专项_名称_YYYYMMDD_HHmm.md` | `测试报告_专项_回归_20260628_1430.md` |
| 上线观测报告 | `观测报告_YYYYMMDD_HHmm.md` | `观测报告_20260628_2000.md` |

### 1.2 Bug 报告

| 类型 | 命名规范 | 示例 |
|------|---------|------|
| Bug 报告 | `BUG-YYYYMMDD-NNN.md` | `BUG-20260628-001.md` |

> NNN 为当日序号，从 001 开始。

## 四、归档要求

1. **及时归档**：每次测试执行完成后 24 小时内归档报告
2. **版本对应**：报告需标注对应的后端/前端版本号与 commit hash
3. **附件归档**：E2E 录屏、截图、覆盖率报告等附件一并归档至 `tests/reports/`
4. **不可篡改**：已归档报告不可修改，如需补充请新建补充报告
5. **命名严格**：严格按命名规范，便于检索与统计
