## 三、文档职责划分（避免重复）

```
┌─────────────────────────────────────────────────────────────┐
│  使用说明书.md         → 面向用户：怎么用                      │
│  接口规范清单_v1.md    → 面向开发：API 契约                    │
│  知识库部署方案_*.md   → 面向运维：怎么部署                     │
│  私有化全端个人知识库_v6.md → 面向架构：为什么这样设计           │
└─────────────────────────────────────────────────────────────┘
```

**关键边界**：
- **路径规划** → 统一在 `接口规范清单_v1.md`（第 1.2 节"公网访问路径说明"），不在部署方案中重复
- **Nginx 配置** → 统一在 `知识库部署方案_*.md`（第五节），不在路径规划文档中重复
- **API 清单** → 统一在 `接口规范清单_v1.md`，不在其他文档中维护副本
- **架构图** → 统一在 `私有化全端个人知识库_v6.md`，部署方案中只引用

## 五、文档更新 Checklist

更新任何文档前，**必须**执行：

- [ ] 全量扫描 `mykng/` 下所有 `.md` 文件（使用 `Get-ChildItem -Recurse -Filter *.md`）
- [ ] 确认要修改的文档**职责边界**（避免与其他文档重复）
- [ ] 检查是否有过时文档需要同步归档（加 `_已过时` 后缀移至 `archive/`）
- [ ] 更新本文档索引（如新增/归档文档）
- [ ] 检查相关文档是否需要同步更新（如接口变更需同步 `api-spec.json`）

## 六、版本约定

| 文档类型 | 版本规则 | 示例 |
|---------|---------|------|
| 设计文档 | 主版本号 v1, v2, v3... | `私有化全端个人知识库_v6.md` |
| 部署方案 | 日期后缀 | `知识库部署方案_20260627.md` |
| 接口规范 | 内部版本号（v2.2） | `接口规范清单_v1.md`（文件名固定，内部版本号变更） |
| 使用说明书 | 主版本号 | `使用说明书.md`（v1.0） |

**过时归档规则**：
- 文件名加 `_已过时` 后缀
- 移至 `docs/archive/`
- 在本索引"已归档文档"表中记录过时原因和归档日期
