# Private-Knowledge-Base 私有化全端个人知识库（v2）

> 自研私有部署知识库系统 | 文件即知识 + MySQL + MongoDB + 分层部署
> 基于 v1 方案讨论修订，2026-06-05

---

## 📌 核心设计原则

1. **文件即知识单元** — 上传的文件不是笔记的附件，文件本身就是一条独立知识，在目录树下有自己的位置，有独立的详情页
2. **关系骨架 + 内容仓库** — MySQL 管关系元数据，MongoDB 管内容数据
3. **上传即索引** — 文件上传时同步解析文本存入 MongoDB，不存在索引延迟问题
4. **搜索直接查数据库** — 不引入 ES/MeiliSearch，通过 MongoDB full-text 索引检索
5. **分层部署** — 应用层在云上（公网访问），存储层在内网（大盘稳定）
6. **MVP First** — 第一版只做 Web 后台，跑通文件知识单元核心链路，APP/小程序/OnlyOffice/AI 后续迭代

## 1. 项目简介

### 核心功能清单

- 文件上传 → 解析全文 → 独立知识条目，树形目录分类、标签管理
- 全文检索：文件内容 + 笔记正文 + 网页剪藏统一搜索，命中即找到文件
- 手动富文本笔记录入（辅助功能）
- URL 网页一键收藏，自动清洗正文并存为知识条目
- 私有化大模型 AI 摘要与复盘（后续迭代）
- MinIO 多桶存储，预签名 URL 访问
- 三级共享：私密提取码、目录授权、公开知识库
- 版本管理与操作日志
- **后续**：Android/iOS APP、微信小程序、OnlyOffice 在线编辑

### 部署特点

全部 Docker 化，数据私有化，不依赖第三方云服务。

## 3. 技术栈

### 3.1 后端

| 组件 | 选型 | 说明 |
|------|------|------|
| 框架 | Spring Boot 3.2 + Spring Security + JWT | |
| 关系库 | MySQL 8.0 | 用户/目录/文件元信息/标签/分享/版本/日志 |
| 内容库 | MongoDB 7.0 | 文件解析全文、笔记正文、网页内容、AI 摘要 |
| 缓存 | Redis | 会话缓存、数据缓存 |
| 对象存储 | MinIO | 文件二进制存储，预签名 URL 访问 |
| 文件解析 | POI(Office) + PdfBox(PDF) + PaddleOCR/Tesseract(图片) | |
| 网页抓取 | Jsoup(静态) + Playwright(动态页面) | |
| AI 大模型 | Qwen2 (7B GPU / 1.5B-Q4 CPU) | 后续迭代 |

**移除的组件（对比 v1）**：

| 原组件 | 移除原因 | 替代方案 |
|--------|----------|----------|
| Elasticsearch / MeiliSearch | 内容存 MongoDB，直接用它全文检索 | MongoDB 内建 text index + 自定义中文分词 |
| RabbitMQ | 文件解析为同步流程，不需消息队列 | 上传解析同步执行 |
| XXL-JOB | 第一版不做定时复盘 | Spring @Scheduled（后续需要再加）|

### 3.2 前端

| 端 | 技术选型 | 优先级 |
|----|----------|--------|
| PC 管理后台 | Vue3 + ElementPlus + Vite | **第一版** |
| H5 (PWA) | 同上，支持 ServiceWorker 弱离线 | 后续 |
| Android/iOS APP | UniApp + Vue3 + Pinia | **后续迭代** |
| 微信小程序 | UniApp 一套源码编译 | **后续迭代** |

### 3.3 搜索策略

搜索不走 ES/MeiliSearch，直接基于 MongoDB 实现：

```
关键词 → /api/v1/search
  → MongoDB $text 搜索（跨 file_content / doc / web_page 集合）
  → 返回匹配的知识条目（文件/笔记/网页）
  → 前端展示结果 + 高亮
```

**MongoDB 全文搜索能力评估：**
- `$text` 索引支持多字段联合搜索、权重设置
- 中文分词需要处理（MongoDB Atlas 或 elastic/docker-pinyin-analysis）
- 个人知识库万级文档量，性能完全够用
- 后续如果需要更精准的中文分词，可以引入 MongoDB 的 ICU 分词插件或自定义分词

### 3.4 文件上传流程（简化版）

```
用户上传文件
  → 前端分片上传（大文件）
  → MinIO 存储二进制
  → 后端同步解析：
       ├── Office → POI 提取全文
       ├── PDF  → PdfBox 提取全文
       ├── 图片 → PaddleOCR/Tesseract 识别文字
       └── 文本 → 直接读取
  → 解析结果写入 MongoDB（file_content 集合）
  → MySQL 记录文件元信息
  → 搜索立即可搜索到
```

**无异步队列**：解析与上传同步执行，对于个人使用（单文件上传），同步解析体验更好。

## 5. MongoDB 内容仓库

### 5.1 集合设计

| 集合 | 存储内容 | 主要字段 |
|------|----------|----------|
| `file_content` | 文件解析全文 | fileId, userId, title, content(全文), textIndex, createdAt |
| `doc_content` | 富文本笔记正文 | docId, userId, content(富文本HTML), textIndex, createdAt |
| `web_content` | 网页清洗正文 | webId, userId, url, title, content(正文), textIndex, createdAt |
| `ai_summary` | AI 摘要缓存 | bizType, bizId, summary, model, createdAt |

### 5.2 索引策略

```javascript
// 文件内容全文索引
db.file_content.createIndex(
  { title: "text", content: "text" },
  { name: "file_fulltext", weights: { title: 10, content: 5 } }
)

// 笔记正文全文索引
db.doc_content.createIndex(
  { title: "text", content: "text" },
  { name: "doc_fulltext", weights: { title: 10, content: 5 } }
)

// 网页内容全文索引
db.web_content.createIndex(
  { title: "text", content: "text" },
  { name: "web_fulltext", weights: { title: 10, content: 5 } }
)

// 通用查询索引
db.file_content.createIndex({ userId: 1, fileId: 1 })
db.doc_content.createIndex({ userId: 1, docId: 1 })
db.web_content.createIndex({ userId: 1, webId: 1 })
db.ai_summary.createIndex({ bizType: 1, bizId: 1 })
```

### 5.3 MongoDB 全文搜索示例

```java
// Spring Data MongoDB 搜索
Query query = Query.query(
    Criteria.where("userId").is(userId)
        .andOperator(
            Criteria.where("content").regex(searchKeyword, "i")
        )
);

// 或使用 $text 索引（需引入中文分词插件）
Query query = Query.query(
    Criteria.where("userId").is(userId)
        .and("$text").is(TextCriteria.forDefaultLanguage()
            .matching(searchKeyword))
);
```

    url: jdbc:mysql://100.105.196.63:3306/knowledge_base
  data:
    mongodb:

## 10. 资源评估

### 10.1 应用层（腾讯云2号）

| 组件 | 内存 | CPU | 磁盘 |
|------|------|-----|------|
| Spring Boot | 512MB | 低~中 | 300MB |
| Redis | 128MB | 极低 | 50MB |
| 预留 | 256MB | — | — |
| **合计** | **~1GB** | **2 核足矣** | **< 500MB** |

### 10.2 存储层（内网 Debian）

| 组件 | 内存 | CPU | 磁盘 |
|------|------|-----|------|
| MySQL | 512MB~1G | 低 | 500MB + 数据 |
| MongoDB | 512MB~1G | 低~中 | 1GB + 数据 |
| MinIO | 256MB~512MB | 低 | 500MB + 文件存储 |
| **合计** | **~2GB** | **2 核** | **~2GB + 数据** |

> 内网 Debian 16GB 内存，存储层三个服务绰绰有余，还剩大把资源。MinIO 存储空间随文件量增长，建议初始分配 50GB 以上。

### 10.3 存储估算（与 v1 基本一致）

1000 篇知识文档约需 **3.5~4.5GB**，10000 篇约 **35~45GB**。
