## A1. 产品定位与核心理念

### 1.1 什么是 Private-Knowledge-Base？

Private-Knowledge-Base 是一套**完全私有化部署**的个人知识管理系统。核心理念是**"文件即知识"**——你上传的每一个文件（PDF 论文、Word 报告、Excel 数据表、扫描件图片）本身就是一条独立的知识条目，而非某个笔记的附件。

### 1.2 为什么需要私有化知识库？

| 痛点 | 我们的解决方案 |
|------|---------------|
| 第三方笔记应用数据存在云端，隐私无法保障 | 全部数据存储在自己的服务器上，不依赖任何第三方云服务 |
| 文件散落在电脑各处，找不到、搜不到 | 上传即解析、即索引，全文搜索秒级命中 |
| 网页看到好文章，收藏后原链接失效 | 一键收藏网页，自动清洗正文永久保存 |
| 不同类型的知识（文件/笔记/网页）分散在不同工具 | 文件、笔记、网页收藏统一管理，一次搜索全部命中 |
| 想要分享知识给同事，但文件太大无法通过聊天发送 | 生成分享链接 + 提取码，对方打开链接即可查看 |

### 1.3 核心设计原则

1. **文件即知识单元** — 文件不是笔记的附件，它本身就是一条独立知识，有目录位置、有标签、有版本历史
2. **上传即索引** — 文件上传后自动解析全文并建立搜索索引，无需手动处理
3. **统一搜索** — 文件内容、笔记正文、网页收藏一次搜索全部命中
4. **完全私有** — 数据存储在自己的服务器上，不经过任何第三方
5. **渐进式建设** — 先跑通核心链路，再逐步迭代高级功能

## A3. 知识采集

### 3.1 文件上传与解析

**支持格式**（MVP 阶段 → 后续扩展）：

| 阶段 | 格式 | 说明 |
|------|------|------|
| MVP | txt、md | 直接读取全文 |
| MVP | pdf | PdfBox 提取纯文本层 |
| MVP | docx | POI 提取文本内容 |
| 后续 | xlsx、pptx | POI 提取表格/演示内容 |
| 后续 | jpg、png | PaddleOCR/Tesseract 图片文字识别 |
| 后续 | 更多 Office 格式 | 持续扩展 |

**上传体验**：

- 支持大文件分片上传，断点续传
- 拖拽上传、批量上传
- 上传后自动异步解析，不阻塞操作
- 文件列表实时显示解析状态（解析中 → 已就绪 → 解析失败）
- 解析失败自动重试（最多 3 次），支持手动触发重新解析

**文件作为独立知识单元**：

每个文件在系统中拥有完整的"身份"：

| 属性 | 说明 |
|------|------|
| 📁 目录位置 | 在树形目录中有自己的归属，可自由移动 |
| 📄 详情页 | 独立的详情页面，展示元信息和解析内容 |
| 🏷️ 标签 | 可关联多个自定义标签 |
| ⭐ 星标 | 重要文件可加星标，快速定位 |
| 📋 版本 | 每次更新保留历史版本，可随时回溯 |
| 🔗 分享 | 可独立生成分享链接 |

### 3.2 网页一键收藏

将互联网上的好文章永久保存到自己的知识库：

```
① 复制网页 URL → 粘贴到知识库
② 后端自动抓取网页内容
③ 智能清洗：去除广告、导航栏、侧边栏等噪音，提取正文
④ 存为独立知识条目，自动进入搜索索引
⑤ 即使原网页失效，知识依然完整保留
```

**支持的网页类型**：
- 静态网页（MVP）：Jsoup 直接抓取
- 动态网页/SPA（后续）：Playwright 渲染后抓取

### 3.3 富文本笔记

对于需要手动记录的知识，提供富文本编辑器：

- 图文混排
- 标题、列表、表格、代码块、引用
- Markdown 快捷输入
- 笔记同样作为独立知识条目，有目录位置和标签

### 3.4 典型使用场景

| 场景 | 操作流程 |
|------|---------|
| 保存技术文档 | 下载 PDF → 拖拽上传到"技术文档"目录 → 自动解析 → 全文可搜索 |
| 收藏技术博客 | 复制博客 URL → 粘贴到知识库 → 自动抓取正文 → 归类到"前端开发"目录 |
| 记录会议纪要 | 新建笔记 → 富文本编辑 → 添加"会议纪要"标签 → 归档到"工作"空间 |
| 整理学习资料 | 批量上传课件 PDF → 自动解析 → 按课程分目录管理 → 打标签 |
| 分享报告给同事 | 找到报告文件 → 生成分享链接 + 提取码 → 发送链接给同事 |

## A4. 知识组织

### 4.1 树形目录

- 支持**无限级嵌套**的树形目录结构
- 文件、笔记、网页收藏统一在目录树中管理
- 支持拖拽移动、批量操作
- 目录结构示例：

```
📁 我的知识库
├── 📁 工作
│   ├── 📁 项目文档
│   │   ├── 📁 2026-Q2
│   │   │   ├── 📄 需求规格说明书.pdf
│   │   │   └── 📄 技术方案评审.docx
│   │   └── 📁 2026-Q3
│   ├── 📁 会议纪要
│   └── 📁 周报
├── 📁 学习
│   ├── 📁 前端开发
│   │   ├── 🌐 Vue3 组合式 API 详解（网页收藏）
│   │   └── 📄 TypeScript 手册.pdf
│   ├── 📁 后端开发
│   └── 📁 读书笔记
├── 📁 生活
│   ├── 📁 医疗健康
│   └── 📁 财务记录
```

### 4.2 标签系统

- 自定义创建标签，无数量限制
- 一个知识条目可关联多个标签
- 支持按标签筛选和组合搜索
- 标签示例：`#重要` `#待处理` `#前端` `#架构设计` `#2026`

### 4.3 多空间管理

支持创建多个独立的知识库空间，彼此隔离：

| 空间 | 用途 | 权限 |
|------|------|------|
| 工作空间 | 存放工作相关文档 | 仅自己 |
| 学习空间 | 存放学习资料 | 仅自己 |
| 团队空间 | 团队共享知识 | 指定成员可访问 |
| 公开空间 | 对外分享的知识 | 所有人可访问 |

### 4.4 星标与快速访问

- 重要文件/笔记可加星标
- 星标列表提供快速访问入口
- 最近访问/最近修改列表

## A6. 知识分享

### 6.1 三级共享机制

| 级别 | 方式 | 适用场景 | 配置 |
|------|------|---------|------|
| 🔒 私密分享 | 链接 + 提取码 + 有效期 | 分享给特定的人 | 设置 4 位提取码 + 7 天有效期 |
| 👥 目录授权 | 指定用户/目录权限 | 团队内部协作 | 给同事开通某目录的只读/编辑权限 |
| 🌐 公开知识库 | 无需密码直接访问 | 公开知识分享 | 设置空间为公开，任何人可通过链接访问 |

### 6.2 分享安全

- 提取码保护（4 位数字）
- 链接有效期控制（1 天 / 7 天 / 30 天 / 永久）
- 访问日志记录（谁在什么时候访问了什么）
- 防爬虫机制（Referer 校验）
- 分享资源 7 天自动过期清理

### 6.3 分享场景示例

| 场景 | 操作 |
|------|------|
| 给同事分享需求文档 | 选中文件 → 生成私密链接 + 提取码 → 发送链接 |
| 团队共享项目资料 | 创建团队空间 → 邀请成员 → 授权目录权限 |
| 发布技术文章 | 将笔记设为公开 → 生成公开链接 → 分享到社交媒体 |

## A7. 知识沉淀

### 7.1 版本管理

- 文件/笔记每次更新自动生成版本快照
- 可查看任意历史版本的内容
- 支持版本对比和回滚
- 版本历史时间线展示

### 7.2 操作日志

- 记录所有用户操作（上传、删除、修改、分享、登录等）
- 可按时间范围、操作类型筛选
- 完整的操作审计追踪

### 7.3 回收站

- 删除操作为逻辑删除（软删除），不会立即永久删除
- 支持从回收站一键恢复
- 回收站中的文件保留 30 天，过期自动清理
- 支持手动永久删除

### 7.4 数据备份

- MySQL / MongoDB / MeiliSearch 每日自动备份
- 备份存储在 MinIO 中，保留 30 天滚动
- 磁盘空间使用率超过 80% 自动告警
- 支持手动触发全量备份

## A8. 知识智能（AI 能力，后续迭代）

### 8.1 AI 摘要

文件上传解析后，本地大模型自动生成内容摘要：
- 快速了解文档核心内容，无需通读全文
- 摘要结果缓存在系统中，随时查看

搜索命中文件后，AI 基于文件内容回答你的问题：
```
问：这个项目的数据库选型是什么？
AI：根据搜索到的《技术方案评审.docx》，本项目采用 MySQL + MongoDB
    混合存储架构，MySQL 管关系元数据，MongoDB 管内容数据...
```

### 8.3 定时复盘

指定目录下所有文档的 AI 汇总报告：
- 每周自动生成"本周学习复盘"
- 每月自动生成"项目进度汇总"

### 8.4 本地私有化 AI

所有 AI 能力基于**本地部署的大模型**（Qwen2），知识数据不会上传到任何第三方服务。

> 本部分从**技术视角**出发，详细描述系统的架构设计、技术选型、数据模型、部署方案和实施计划。

## B1. 技术架构总览

### 1.1 架构设计原则

1. **关系骨架 + 内容仓库 + 搜索引擎** — MySQL 管关系元数据，MongoDB 管内容数据，MeiliSearch 管全文搜索
2. **上传即索引** — 文件上传时异步解析文本存入 MongoDB，同时写入 MeiliSearch 索引
3. **最终一致性** — MySQL + MongoDB + MinIO 三写采用补偿机制，允许短暂不一致，后台自动修复
4. **分层部署** — 应用层在云上（公网访问），存储层在内网（大容量稳定）
5. **MVP First** — 第一版只做 Web 后台，跑通核心链路

| 对比项 | MongoDB $text | Elasticsearch | MeiliSearch（选定） |
|--------|---------------|---------------|---------------------|

## B4. 核心流程设计

### 4.1 文件上传与解析流程

```
用户上传文件
  → 前端分片上传（大文件）
  → MinIO 存储二进制
  → MySQL 记录文件元信息（status: PARSING）
  → 后端异步解析（@Async）：
       ├── txt/md → 直接读取
       ├── docx   → POI 提取全文
       ├── pdf    → PdfBox 提取全文（纯文本层）
       ├── 图片   → PaddleOCR/Tesseract（后续迭代）
       └── 其他   → 暂不支持，记录日志
  → 解析结果写入 MongoDB（file_content 集合）
  → 解析结果写入 MeiliSearch（kb_files 索引）
  → MySQL 更新文件状态（status: READY）
  → 搜索立即可搜索到
  → 前端轮询/SSE 获取解析完成通知
```

### 4.2 解析失败补偿机制

```
解析失败
  → MySQL 记录 status: PARSE_FAILED + error message
  → 重试信息写入 Redis List（parse:retry:queue）
  → Spring @Scheduled 每 5 分钟消费重试队列
  → 最多重试 3 次，超过则标记 status: PARSE_PERMANENT_FAILED
  → 用户可在管理后台手动触发重新解析
```

### 4.3 数据一致性保障

MySQL + MongoDB + MinIO 三写的一致性策略：

| 场景 | 处理方式 |
|------|---------|
| MinIO 成功 + MySQL 成功 + MongoDB 失败 | Redis 记录重试，@Scheduled 补偿写入 MongoDB + MeiliSearch |
| MinIO 成功 + MySQL 失败 | 回滚 MinIO 文件，返回上传失败 |
| 全部成功 | 正常流程 |
| 删除操作 | 软删除（MySQL 标记 deleted），定时任务清理 MongoDB + MinIO |

### 4.4 搜索流程

```
用户输入关键词
  → /kb/api/search?q=关键词&type=all&folderId=xxx
  → 并行查询 MeiliSearch 三个索引（kb_files / kb_notes / kb_webpages）
  → 合并结果、按相关性/时间排序
  → 返回匹配列表 + 高亮片段
  → 前端展示搜索结果
```
