# 激活码管理系统 - 需求文档

## 1. 项目概述

### 1.1 项目背景
本项目旨在构建一个**高安全性、纯离线可用**的激活码管理系统，用于生成和验证软件产品的激活码。系统采用非对称加密（RSA）技术保证激活码的安全性，支持设备绑定验证，具备反调试检测能力。

### 1.2 项目目标
- 提供激活码生成服务（支持设备绑定）
- 提供激活码验证服务（纯离线验证）
- 确保激活码不可伪造和篡改
- 支持激活码与设备绑定，防止多设备使用
- 具备反调试检测能力
- 支持激活码有效期管理
- 记录激活码使用历史

### 1.3 安全性要求
- 激活码必须使用 RSA 非对称加密签名（2048位）
- 私钥严格保密，仅用于生成激活码
- 公钥用于验证激活码
- 激活码支持绑定设备ID
- 验证工具具备反调试检测能力
- 敏感数据使用后立即清理内存

## 4. 接口需求

### 4.1 生成激活码接口
- **URL**: `POST /api/activation/generate`
- **请求体**:
  ```json
  {
    "serialNumber": "string (必填, 设备序列号)",
    "deviceId": "string (可选, 设备唯一ID，为空则不绑定设备)",
    "expireDays": "integer (可选, 有效期天数, 默认365)"
  }
  ```
- **响应体**:
  ```json
  {
    "success": "boolean",
    "message": "string",
    "activationCode": "string (激活码，格式：serialNumber|deviceId|expireTimestamp.signature)",
    "expireTime": "long (过期时间戳)",
    "serialNumber": "string",
    "deviceId": "string (绑定的设备ID)"
  }
  ```

### 4.2 验证激活码接口
- **URL**: `POST /api/activation/verify`
- **请求体**:
  ```json
  {
    "activationCode": "string (必填, 激活码)",
    "deviceId": "string (可选, 当前设备ID)"
  }
  ```
- **响应体**:
  ```json
  {
    "success": "boolean",
    "message": "string",
    "serialNumber": "string (序列号)",
    "deviceId": "string (绑定的设备ID)",
    "expireTime": "long (过期时间戳)",
    "expired": "boolean (是否过期)",
    "deviceMismatch": "boolean (设备不匹配)"
  }
  ```

## 5. 数据需求

### 5.1 数据库表设计
**表名**: `activation_record`

| 字段名 | 类型 | 约束 | 说明 |
| :--- | :--- | :--- | :--- |
| id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | 主键ID |
| serial_number | VARCHAR(512) | NOT NULL, UNIQUE | 设备序列号 |
| device_id | VARCHAR(128) | DEFAULT '' | 绑定的设备ID |
| activation_code | TEXT | NOT NULL | 激活码 |
| expire_time | BIGINT | NOT NULL | 过期时间戳(毫秒) |
| create_time | DATETIME | NOT NULL | 创建时间 |
| update_time | DATETIME | NOT NULL | 更新时间 |

### 5.2 激活码结构
```
激活码 = Base64URL(serialNumber|deviceId|expireTimestamp) + "." + Base64URL(RSA签名)

示例：
ZGV2aWNlLTAwMXxERTAxMjM0NTY3ODl8MTczNTY4OTYwMDAw.MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8A...

字段说明：
- serialNumber: 设备序列号
- deviceId: 绑定的设备ID（可为空）
- expireTimestamp: 过期时间戳（毫秒）
- RSA签名: 使用私钥对payload进行SHA256withRSA签名
```

### 5.3 密钥文件
- **私钥文件**: `./rsa_keys/private_key.pem` - 用于生成激活码签名
- **公钥文件**: `./rsa_keys/public_key.pem` - 用于验证激活码

## 6. 安全设计

### 6.1 加密机制

**激活码结构**:
```
激活码 = Base64URL(payload) + "." + Base64URL(signature)
payload = serialNumber + "|" + deviceId + "|" + expireTimestamp
signature = SHA256withRSA(payload, privateKey)
```

**加密流程**:
1. 构造payload: `序列号|设备ID|过期时间戳`
2. 使用私钥对payload进行SHA256withRSA签名
3. 将payload和signature分别进行Base64URL编码
4. 用"."连接两部分形成最终激活码

**验证流程**:
1. 按"."分割激活码得到payload和signature
2. 对两部分分别进行Base64URL解码
3. 使用公钥验证signature是否正确
4. 解析payload获取序列号、设备ID和过期时间戳
5. （可选）验证设备ID是否匹配
6. 检查过期时间是否有效
7. 清理内存中的敏感数据

### 6.2 设备绑定机制

**绑定规则**:
- 生成激活码时可指定deviceId
- 如果deviceId为空，则激活码不绑定设备，可在任意设备使用
- 如果deviceId有值，则激活码绑定到该设备
- 验证时如提供deviceId，则进行设备匹配检查

**设备ID获取**:
- 可通过硬件信息（CPU、主板、硬盘）生成唯一标识
- 使用SHA256哈希确保固定长度

### 6.3 反调试检测

**检测方法**:
1. 检测Debugger.IsAttached
2. 调用CheckRemoteDebuggerPresent API
3. 执行时间检测（调试器会显著减慢执行）

**处理策略**:
- 检测到调试器时静默返回验证失败
- 不暴露任何调试相关信息

### 6.4 内存清理

**清理时机**:
- 验证完成后，无论成功失败
- 使用try-finally确保必然执行

**清理内容**:
- payload字节数组
- signature字节数组
- 任何包含敏感信息的临时变量

## 7. 业务流程

### 7.1 激活码生成流程
```
管理员请求 → 参数校验 → 查询已存在记录 → 计算过期时间 → 生成激活码(含设备绑定) → 保存记录 → 返回激活码
```

### 7.2 激活码验证流程（客户端离线）
```
输入激活码 → 反调试检测 → 解析激活码 → 验证签名 → 设备匹配检查 → 有效期检查 → 内存清理 → 返回结果
```

### 7.3 激活码验证流程（服务端）
```
接收请求 → 解析激活码 → 验证签名 → 设备匹配检查 → 有效期检查 → 更新记录 → 返回结果
```
