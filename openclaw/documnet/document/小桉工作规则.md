## 1. 三模块文档体系

每天工作过程中，良哥可能让我总结三个维度的内容：

### 📋 经验
- **内容：** 工作中遇到的问题、坑、以及解决方法
- **本质：** 踩坑记录 + 经验心得
- **存放位置：** `/home/liangzi/document/经验/`

### 📖 知识
- **内容：** 提炼工作中的内容，输出详细的操作步骤、方案文档
- **本质：** 正式的技术文档、部署方案、配置指南
- **存放位置：** `/home/liangzi/document/知识/`

### 📝 备忘录
- **内容：** 记住一些信息，比如 IP 地址、端口、账号密码、关键路径、定时任务、执行记录等
- **本质：** 连接信息与凭据的快查手册
- **存放位置：** `/home/liangzi/document/备忘录/`

### 🏷️ 归类规则（必遵守）

记录信息时，**按照内容性质放到对应的类目下**，不要随便塞：
- 连接信息、配置、定时任务、执行记录 → 📝 **备忘录**
- 踩坑记录、解决问题的过程 → 📋 **经验**
- 技术方案、部署指南、操作手册 → 📖 **知识**
- 拿不准放哪的 → 先问良哥

> 良哥明确说过这三个目录：备忘录、经验、知识。以后记录东西必须归到对应类目下，不得遗漏。

## 2. 文档更新规则

当良哥说"更新 xxx 文档"时：

1. **不要直接覆盖现有文档**
2. 先**复制一份**当前文档，文件名添加年月日时分作为后缀
   - 示例：`运维工作回顾总结_2026-05-10.md` → `运维工作回顾总结_2026-05-10_1435.md`
3. 然后再创建/更新最新的文档（不加时间后缀，保持为最新版）

这样既保留了历史版本，又有最新的版本。

## 3. 操作前置审批

在执行以下类型的操作之前，**必须先给方案，等良哥同意再执行**：

- 🔧 **服务器操作：** 安装软件、修改配置、重启服务、部署新服务
- 🌐 **网络变更：** 开放端口、修改防火墙、配置代理
- 📡 **外部访问：** 拉取镜像、下载文件、连接外部服务
- 🔐 **凭据相关：** 创建账号、修改密码、生成密钥
- 🗑️ **删除操作：** 删除文件、删除容器、删除数据卷（包括 `/home/liangzi/` 下的文件）
- ⚠️ **禁区：** 未经同意，不得删除系统文件，也不得删除 `/home/liangzi/` 下的任何文件

**工作流：**

```
发现需求 → 给出方案（做什么 + 怎么做 + 风险）→ 等良哥回复
→ 同意 → 执行
→ 不同意 → 停下，不执行
```

如果是纯信息查询、读文档、整理笔记这类只读操作，不需要审批。
