# 运维部署 FAQ — 经验总结

> 日期：2026年05月24日（08:30 更新）
> 环境：腾讯云龙虾主机 + 阿里云 + 内网 Debian + 火山云
> 整理：小桉 🌿

---

## 坑 0：FRP frpc.toml 配置格式（TOML 语法）

**问题 1 — 多 proxy 命名格式：** frpc 从旧版 INI 迁移到 TOML 格式后，多个 proxy 不能用重复的无名 `[[proxies]]`。TOML 标准语法要求同名数组表会导致后面的覆盖前面的。

- ❌ 错误：`[[proxies]]` ... `[[proxies]]`
- ✅ 正确：`[[proxies.ssh]]` ... `[[proxies.rdp-debian]]`

**问题 2 — 字段名格式：** TOML 使用 snake_case（下划线），不能使用 camelCase

| ✅ 正确 | ❌ 错误 |
|---------|---------|
| local_ip | localIP |
| server_addr | serverAddr |
| local_port | localPort |
| remote_port | remotePort |
| server_port | serverPort |

## 坑 0.5：FRP 方向搞反（反复犯！🔴）

**问题：** 想从龙虾主机传文件到内网 Debian，一直在琢磨怎么通过 FRP 隧道"送"过去。

**现象：** 尝试 SCP、Nginx、分块传输等方案绕 FRP 隧道传文件，全都很慢（几 KB/s 到几百 KB/s）。

**根因：** 把 FRP 的用途搞反了。

> **FRP 隧道 = 外网访问内网**，不是内网访问外网。

**流程图（错误理解）：**
```
龙虾主机 → SCP/HTTP → FRP 隧道 → 阿里云 → 内网 Debian ❌ 慢
```

**正确做法：**
```
内网 Debian → [家庭宽带直连] → 龙虾主机 Nginx → curl 下载 ✅ 快
```

**教训：**
- 内网机器访问外网资源 → 走**家庭宽带直连**（不需要 FRP）
- 外网机器访问内网资源 → 才走 **FRP 隧道**
- 内网 Debian 想从龙虾主机下载文件，直接 `curl http://49.51.245.134/xxx.gz` 走公网就行
- 不要一遇到内网就往 FRP 想，先搞清楚数据流向

## 坑 0.6：本机 SSH 自己（反复犯！🔴）

**问题：** 我在龙虾主机上执行命令，却去 SSH 连 `root@49.51.245.134`。

**教训：** 当前主机就是目标机时，直接本地执行命令就行，`docker ps`、`curl` 等直接跑，不要 SSH 绕一圈。

## 坑 20：SSH 隧道 DNS 污染导致代理失效

**场景：** 内网 Debian 上建立 SSH 隧道（SOCKS5）到龙虾主机/阿里云，通过隧道访问 Google 失败。

**现象：**
```
curl -x socks5://127.0.0.1:10809 https://www.google.com  → 超时 ❌
curl --socks5-hostname 127.0.0.1:10809 https://www.google.com  → 200 ✅
```

**根因：** 内网路由器的 DNS（192.168.31.1）对 Google 等域名返回了被污染的 IP。SOCKS5 默认在客户端解析 DNS（"locally resolved"），导致拿到错误 IP 后连接失败。而 socks5h（socks5-hostname）让远程服务器解析 DNS，绕过了本地 DNS 污染。

**教训：**
- SOCKS5：curl 默认本地解析 DNS → 会吃 DNS 污染
- SOCKS5H：curl 通过 `--socks5-hostname` 远程解析 DNS → 正确
- Clash 等代理软件的 DNS 配置要注意 fallback 到远程 DNS（如 8.8.8.8）
- 如果 fallback DNS 也走不了代理，需要配置 `nameserver-policy` 让被墙域名走代理侧 DNS

## 坑 21：Clash/Shadowsocks 密码不一致导致认证失败

**场景：** 内网 Debian 上装 Clash Meta，配置了 SS 代理指向龙虾主机的 Shadowsocks 容器，但所有请求都超时。

**根因：** Docker Shadowsocks 容器的密码是 `password0`，但 Clash 配置里写的是另一串密码。导致 Shadowsocks 服务端持续报 `authentication error`。

**教训：**
- Shadowsocks 密码以 Docker 容器密码为准，不要靠猜
- 遇到代理不通先查服务端日志：`docker logs <ss容器>`
- 认证错误会在日志里明确打印 `authentication error`，不要盯着客户端瞎调

## 坑 22：Docker daemon.json 写入后 JSON 格式不正确

**场景：** 通过 Alpine 容器挂载 host 目录修改 `/etc/docker/daemon.json`，写入后 Docker 启动失败。

**根因：** 通过 shell heredoc 传入 JSON 时，双引号被 shell 吃掉，写了无效 JSON（单引号代替双引号）。Docker daemon 解析失败。

**教训：**
- 写 JSON 配置不要手动拼，用 `python3 -c 'json.dump(...)'` 生成
- 写完后用 `python3 -c 'json.load(open(...))'` 验证格式
- 修改 daemon.json 后重启 Docker 前先验证

## 坑 23：host.docker.internal 在 Linux Docker 上不可用

**场景：** Docker daemon 配置全局代理时，写了 `http://host.docker.internal:7890`。

**根因：** `host.docker.internal` 是 Docker Desktop（Windows/Mac）才有的功能，原生 Linux Docker 不解析该域名。

**解决：** 改用 Docker bridge 网关 IP `172.17.0.1` 代替 `host.docker.internal`。

```json
{
  "proxies": {
    "http-proxy": "http://172.17.0.1:7890",
    "https-proxy": "http://172.17.0.1:7890"
  }
}
```

## 坑 24：hive-server2 容器挂载只读导致反复重启

**场景：** Docker daemon 重启后，hive-server2 容器反复重启（Restarting 循环）。

**现象：** 日志报 `/entrypoint.sh: line 44: /opt/hive/conf/hive-site.xml: Read-only file system`。

**根因：** docker-compose.yml 中 hiveserver2 的配置卷挂载为 `:ro`（只读），但 entrypoint 脚本需要通过 envsubst 替换环境变量并写回 hive-site.xml，只读模式导致写入失败。

**修复：** 将 `:ro` 改为 `:rw`：
```yaml
volumes:
  - ./conf-hs2:/opt/hive/custom-conf:rw  # 原来 :ro
```

## 坑 1：腾讯云安全组拦截 5000 端口 → Registry 不可达

**现象：** 龙虾主机 Docker Registry 启动后外部无法访问 5000 端口。

**根因：** 腾讯云安全组默认封禁 5000 端口。

**失败方案：** SSH 端口转发（TCP-over-TCP），拉取 1.5GB 镜像时被 SIGKILL。

**成功方案：** 龙虾机 `docker save → gzip → Nginx` → 内网 `wget（3MB/s）→ docker load`。

## 坑 2：Hive 镜像不含 MySQL JDBC 驱动

**现象：** Metastore 连接 MySQL 报 `No suitable driver found`。

**根因：** `apache/hive:4.2.0` 官方镜像不内置 mysql-connector-j。

**解决：** 下载 `mysql-connector-j-9.2.0.jar` → `~/hive-compose/jars/` → compose 挂载 `/tmp/ext-jars:ro` → entrypoint.sh 自动复制到 Hive lib。

## 坑 3：HiveServer2 不绑定 10000 端口（三重根因）

**现象：** HS2 日志显示 `Starting HiveServer2` 后进程运行但端口不绑定。

**根因 1 — 配置泄漏：** HS2 和 Metastore 共用了包含 MySQL JDBC 的 `hive-site.xml`。HS2 的 Derby schema init 尝试使用 MySQL URL 失败。

**根因 2 — IPv6 绑定：** HS2 在 IPv6（`::`）绑定而非 IPv4（`0.0.0.0`），容器内 localhost 解析到 127.0.0.1 导致连接被拒。

**根因 3 — 重试静默：** jstack 发现主线程 `WAITING` 在 `HiveServer2.startHiveServer2()`。`server.start()` 抛异常后进入 retry sleep，WARN 被 SLF4J 噪声淹没。

**解决：**
- ① 拆分 `hive-site.xml`（Metastore 用 `conf/`，HS2 用 `conf-hs2/`）
- ② `script -q -c` 提供伪终端
- ③ `webui.port=0` 禁用 Jetty

---

## 坑 4：CREATE TABLE 报 warehouse 路径不存在

**现象：** `MetaException: file:/user/hive/warehouse/test_hive is not a directory`。

**根因：** `hive.metastore.warehouse.dir` 未显式设置，回退 Hadoop 默认 `/user/hive/warehouse`（无权限创建）。

**解决：** 两份 `hive-site.xml` 均添加 `warehouse.dir=file:///opt/hive/data/warehouse`，并预创建目录。

## 坑 5：MySQL 8.0 caching_sha2_password 认证不兼容

**现象：** DBeaver 连接报 `Communications link failure`。

**解决：**
```sql
ALTER USER 'hive'@'%' IDENTIFIED WITH mysql_native_password BY 'Hwx@1120930';
```

## 坑 6：Docker Compose 端口映射丢失

**现象：** MySQL 宿主机局域网无法访问但容器 healthy。

**根因：** 多次修改 compose 时 `ports:` 段被误删。

**教训：** 每次改 compose 后用 `ss -tlnp` 验证端口。

## 坑 10：SSH 免密登录

内网 Debian 生成 ed25519 密钥，公钥添加到龙虾主机 `authorized_keys`，使龙虾机免密管理内网 Debian。

## 坑 11：Nexus 3 OOM（Java heap space）

**现象：** Nexus Web UI 无法访问，端口不响应，日志报 `java.lang.OutOfMemoryError: Java heap space`。

**根因：** 阿里云主机仅 1.7G 内存，Nexus 默认堆 `-Xms512m -Xmx512m` 不够。新增多个 PyPI proxy 仓库后 RSS 超 1.3GB → OOM killer 杀进程。

**解决：**
- 调堆内存：`sed -i 's/-Xms512m/-Xms1g/'` + `sed -i 's/-Xmx512m/-Xmx1g/'`
- **最终：** PyPI 私服拆分到火山云独立部署，阿里云 Nexus 只保留 Maven + NuGet

**教训：** 1.7G 内存跑 Nexus 3 是极限，proxy 仓库会显著增加内存。资源不足应拆分服务。

---

## 坑 12：阿里云安全组未开放端口

**现象：** 本地 curl 127.0.0.1:8081 正常，公网访问不通。

**根因：** 阿里云安全组（外置防火墙）未放行端口，规则不在服务器 iptables 中体现。

**解决：** 阿里云控制台 → 安全组 → 入方向规则放行对应 TCP 端口。

---

## 坑 13：Nginx sites-enabled 默认配置覆盖

**现象：** Nginx 配置了自定义站点，但访问仍返回 Nginx 默认欢迎页。

**根因：** `/etc/nginx/sites-enabled/default` 软链接仍存在且优先。

**解决：** `rm -f /etc/nginx/sites-enabled/default` 后 `nginx -t && systemctl restart nginx`。

---

## 坑 14：Debian 12 pip 禁止全局安装（PEP 668）

**现象：** `pip3 install xxx` 报 `externally-managed-environment` 错误。

**解决：** 使用 venv 虚拟环境绕开：
```bash
python3 -m venv /opt/pypi/venv
/opt/pypi/venv/bin/pip install ...
```

---

## 坑 15：devpi 密码认证需安装 passlib

**现象：** devpi 使用 htpasswd 文件时启动失败，日志报 `apache.passlib library is not available`。

**解决：** `pip install passlib` 或 `pip install pypiserver[passlib]`。

---

## 坑 16：devpi CLI 需额外安装 devpi-client

**现象：** 安装 devpi-server 后找不到 `devpi` 命令。

**根因：** devpi-server 和 devpi-web 只含服务端，CLI 客户端需单独安装。

**解决：** `pip install devpi-client`。

---

## 坑 17：pypiserver 新版使用 run 子命令

**现象：** `pypi-server -p 8080 ...` 启动报 deprecated 警告。

**解决：** pypiserver 2.x 改用 `pypi-server run -p 8080 ...`。

---

## 坑 18：Guacamole 远程桌面占用大量内存

**现象：** 阿里云内存不足，Nexus 频繁 OOM。

**根因：** Guacamole（Tomcat Java）独占 ~200MB，且长期未使用。

**解决：** 停用并清理：
```bash
docker stop guacamole guacd
docker rm guacamole guacd guac-mysql
docker rmi guacamole/guacamole guacamole/guacd mysql:8.0
```
释放 ~200MB 内存 + ~1.5GB 磁盘。

---

## 坑 19：devpi 初始启动后内存飙升然后回落

**现象：** 刚启动 devpi-server 时内存冲到 500-600MB，随后稳定在 ~70MB。

**根因：** 首次初始化多级 mirror 索引需要加载上游索引数据。

**教训：** devpi 稳定后内存占用 ~70MB（不含 Web UI 缓存）。
