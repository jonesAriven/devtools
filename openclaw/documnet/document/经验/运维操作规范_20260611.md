# 运维操作规范 & 教训记录

> 建立日期：2026-06-11
> 起因：DS卸载过程中反复试错，密码不通、权限不够、命令搞错

## 核心问题

每次操作服务器，习惯"现场摸索"而非"参考历史记录"，导致：
1. 试错成本高（密码试错、命令试错、权限试错）
2. 操作不一致（上次用A方式，这次用B方式）
3. 容易搞坏配置（Nginx行号删错）

## 铁律

### 1️⃣ 操作前先查「标准操作路径表」
- 位置：`/home/liangzi/document/备忘录/连接信息.md` → 3.10 节
- 各机器有明确的标准SSH命令，直接复制使用，**不要自己编**

### 2️⃣ 改配置文件前先看完整文件
- 先 `cat` 看结构，明确行号和内容
- 标号（cat -n）后再sed删改
- 改完必须验证（nginx -t、检查语法）
- 关键文件先备份（cp xxx xxx.bak）

### 3️⃣ 操作前想清楚访问链路
内网Debian的推荐登录方式：
```
龙虾主机 → sshpass → 阿里云(root@120.26.66.182) → sshpass → 内网Debian(root01@127.0.0.1:3383)
```
需要sudo时：`echo root01 | sudo -S 命令`

### 4️⃣ 出问题先停手查文档
- 连不上 → 查标准操作路径表
- 密码不对 → 查连接信息备忘录
- 不确定怎么改 → 先看完整内容再动手
- 清不清零、删不删数据 → 先问良哥

### 5️⃣ 有问题先记下来
操作中发现的新问题（端口、密码、配置变更）必须双记：
1. MEMORY.md
2. `/home/liangzi/document/` 下对应的备忘录
