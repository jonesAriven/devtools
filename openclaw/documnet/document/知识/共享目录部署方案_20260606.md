# 📁 Tailscale VPN + Windows SMB 共享目录部署方案

> 文档类型：📖 知识
> 创建时间：2026-06-06
> 状态：✅ 已定稿

> **别名对照（良哥定义）：**
> - `文件共享目录` 🗂️ → `/mnt/shared` — 日常读写、文件传输、开发源码
> - `数据备份共享目录` 📦 → `/mnt/0000sharebak` — 定时任务备份专用，平时不动

## 一、方案概述

### 背景

多台跨网络服务器（内网 Windows + 多台云 Linux）需要共享文件目录。最初使用内网 Debian 的 Samba 服务，后迁移到内网新 Windows 的 SMB 共享。

### 使用到的软件

| 软件 | 版本 | 用途 | 安装位置 |
|------|------|------|---------|
| **Tailscale** | 最新版 | VPN 虚拟组网，打通跨网络机器 | 所有机器（Windows + Linux） |
| **Windows SMB** | Windows 自带 | 文件共享服务 | 内网新 Windows（服务端） |
| **mount.cifs** | Linux 内核模块 | Linux 挂载 Windows SMB 共享 | 各 Linux 机器（客户端） |

### 网络拓扑

```
Tailscale 虚拟网络 (100.x.x.x)
              │
    ┌────┬────┼────┬────┬────┐
    │    │    │    │    │    │
 🦐龙虾 ☁️云2 ☁️阿里 📦Debian 🪟新Win
100.122 100.110 100.89 100.105  100.70
.231.95 .114.16 .102.74 .196.63  .76.54
         ↓                         ↓
    (Linux 客户端)           (SMB 服务端)
     mount.cifs 挂载        Windows 共享文件夹
```

## 二、软件安装步骤

### 2.1 Tailscale 安装（打通网络）

所有机器都必须安装 Tailscale 并登录同一账号。

#### 🪟 Windows 端安装

1. **官网下载：** https://tailscale.com/download
   - 下载 Windows 安装包（exe）
   - 双击安装，一路默认下一步
2. **登录：** 安装完后自动弹出浏览器，用 Google / Microsoft / GitHub 账号登录
3. **确认连接：** 右下角任务栏出现 Tailscale 图标（绿色 = 已连接）
4. **获取 Tailscale IP：**
   - 右键图标 → Admin Console
   - 或 CMD 执行 `ipconfig`，看到 `Tailscale` 网卡的 IP（100.x.x.x）

#### 🐧 Linux 端安装

```bash
# Debian/Ubuntu 一行命令
curl -fsSL https://tailscale.com/install.sh | sh

# 启动并登录
tailscale up

# 会弹出浏览器登录链接，复制到浏览器登录即可
# 登录完后确认 IP
tailscale ip -4
```

#### ✅ 验证网络互通

安装完成后，任意一台机器 ping 其他机器的 Tailscale IP 能通即正常：

```bash
ping -c3 100.70.76.54    # Ping Windows
ping -c3 100.122.231.95  # Ping 龙虾主机
```

> **注意：** Tailscale 免费版最多支持 20 台设备，个人使用完全足够。

### 2.2 创建 Windows 专用共享用户

> 为了安全，建议不要用 Everyone + 关闭密码保护，而是创建一个专用用户。

#### 🪟 Windows 上操作

1. **打开计算机管理**
   - 右键"此电脑" → **管理** → **系统工具** → **本地用户和组** → **用户**
2. **新建用户**
   - 右键空白区域 → **新用户**
   - 用户名：`share`
   - 密码：`share123`
   - 取消勾选"**用户下次登录时须更改密码**"
   - 勾选"**密码永不过期**"
   - 点击创建
3. **（可选）如果之前设置了关闭密码保护共享**
   - **控制面板 → 网络和共享中心 → 更改高级共享设置**
   - **所有网络 → 密码保护的共享 → 开启密码保护共享**

## 四、Linux 客户端挂载

### 4.1 挂载命令

```bash
# 创建挂载点
mkdir -p /mnt/shared         # ideaworkspace
mkdir -p /mnt/0000sharebak   # 0000sharebak

# 挂载 ideaworkspace
mount -t cifs //100.70.76.54/ideaworkspace /mnt/shared \
  -o username=share,password=share123,vers=2.0,soft,file_mode=0755,dir_mode=0755

# 挂载 0000sharebak
mount -t cifs //100.70.76.54/0000sharebak /mnt/0000sharebak \
  -o username=share,password=share123,vers=2.0,soft,file_mode=0755,dir_mode=0755
```

### 4.2 /etc/fstab 开机自动挂载

```bash
# ideaworkspace（主共享）
//100.70.76.54/ideaworkspace  /mnt/shared  cifs  username=share,password=share123,vers=2.0,_netdev  0  0

# 0000sharebak（备用共享，2026-06-06 新增）
//100.70.76.54/0000sharebak  /mnt/0000sharebak  cifs  username=share,password=share123,vers=2.0,_netdev  0  0
```

### 4.3 参数说明

| 参数 | 说明 |
|------|------|
| `vers=2.0` | SMB 协议版本，Windows 10+ 默认支持 SMB2/3，但 vers=3.0 有时连接不稳定，降为 2.0 更稳 |
| `soft` | 网络中断时不阻塞进程 |
| `_netdev` | 网络设备，启动时等待网络就绪再挂载 |
| `file_mode=0755,dir_mode=0755` | 挂载后文件和目录的权限 |

### 4.4 各机器挂载情况

| 机器 | 挂载点 | 备注 |
|------|--------|------|
| 🦐 龙虾主机 | `/mnt/shared` + `/mnt/0000sharebak` | 已配置 |
| ☁️ 腾讯云2号 | `/mnt/shared` | 已配置 |
| ☁️ 阿里云 | `/mnt/shared` | 需配置 0000sharebak |
| 📦 内网 Debian | `/mnt/shared` | 局域网直连 |

## 五、故障排除

### 5.1 挂载失败 - SMB 版本不兼容

```
mount error: Server abruptly closed the connection.
```

**解决：** 尝试不同 SMB 版本

```bash
mount -t cifs //100.70.76.54/共享名 /mnt/路径 -o username=share,password=share123,vers=2.0
# 如果 2.0 不行，试 1.0
mount -t cifs //100.70.76.54/共享名 /mnt/路径 -o username=share,password=share123,vers=1.0
# 如果 2.0/1.0 不行试 3.0
mount -t cifs //100.70.76.54/共享名 /mnt/路径 -o username=share,password=share123,vers=3.0
```

### 5.2 挂载卡死 - 服务端不可达

**症状：** `ls /mnt/shared` 一直卡住不返回

**原因：** 通常是一个挂载点叠了两个 CIFS 挂载，或服务端 SMB 服务卡死

**解决：**
```bash
# 强制卸载
umount -l /mnt/shared
# 重新挂载
mount -t cifs //100.70.76.54/ideaworkspace /mnt/shared -o ...
```

### 5.3 权限拒绝

**症状：** `mount error(13): Permission denied`

**原因：** 用户名或密码错误，或 Windows 端未授权该用户

**检查：**
- 确认 Windows 上 `share` 用户存在、密码正确
- 确认文件夹共享权限里有 `share` 用户
- 确认 NTFS 权限里也有 `share` 用户

## 六、文件传输规则

> **良哥定的规矩：** 服务器间传文件统一走共享目录

| 规则 | 说明 |
|------|------|
| 临时文件统一放 | `/mnt/shared/temp/` |
| 禁止 | scp、SSH 管道、HTTP 下载等跨服务器传文件 |
| 源码放共享目录 | 编译环境装各自主机，不在共享目录装编译工具 |
