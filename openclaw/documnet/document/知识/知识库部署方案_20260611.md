## 一、整体架构

```
用户（公网）
    │ HTTPS
    ▼
┌─────────────────────────────┐
│  腾讯云2号 Nginx (:443)      │
│  tools.marschat.online      │
│  → 反代到 mykng-debain      │
└──────────┬──────────────────┘
           │ Tailscale 直连
           ▼
┌─────────────────────────────┐
│  mykng-debain 虚拟机          │
│  (VirtualBox on 旧Windows)  │
│  ┌───────────────────────┐  │
│  │ Docker (deploy_kb-net) │  │
│  │  ├─ kb-backend (SpringBoot)│
│  │  ├─ MySQL 8.0          │  │
│  │  ├─ MongoDB 7.0        │  │
│  │  ├─ Redis 7            │  │
│  │  ├─ MinIO              │  │
│  │  └─ MeiliSearch        │  │
│  └───────────────────────┘  │
└─────────────────────────────┘
```

**数据流向（主链路）：** 外网用户 → 腾讯云2号 Nginx（SSL终结）→ Tailscale 直连 → mykng-debain 虚拟机 → Docker 容器

**数据流向（备选链路）：** 外网用户 → 腾讯云2号 Nginx（SSL终结）→ 阿里云:18085 → FRP 隧道 → mykng-debain:8080 → Docker 容器

> ⚠️ FRP 隧道（18085端口）已配置但未启用（Tailscale 直连优先），仅作为 Tailscale 故障时的备选方案

## 六、踩坑总结

### 6.1 Docker 容器间通信地址

**问题：** `application-prod.yml` 中配置 `172.18.0.1`（Docker网关）连接 MongoDB，导致超时
**原因：** 网关地址不转发流量到容器，仅用于宿主机到容器的通信
**解决：** 通过环境变量覆盖，改用容器名（`kb-mysql`、`kb-mongo`、`kb-redis`、`kb-minio`、`kb-meilisearch`）
**教训：** Docker 自定义网络中，容器名 DNS 解析是标准做法，不要用 IP 地址

### 6.2 镜像拉取慢

**问题：** 家庭宽带 + Clash 代理拉取 Docker Hub 镜像速度慢
**解决：** 从内网 Debian 用 `docker save/load` 传输已有镜像；Docker daemon 配置了 Daocloud/163/dockerproxy.com 镜像加速

### 6.3 MySQL 认证方式

**问题：** 默认 `caching_sha2_password` 不兼容某些客户端
**解决：** 改为 `mysql_native_password`，创建用户时指定认证插件

### 6.4 Tailscale 连接不稳定

**问题：** mykng-debain 的 Tailscale 服务停止运行，导致腾讯云2号无法通过 Tailscale 访问，所有 API 返回 403
**原因：** Tailscale 服务意外停止（可能是系统重启或网络波动）
**解决：** 重启 Tailscale 服务 `systemctl restart tailscaled && tailscale up`
**教训：** 
1. 需要配置 Tailscale 服务开机自启
2. 建议添加监控脚本，检测 Tailscale 连接状态
3. FRP 隧道可作为 Tailscale 故障时的备选方案

### 6.5 知识库密码哈希不匹配

**问题：** 知识库 admin 密码 `admin123` 无法登录，返回“用户名或密码错误”
**原因：** 数据库中的密码哈希与 `admin123` 不匹配（可能是初始化时使用了不同的密码）
**解决：** 更新数据库中的密码哈希为 `admin123` 的正确 BCrypt 值
```sql
UPDATE user SET password='$2b$10$zgCtn4bdqCN6ltv38WdyUuJkers7A3XZrd0.baZUK1LtJ5Air0aEu' WHERE username='admin';
```
**教训：** 部署时要确认初始密码，并记录在案

## 七、运维命令速查

```bash
# 查看所有容器状态
docker ps -a --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}'

# 查看后端日志
docker logs --tail 50 kb-backend

# 重启后端
docker restart kb-backend

# 重建后端（环境变量覆盖配置时）
docker rm -f kb-backend
docker run -d --name kb-backend --network deploy_kb-net \
  -e SPRING_DATASOURCE_URL='jdbc:mysql://kb-mysql:3306/knowledge_base?...' \
  -e SPRING_DATA_MONGODB_URI='mongodb://kb-mongo:27017/knowledge_base?...' \
  ... \
  deploy-kb-backend:latest

# 健康检查
curl http://localhost:8080/kb/actuator/health

# 登录测试
curl -X POST http://localhost:8080/kb/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'

# 查看 Docker 网络
docker network inspect deploy_kb-net

# MySQL 查询
docker exec kb-mysql mysql -ukb -pkb123456 -hkb-mysql knowledge_base -e 'SHOW TABLES;'

# MinIO 桶列表
docker exec kb-minio mc ls data/

# === FRP 隧道管理（mykng-debain） ===

# 查看 frpc 状态
ps aux | grep frpc

# 启动 frpc（后台运行）
nohup frpc -c /etc/frp/frpc.toml > /var/log/frpc.log 2>&1 &

# 查看 frpc 日志
tail -f /var/log/frpc.log

# 重启 frpc
pkill frpc && sleep 1 && nohup frpc -c /etc/frp/frpc.toml > /var/log/frpc.log 2>&1 &

# 测试 FRP 隧道（从阿里云）
curl -s http://127.0.0.1:18085/kb/actuator/health
```

> ⚠️ **FRP 隧道说明：**
> - frpc 配置文件：`/etc/frp/frpc.toml`
> - 映射关系：`local_port=8080` → `remote_port=18085`
> - FRP 服务端：阿里云 `100.89.102.74:7000`
> - Token：`YourStrongToken!`
