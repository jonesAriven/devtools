## 二、执行流程

```
02:30 ── daily-backup.sh ──────────────────
       收集所有文件 → 合并打包 → Nginx 目录
       耗时 8秒，约 71MB
       
02:50 ── push-to-windows.sh ────────────────
       从 Nginx 目录 → smbclient 推送 → Windows 共享
       慢就慢慢传（跨太平洋链路限制，约 30KB/s）
```

### 02:30 备份打包（`daily-backup.sh`）

- 把 4 类文件收集到临时目录
- `tar czf` 打包成一个 `backup-日期.tar.gz`
- 复制到 Nginx 下载目录 `/home/www/html/backup/日期/`
- 清理临时文件

### 02:50 推送 Windows（`push-to-windows.sh`）

- 从 Nginx 目录读取备份文件
- `smbclient` 推送到 `//100.70.76.54/0000sharebak/openclaw/日期/`
- 失败重试 5 次，每次间隔 60 秒
- 5 次全失败就放弃，明天再试

## 四、为什么慢

龙虾是**国外服务器**（腾讯云海外节点），备份文件要跨太平洋传到国内家庭宽带的内网 Windows。

```
龙虾(国外) ── 国际出口带宽 ~30KB/s ──→ 国内 → 内网 Windows
```

这是物理限制，不是哪个环节可以优化的。凌晨 5 点跑，没人等着，让它慢慢传。
