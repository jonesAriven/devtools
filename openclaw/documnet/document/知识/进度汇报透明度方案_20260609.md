# 进度汇报透明度方案

> 良哥和小桉约定：回答时的信息透明程度。

## 三种级别

### 精简版（默认）

- **你不说级别时用的默认模式**
- 你问 → 我直接答
- 和现在一样，不额外报进度

示例：
```
你：Hive的配置是什么？
我：JDBC地址 jdbc:hive2://192.168.31.182:10000/default，无账号密码
```

### 标准版

- 每步关键步骤报一声
- 告知我在做什么，不暴露工具参数细节

示例：
```
你：Hive的配置是什么？
我：收到，先查一下记忆
→ 找到1条相关记忆
Hive的JDBC地址是 jdbc:hive2://192.168.31.182:10000/default，无账号密码
```

### 完整版

- 每一步调了什么工具都报出来
- 包含工具名和关键参数

示例：
```
你：Hive的配置是什么？
我：收到
→ 调 memory_search(query="Hive 配置")
→ 找到 1 条，相关度 0.76
Hive的JDBC地址是 jdbc:hive2://192.168.31.182:10000/default，无账号密码
```

## 切换方式

| 你说 | 切换到 |
|------|--------|
| （什么都没说） | **精简版**（默认） |
| "标准版" | 标准版 |
| "完整版" | 完整版 |
| "精简版" | 精简版 |

- 切换到某个级别后，**本次对话持续生效**，直到你再说换级别

## token 消耗估算

| 级别 | 每条额外输出 token | 每天成本（50条） |
|------|:----------------:|:---------------:|
| 精简版 | 0 | $0 |
| 标准版 | ~50 | $0.0007 |
| 完整版 | ~200 | $0.0028 |

> 成本基本可以忽略不计。

## 实现方式（小桉内部机制）

### 1. 实现机制（三保险）

**第一道：AGENTS.md 铁律（系统级注入）**
- AGENTS.md 由 OpenClaw 系统自动读取并注入到每轮会话的 system prompt 中
- 小桉**每次回复前被迫读到**进度汇报铁律，不需要自觉去翻文件
- 铁律包含强制自检指令：「每次回复前想一下当前级别 + 这条回复符合要求吗？」
- 这是最核心的一道保险，靠系统注入，不依赖小桉自觉

**第二道：MEMORY.md 当前级别副本**
- MEMORY.md 中也记录了当前级别，作为会话初始化的辅助标记
- 标注了"以 AGENTS.md 为准"，避免两处不同步

**第三道：小桉自身的指令执行力**
- 小桉的「思维模型」里内置了三个级别的行为规则
- **精简版** → 不主动报工具调用过程，直接给结论
- **标准版** → 每步的关键动作告知用户（如"先查一下记忆"），不暴露内部tool名字和参数
- **完整版** → 每一步把调了啥tool、参数是啥、结果咋样都列出来

### 2. 切换靠「自然语言理解」

当用户说"标准版"、"完整版"、"精简版"时：
1. 小桉识别到这句话是在切换进度级别
2. 小桉更新自己的「当前级别」认知（此对话内有效）
3. 后续所有回答按新级别约束输出

切换是**对话级别的变量**，只对本对话有效。新开一个对话，默认级别会重新从 AGENTS.md 的铁律读取。

### 3. 为什么用"三保险"而不是代码开关？

因为小桉本质上是 LLM Agent，不是传统软件。没有可编程的运行时配置开关。行为由：
- **AGENTS.md/MEMORY.md/SOUL.md** 等系统注入的启动指令初始化
- **对话中的上下文** 动态调整
- **小桉自己对规则的理解和执行** 保证一致性

三保险中，AGENTS.md 是最稳的——它被系统强行注入，我不需要"记得去读"。
