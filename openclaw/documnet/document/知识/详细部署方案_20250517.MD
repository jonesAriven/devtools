## 2.2 Docker 安装（Debian 13 通用）

```bash
# 添加 Docker 官方 GPG 密钥和 apt 源
curl -fsSL https://download.docker.com/linux/debian/gpg | \
  gpg --dearmor -o /usr/share/keyrings/docker.gpg
echo "deb [arch=amd64 signed-by=/usr/share/keyrings/docker.gpg] \
  https://download.docker.com/linux/debian trixie stable" \
  > /etc/apt/sources.list.d/docker.list

# 安装 Docker
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io \
  docker-compose-plugin docker-buildx-plugin

# 镜像加速
cat > /etc/docker/daemon.json << 'EOF'
{ "registry-mirrors": ["https://registry.cn-hangzhou.aliyuncs.com"] }
EOF
systemctl restart docker
```

### 2.4.6 关键设计决策

| 决策 | 说明 |
|------|------|
| **为什么拆分配置文件？** | Metastore 需要 MySQL JDBC 配置来存取元数据。HS2 只需通过 Thrift 连接 Metastore。如果共用 hive-site.xml，HS2 启动时会用 MySQL URL 做 Derby schema init 而失败。 |
| **IS_RESUME=true？** | 避免 HS2 启动时重复执行 schema init（已由 Metastore 完成）。 |
| **webui.port=0？** | 禁用 HS2 Web UI。否则 Jetty+JspFactory 初始化可能导致启动卡顿。 |
| **hive.execution.engine=mr？** | 使用 MapReduce local 模式（单机），无需 YARN/Tez 集群，适用于开发测试环境。 |

## 2.5 FRP 内网穿透配置

### 2.5.1 阿里云 frps 服务端：/etc/frp/frps.ini

```ini
[common]
bind_port = 7000
dashboard_port = 7500
dashboard_user = admin
dashboard_pwd = MySecurePassword@2025
token = YourStrongToken!
vhost_http_port = 80
vhost_https_port = 443
allow_ports = 3381,3382,3383,3384
log_file = /var/log/frps/frps.log
log_level = info
```

> ⚠️ `allow_ports` 使用逗号分隔（不是 `~`）。新增端口需同步修改此配置 + 阿里云安全组。

### 2.5.2 内网 Debian frpc 客户端：/etc/frp/frpc.toml

```toml
server_addr = "120.26.66.182"
server_port = 7000
token = "YourStrongToken!"
log_file = "/var/log/frpc.log"
log_level = "info"
log_max_days = 3

[[proxies.ssh]]
name = "ssh"
type = "tcp"
local_ip = "127.0.0.1"
local_port = 22
remote_port = 3383

[[proxies.rdp-debian]]
name = "rdp-debian"
type = "tcp"
local_ip = "127.0.0.1"
local_port = 3389
remote_port = 3384
```

> ⚠️ **TOML 语法关键点（这里踩过坑！）：**
> 1. 多个 proxy 必须用**命名格式**：`[[proxies.ssh]]`、`[[proxies.rdp-debian]]`，不能用重复的 `[[proxies]]`
> 2. 所有字段用**下划线**（snake_case）：`local_ip`、`server_addr`、`remote_port`，不要用驼峰
> 3. 字符串值需要**引号**：`"120.26.66.182"`、`"info"`
> 4. `token` 在 frps 和所有 frpc 之间**必须一致**

### 2.5.3 新增/修改穿透端口的操作流程

1. **阿里云安全组：** 放行新端口
2. **阿里云 frps.ini：** 修改 `allow_ports`，添加新端口号
3. `systemctl restart frps`
4. **内网 frpc.toml：** 添加新的 `[[proxies.xxx]]` 块
5. `systemctl restart frpc`
6. **验证：** `telnet 120.26.66.182 <新端口>`

### 2.5.4 FRP 隧道映射表

| 服务 | 内网地址:端口 | 公网端口 | 协议 |
|------|-------------|---------|------|
| SSH（内网 Debian） | 127.0.0.1:22 | 3383 | TCP |
| RDP（内网 Debian） | 127.0.0.1:3389 | 3384 | TCP |

### 2.6.2 smart-dl + dl-relay + 国内镜像

**smart-dl 决策逻辑：**
```
① 软件源(apt/pip/npm/docker/git) → 国内镜像
② 直连快 + 文件小 → 本地下载
③ 大文件(≥200MB) → aria2 中继
④ 直连慢 + 代理通路 → proxychains
⑤ 都不行 → 中继兜底
```

| Python pip | mirrors.aliyun.com/pypi/simple/ |

### 2.8.2 部署步骤

```bash
# 1. 安装依赖
apt-get update && apt-get install -y nginx python3-venv

# 2. 创建 venv 并安装 devpi
python3 -m venv /opt/pypi/venv
/opt/pypi/venv/bin/pip install devpi-server devpi-web devpi-client

# 3. 初始化数据目录
/opt/pypi/venv/bin/devpi-init --serverdir /opt/devpi/data

# 4. 创建 systemd 服务
cat > /etc/systemd/system/devpi.service << 'EOF'
[Unit]
Description=DevPI Server
After=network.target

[Service]
Type=simple
User=root
Group=root
ExecStart=/opt/pypi/venv/bin/devpi-server \
  --serverdir /opt/devpi/data \
  --host 127.0.0.1 --port 3141
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload && systemctl enable --now devpi
```

## 3.8 故障恢复指南

### 场景 A：龙虾主机崩溃，需重建

1. 安装 Docker（见 2.2）
2. 安装 Nginx，恢复 `/home/www/html/` 中的镜像文件
3. 重新启动 Registry 并推送镜像
4. 恢复 SSH 密钥以便免密连接内网 Debian

### 场景 B：内网 Debian 重装系统

1. 安装 Docker + Compose（见 2.2）
2. 恢复 `~/hive-compose/` 目录
3. 从龙虾机 wget 下载 Hive 镜像 → `docker load`
4. `docker pull docker.m.daocloud.io/library/mysql:8.0`
5. `docker compose up -d`
6. 执行首次配置（MySQL 认证修复 + 创建 warehouse 目录，见 2.4.5）

### 场景 C：Hive 服务异常

1. `docker compose down && docker compose up -d`
2. 检查日志：`docker logs hive-server2`
3. 如 HS2 不绑定端口，检查 `conf-hs2/hive-site.xml` 是否只含 Metastore URI
4. 确认 `warehouse.dir` 在两份配置中均已设置

## 3.9 Clash Meta 代理部署方案

> 部署日期：2026-05-24
> 目标：为内网 Debian 提供智能代理路由，加速 Docker 拉取海外镜像及 GitHub 访问

### 3.9.1 拓扑概览

```
内网 Debian（192.168.31.182）
  ├── Clash Meta v1.18.10（系统服务）
  │   ├── 监听 :7890（HTTP/SOCKS5 混合代理）
  │   ├── 监听 :53（DNS）
  │   └── 控制面板 :9090
  ├── SSH Tunnel → 龙虾主机 :10809（SOCKS5 备用）
  ├── SSH Tunnel → 阿里云 :10808（SOCKS5 备用）
  └── 上游代理：龙虾 Shadowsocks（49.51.245.134:8388）

龙虾主机（49.51.245.134）
  └── Shadowsocks 容器（teddysun/shadowsocks-libev）
      ├── 密码: password0
      ├── 加密: aes-256-gcm
      ├── 端口: 8388（公网）→ 9000（容器内）
      └── 默认 DNS: 8.8.8.8
```

### 3.9.2 安装步骤

```bash
# ① 下载 Clash Meta 二进制（在龙虾主机上下好）
# 注意选对架构：内网 Debian 是 amd64，不支持 mihomo v3 的 CPU
# 实际安装版本：mihomo-linux-amd64-v1.18.10

# ② 传到内网 Debian（通过 Nginx HTTP 直连下载，不走 FRP）
# 把文件放龙虾主机 /home/www/html/
# 内网 Debian 执行：
curl -o /tmp/clash.gz http://49.51.245.134/clash.gz

# ③ 安装
gunzip /tmp/clash.gz
sudo install -m 755 /tmp/clash /usr/local/bin/clash-meta

# ④ 创建系统服务
sudo tee /etc/systemd/system/clash-meta.service << 'EOF'
[Unit]
Description=Clash Meta Proxy
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/clash-meta -d /etc/clash
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl enable --now clash-meta
```

### 3.10.1 配置方法

```json
  }

```

> ⚠️ Linux 原生命令：用 `172.17.0.1`（Docker bridge 网关）代替 `host.docker.internal`（仅限 Docker Desktop）

### 3.10.2 生效验证

```bash

systemctl restart docker

# 验证代理已生效
docker info | grep -A2 Proxy
# 输出应为：
# HTTP Proxy: http://172.17.0.1:7890
# HTTPS Proxy: http://172.17.0.1:7890
# No Proxy: ...

# 测速：拉 Java 21 镜像约 1 分钟
docker pull eclipse-temurin:21-jre
```

### 3.10.3 `host.docker.internal` 解析方案

> 场景：activecode 容器连接 MySQL 使用了 `host.docker.internal` 域名
> 问题：Linux Docker 默认不解析该域名

**最终方案：Clash `hosts` 配置固定解析**

```yaml
# /etc/clash/config.yaml
hosts:
  host.docker.internal: 192.168.31.182
```

**原理：** 所有容器的默认 DNS 指向 Clash（`172.17.0.1:53`），Clash 收到 `host.docker.internal` 查询时直接返回配置的 IP，不依赖上游 DNS。

**为什么不用其他方案：**
- ❌ `host.docker.internal:host-gateway` → 需要每个容器创建时加 `--add-host`，现有容器不生效
- ❌ dnsmasq 独立 DNS → 需要占用 53 端口，与 Clash 冲突
- ❌ 宿主机 `/etc/hosts` → 容器不直接查宿主机 hosts 文件
- ✅ Clash hosts → 全局生效、不依赖上游、可移植

### 3.10.4 注意事项

- 没有 root 权限时，可通过特权容器修改 daemon.json：
  ```bash
  docker run --rm -v /etc/docker:/dest alpine sh -c 'cat > /dest/daemon.json'
  ```
- 修改后需要重启 Docker：`docker run --rm --privileged --pid=host -v /:/host alpine chroot /host systemctl restart docker`
- 重启后 Docker socket 短暂不可用，需要等待几秒
- 修改 Clash 配置后重启 Clash：`docker run --rm --privileged --pid=host -v /:/host alpine chroot /host systemctl restart clash-meta`

## 3.11 阿里云 Clash 部署

> 部署日期：2026-05-24
> 目标：阿里云主机走龙虾 Shadowsocks 代理访问国外网站，与内网 Debian 统一方案

### 3.11.1 安装步骤

阿里云为 CentOS 7，安装方式与内网 Debian 一致。

```bash
# ① 下载 Clash Meta 二进制
# 从龙虾 Nginx 或 GitHub 下载
curl -L -o /tmp/clash.gz http://49.51.245.134/clash.gz

# ② 安装
gunzip /tmp/clash.gz
install -m 755 /tmp/clash /usr/local/bin/clash-meta

# ③ 创建 systemd 服务
cat > /etc/systemd/system/clash-meta.service << 'EOF'
[Unit]
Description=Clash Meta Proxy
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/clash-meta -d /etc/clash
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now clash-meta
```

### 3.11.2 配置要点

阿里云上 DNS 无污染问题，可关闭 Clash DNS（`dns.enable: false`）。

```yaml

mixed-port: 7890
allow-lan: true
mode: rule

  enable: false    # 阿里云 DNS 无污染，不需要 Clash DNS

  - name: "龙虾-SS"
    type: ss
    server: 49.51.245.134
    port: 8388
    cipher: aes-256-gcm
    password: password0

proxy-groups:
  - name: "Proxy"
    type: select
    proxies:
      - 龙虾-SS

rules:
  - DOMAIN-SUFFIX,google.com,Proxy
  - DOMAIN-SUFFIX,youtube.com,Proxy
  - DOMAIN-SUFFIX,github.com,Proxy
  - DOMAIN-SUFFIX,docker.com,Proxy
  - DOMAIN-SUFFIX,pypi.org,Proxy
  - DOMAIN-SUFFIX,python.org,Proxy
  - DOMAIN-SUFFIX,cloudflare.com,Proxy
```
