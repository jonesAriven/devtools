# OpenClaw 核心参数说明文档

> 创建时间：2026-06-14
> 用途：记录 OpenClaw 配置中关键参数的含义和影响

## 参数总览

| 参数路径 | 当前值 | 说明 |
|---------|--------|------|
| `inferenceParams.temperature` | 0.1 | 模型输出随机性控制 |
| `inferenceParams.top_p` | 0.8 | 核采样参数 |
| `inferenceParams.thinkingMode` | minimal | 思考模式 |
| `compaction.mode` | manual | 会话压缩模式 |
| `toolDefaults.maxRetries` | 2 | 工具调用重试次数 |

---

## 详细说明

### 1️⃣ inferenceParams.temperature

**作用：** 控制模型生成文本的随机性/创造性

**取值范围：** 0.0 ~ 2.0（推荐 0.0 ~ 1.0）

| 值 | 行为 | 适用场景 |
|----|------|---------|
| 0.0~0.3 | 输出非常确定，几乎不随机 | 事实性问答、代码生成、数据分析 |
| 0.5~0.7 | 平衡模式 | 日常对话、一般任务 |
| 0.8~1.0 | 高创造性，更多样化 | 创意写作、头脑风暴 |

**对各维度的影响：**
- **准确性：** 值越低，准确性越高（减少"幻觉"）
- **创造性：** 值越高，输出越多样
- **Token 消耗：** 无直接影响
- **响应速度：** 值越低，模型决策路径越短，略快

**当前值 0.1 的含义：** 非常确定性的输出，适合需要高准确性的任务

---

### 2️⃣ inferenceParams.top_p

**作用：** 核采样（Nucleus Sampling）参数，控制从概率最高的多少比例 token 中采样

**取值范围：** 0.0 ~ 1.0

| 值 | 行为 | 适用场景 |
|----|------|---------|
| 0.1~0.5 | 非常保守，可能重复 | 需要高度一致性的任务 |
| 0.6~0.8 | 平衡模式 | 大多数场景 |
| 0.9~1.0 | 完全开放采样 | 创意任务 |

**对各维度的影响：**
- **准确性：** 值越低，输出越可预测
- **多样性：** 值越高，输出越多样
- **Token 消耗：** 无直接影响
- **稳定性：** 值越低，输出越稳定

**当前值 0.8 的含义：** 从概率最高的 80% token 中采样，平衡准确性和多样性

---

### 3️⃣ inferenceParams.thinkingMode

**作用：** 控制模型的思考/推理深度

**可选值：** minimal | low | medium | high

| 值 | 行为 | 适用场景 |
|----|------|---------|
| minimal | 快速响应，最小化思考 | 简单问答、快速查询 |
| low | 轻度推理 | 一般任务 |
| medium | 中度推理 | 复杂问题、需要逻辑推理 |
| high | 深度推理 | 数学证明、复杂分析、多步推理 |

**对各维度的影响：**
- **响应速度：** 值越低越快
- **Token 消耗：** 值越高，思考过程消耗越多 token（可能额外增加 20-50%）
- **准确性：** 值越高，复杂任务的准确性越高
- **成本：** 值越高，API 调用成本越高

**当前值 minimal 的含义：** 快速响应模式，节省 token，适合简单任务

---

### 4️⃣ compaction.mode

**作用：** 控制会话历史的压缩方式

**可选值：** auto | manual

| 值 | 行为 | 适用场景 |
|----|------|---------|
| auto | 自动压缩旧消息，保持上下文长度适中 | 长对话、节省 token |
| manual | 手动控制压缩，保留完整历史 | 需要完整上下文的场景 |

**对各维度的影响：**
- **上下文保持：** manual 完整保留，auto 可能丢失早期上下文
- **Token 消耗：** manual 会累积，auto 可控
- **长对话效率：** auto 更好，manual 后期会变慢
- **准确性：** manual 更高（不丢失上下文）

**当前值 manual 的含义：** 完整保留会话历史，适合需要完整上下文的任务

---

### 5️⃣ toolDefaults.maxRetries

**作用：** 工具调用失败时的最大重试次数

**取值范围：** 0 ~ 5（推荐 1~3）

| 值 | 行为 |
|----|------|
| 0 | 不重试，失败立即返回 |
| 1 | 最多重试 1 次（共 2 次尝试） |
| 2 | 最多重试 2 次（共 3 次尝试） |
| 3+ | 更多重试机会 |

**对各维度的影响：**
- **可靠性：** 值越高，临时故障恢复能力越强
- **响应速度：** 值越高，失败时等待时间越长
- **Token 消耗：** 每次重试都会消耗额外 token
- **成本：** 重试越多，成本越高

**当前值 2 的含义：** 最多重试 2 次，平衡可靠性和效率

---

## 参数组合建议

### 场景 1：事实性问答/数据分析
```yaml
temperature: 0.1
top_p: 0.8
thinkingMode: minimal 或 low
```

### 场景 2：复杂推理/逻辑分析
```yaml
temperature: 0.3
top_p: 0.8
thinkingMode: medium 或 high
```

### 场景 3：创意写作/头脑风暴
```yaml
temperature: 0.7
top_p: 0.9
thinkingMode: low 或 medium
```

### 场景 4：长对话/节省成本
```yaml
compaction.mode: auto
thinkingMode: minimal
```

---

## 当前配置（2026-06-14）

```yaml
inferenceParams:
  temperature: 0.1
  top_p: 0.8
  thinkingMode: minimal

compaction:
  mode: manual

toolDefaults:
  maxRetries: 2
```

**配置说明：** 当前配置偏向高准确性和快速响应，适合事实性任务和短对话。长对话场景下 token 消耗会累积。

---

## 注意事项

1. **参数互相影响：** temperature 和 top_p 一起调整效果更好
2. **模型差异：** 不同模型对参数的敏感度不同
3. **成本控制：** thinkingMode 和 compaction 对 token 消耗影响最大
4. **测试建议：** 修改参数后建议在测试环境验证效果
